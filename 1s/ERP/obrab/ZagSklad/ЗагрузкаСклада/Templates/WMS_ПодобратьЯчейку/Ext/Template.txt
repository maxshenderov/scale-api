# ПодобратьЯчейку — алгоритм подбора оптимальной секции и адреса

## Сигнатура
```
Функция ПодобратьЯчейку(Склад, Высота, Ширина, Глубина, Вес, ОбратныйПорядокВремени=Ложь, Все=Ложь) Экспорт
```
Возвращает **один адрес** (ПЕРВЫЕ 1) — оптимальную ячейку для размещения паллета.

---

## Поля в выдаче `find_cell_for_pallet`

Инструмент возвращает до 20 кандидатов с полным набором критериев. **Все ORDER BY-критерии видны в выдаче — не гадай, смотри на числа.**

| Поле | Тип | Источник | Зачем |
|------|-----|----------|-------|
| `Приоритет_Номер` | Число | Порядковый номер | Позиция в выдаче |
| `СекцияКод` | Строка | `Секция.Код` | Идентификатор секции |
| `Адрес` | Строка | Вычисляемый | Конкретный адрес (Адрес1/2/3) |
| `Стеллаж` | Строка | `Стеллаж.Наименование` | Имя стеллажа |
| `Ряд` | Число | `Секция.Ряд` | Номер ряда |
| `Место` | Число | `Секция.Место` | Горизонтальная позиция |
| `Этаж` | Число | `Секция.Этаж` | Вертикальный уровень |
| `ШиринаСекции` | Число | `Типоразмер.Ширина` | Полная ширина секции, мм |
| `ВысотаСекции` | Число | `Типоразмер.Высота` | Полная высота секции, мм |
| `ОстатокВысота` | Число | `ВысотаСекции − ВысотаПаллета` | Позиция 3 ORDER BY |
| `ОстатокШирина` | Число | Свободная ширина | Позиция 7 ORDER BY |
| `ПотенциалСекции` | Число | 3/2/0 | Позиция 4 ORDER BY |
| `УровеньДоступа` | Число | 1=ближняя, 2=дальняя | Позиция 9 ORDER BY |
| `ВремяДоступа` | Число | Расчётное время | Позиция 10 ORDER BY |
| `ДельтаГрузоподъемности` | Число | `Qb − ВесПаллета` (безлимит=999999) | **Позиция 1 ORDER BY** |
| `ВесПаллета` | Число | Вес паллета, кг | Для проверки: `Дельта = Qb − ВесПаллета` |
| `ГрузоподъемностьСекции` | Число | `Типоразмер.Вес` | Позиция 6 ORDER BY |
| `ОстатокВесЯчейка` | Число | Вес ячейки − ВесПаллета | Позиция 5 ORDER BY |
| `ОстатокВес` | Число | Свободный вес секции | Позиция 8 ORDER BY |
| `МаксВесПодъёмаНаЭтаж` | Число | 0=без ограничения | WHERE-фильтр: если >0 и ВесПаллета > него → отсев |
| `МинГлубинаНеОграничена` | Булево | Секция с дном? | Позиция 2 ORDER BY (False=0 перед True=1) |
| `Узкопроходный` | Булево | Стеллаж узкопроходный? | **Позиция 0 ORDER BY** (Истина=приоритет) |
| `НеОграниченаПоГрузоподъемности` | Булево | Безлимитная секция? | Если Истина → Дельта=999999 |

> **Дельта = ГрузоподъемностьСекции − ВесПаллета.** Для безлимитных = 999999.
> Все компоненты формулы есть в выдаче — проверяй арифметику, а не вычисляй обратным ходом.

---

Склад секционного хранения паллетов. Каждая **секция** (`Справочник.Лико_СкладскиеСекции`) содержит до **3 адресов** (ячеек) внутри одного физического слота:

```
┌─────────────────────────────────┐
│  Адрес1  │  Адрес2  │  Адрес3  │
│   W/3    │   W/3    │   W/3    │
└─────────────────────────────────┘
         W = Типоразмер.Ширина
```

**Категории паллетов по ширине:**

| Категория | Условие | Занимает адресов |
|-----------|---------|-----------------|
| Узкий | ≤ W/3 | 1 |
| Средний | > W/3, ≤ W/2 | 2 (блокирует Адрес2) |
| Широкий | > W/2 | 3 (все) |

---

## 5 CTE-этапов запроса

### ВТСекции — фильтрация кандидатов
WHERE: глубина >=, вес >= (если не безлимитная), высота >=, склад =, НЕ ЗапретРазмещения, стеллаж Мин/Макс ширина/глубина.
Вычисляется `УровеньДоступа`:
```
КОГДА (Место - 1) / 3 + 1 <= КоличествоСекций / 2 ТОГДА 1  -- ближняя зона
ИНАЧЕ 2                                                       -- дальняя зона
```

### ВтОстатки — текущие паллеты
Остатки из `РегистрНакопления.Лико_ПаллетыВСекциях.Остатки` по трём адресам каждой секции.
INNER JOIN `РегистрСведений.Лико_ПараметрыПаллет.СрезПоследних` — типоразмер паллета.

### ВтОстаткиИтог — агрегация
`МАКСИМУМ(Адрес)` — один паллет может иметь движения по нескольким адресам.

### ВтСекцииСОстатками — LEFT JOIN секций × 3 адреса
`Паллет1`/`Типоразмер1` ← по Адрес1, `Паллет2`/`Типоразмер2` ← по Адрес2, `Паллет3`/`Типоразмер3` ← по Адрес3.

### Финальный SELECT — ПЕРВЫЕ 1
WHERE + вычисляемые поля + ORDER BY.

---

## Вычисляемые поля

### ПотенциалСекции
Максимум паллетов в секции **после** размещения:

| Значение | Условие |
|----------|---------|
| 3 | Оба края пусты ИЛИ заняты узкими (≤ W/3) |
| 2 | Один край занят широким (> W/3), другой свободен |
| 0 | Оба края заняты |

### Адрес — целевой адрес размещения

| Ширина паллета | Выбор адреса |
|----------------|-------------|
| > W/2 | Адрес2 (центр) |
| > W/3 | Адрес1 если пуст → иначе Адрес3 |
| ≤ W/3 | Адрес1 → Адрес2 (если оба края узкие) → Адрес3 → Адрес1 |

### ОстатокВысота / ОстатокШирина / ОстатокВес
Остаток вместимости. Используются в WHERE, ОстатокВысота — в ORDER BY.

---

## WHERE — фильтры физической возможности

1. Хотя бы 1 свободный адрес
2. `ОстатокШирина > 0`
3. `ОстатокВес >= ВесПаллета` ИЛИ секция безлимитная
4. Паллет2 если занят → его ширина < W/3
5. Широкий (> W/2): все 3 адреса пусты
6. Средний (> W/3): Адрес2 пуст + (Адрес1 ИЛИ Адрес3 пуст)
7. Узкий (≤ W/3): проходит при любом свободном адресе

### 🛑 ГАБАРИТНЫЕ ОГРАНИЧЕНИЯ СТЕЛЛАЖА — жёсткий фильтр + приоритет

Поля `Стеллаж.МаксШиринаПаллета`, `Стеллаж.МинШиринаПаллета`,
`Стеллаж.МаксГлубинаПаллета`, `Стеллаж.МинГлубинаПаллета` работают в WHERE как **жёсткий фильтр**.
Если значение ≠ 0, паллет НЕ попадёт в стеллаж при нарушении:

| Поле | Условие отсева |
|---|---|
| `МаксШиринаПаллета` ≠ 0 | Ширина паллета **>** МаксШиринаПаллета → ОТСЕЯН |
| `МинШиринаПаллета` ≠ 0 | Ширина паллета **<** МинШиринаПаллета → ОТСЕЯН |
| `МаксГлубинаПаллета` ≠ 0 | Глубина паллета **>** МаксГлубинаПаллета → ОТСЕЯН |
| `МинГлубинаПаллета` ≠ 0 | Глубина паллета **<** МинГлубинаПаллета → ОТСЕЯН |

> Синхронизированы с проверками №14a-14d в ОшибкиРазмещенияВАдрес.
> Значение 0 = «без ограничения» по этому измерению.

### 🆕 ОВЕРРАЙДЫ ГЛУБИНЫ НА УРОВНЕ СЕКЦИИ

Поля секции `МинимальнаяГлубинаНеОграничена` и `МаксимальнаяГлубинаНеОграничена` (Булево)
отменяют соответствующую проверку стеллажа для данной секции:

| Поле секции | Эффект |
|---|---|
| `МинимальнаяГлубинаНеОграничена` = Истина | Пропуск проверки `Стеллаж.МинГлубинаПаллета` |
| `МаксимальнаяГлубинаНеОграничена` = Истина | Пропуск проверки `Стеллаж.МаксГлубинаПаллета` |

### 🆕 МАКСИМАЛЬНЫЙ ВЕС ПОДЪЁМА НА ЭТАЖ

Поле секции `МаксимальныйВесПодъёмаНаЭтаж` (Число) — максимальный вес **одного** паллета,
который погрузчик может поднять на данный этаж.

| Условие | Поведение |
|---|---|
| `МаксимальныйВесПодъёмаНаЭтаж` = 0 | Без ограничения |
| `МаксимальныйВесПодъёмаНаЭтаж` > 0 | Вес паллета **>** МаксимальныйВесПодъёмаНаЭтаж → ОТСЕЯН |

### Разделение стеллажей на узкопроходные и широкопроходные

**Не зашивай список — смотри поле `Узкопроходный` в выдаче `find_cell_for_pallet`.**

Флаг `Узкопроходный` (Булево) есть у каждого кандидата. Определяется полем `Стеллаж.Узкопроходный` в 1С. Если у кандидата `Узкопроходный = Истина` — стеллаж узкопроходный. Если `Ложь` — широкопроходный.

> Раньше в документации было: «узкопроходные = 1,2,3,4,5,6,7,10; широкопроходные = 8А,9». **Не верь этому списку — он мог устареть.** Проверяй поле `Узкопроходный` в данных.

### Правило приоритета (ORDER BY)

В ORDER BY `Узкопроходный УБЫВ`: Истина (1) перед Ложь (0). Узкопроходные получают приоритет.
**Все паллеты, которые помещаются в узкопроходные, идут туда в первую очередь.**
Широкопроходные заполняются только теми паллетами, которые НЕ влезли в узкопроходные.

Если все кандидаты из одного стеллажа — проверь поле `Узкопроходный`: если он `Ложь`, значит узкопроходные отсеяны WHERE-фильтрами (все заняты, запрет размещения, не проходят по габаритам).

---

### 🚨 WHERE → ORDER BY: конвейер, а не параллель

**WHERE-фильтры выполняются ПЕРВЫМИ и жёстко отсеивают неподходящие секции. ORDER BY работает ТОЛЬКО с теми, кто выжил.**

```
Все секции склада
    ↓
[WHERE: физические ограничения]  ← жёсткий отсев
    ↓
Выжившие кандидаты (уже отсортированы WHERE неявно)
    ↓
[ORDER BY: приоритеты]           ← только ранжирование выживших
    ↓
ПЕРВЫЕ N
```

**Следствия для анализа выдачи `find_cell_for_pallet`:**

1. **Если кандидат с лучшими ORDER BY-характеристиками отсутствует в выдаче — он отсеян WHERE-фильтром.** Это НЕ баг алгоритма. Пример: стеллажи 1-7 с дельтой 1700 (лучше) отсутствуют → проверь `validate_pallet_placement`: высота, вес, занятость, запрет размещения.

2. **Одинаковая дельта у всех кандидатов — норма.** Если все выжившие из одного стеллажа с одинаковым типоразмером → грузоподъемность одна → дельта одна. ORDER BY отработал корректно: выбрал лучший стеллаж, а внутри него все секции равны по этому критерию.

3. **Не гадай почему кандидат отсеян — вызови `validate_pallet_placement`.** WHERE-фильтры: габариты (высота/ширина/глубина), вес (суммарный + подъёма на этаж), занятость адресов, запрет размещения, Мин/Макс стеллажа. Без вызова инструмента валидации можно только предполагать.

### WHERE → ORDER BY: полный перечень фильтров отсева

| Фильтр | Где | Что проверяет |
|--------|-----|---------------|
| Высота | ВТСекции | `Типоразмер.Высота >= &Высота` |
| Глубина | ВТСекции | `Типоразмер.Глубина >= &Глубина` |
| Вес секции | ВТСекции | `НеОграниченаПоГрузоподъемности ИЛИ Типоразмер.Вес >= &Вес` |
| Склад | ВТСекции | `Склад = &Склад` |
| Запрет размещения | ВТСекции | `НЕ ЗапретРазмещения` |
| Ширина стеллажа (мин/макс) | ВТСекции | `(0 ИЛИ <= / >= &Ширина)` |
| Глубина стеллажа (мин/макс) | ВТСекции | `(0 ИЛИ <= / >= &Глубина)` c оверрайдами секции |
| Вес подъёма на этаж | ВТСекции | `(0 ИЛИ >= &Вес)` |
| Хотя бы 1 свободный адрес | Финальный | `Паллет1=Пусто ИЛИ Паллет2=Пусто ИЛИ Паллет3=Пусто` |
| Остаток ширины >= W/3 | Финальный | Минимум одна ячейка свободна |
| Вес не превышен | Финальный | `НеОграничена ИЛИ ОстатокВес >= &Вес` |
| Широкий паллет (> W/2) | Финальный | Все 3 адреса пусты |
| Средний паллет (> W/3) | Финальный | Адрес2 пуст + (Адрес1 ИЛИ Адрес3 пуст) |
| Вычисленный адрес ≠ Пусто | Финальный | Дубликат SELECT-логики |

## ORDER BY — итоговая иерархия

```sql
УПОРЯДОЧИТЬ ПО
    -- 0. Узкопроходные стеллажи первыми — см. поле Узкопроходный в выдаче
    Стеллаж.Узкопроходный УБЫВ,
    -- 1. Best-fit по дельте грузоподъемности (безлимитные = 999999 → последние)
    ДельтаГрузоподъемности ASC,
    -- 2. Секции с ограничением глубины — первыми (False=0 перед True=1). Секции с дном — в конец.
    Ссылка.МинимальнаяГлубинаНеОграничена ASC,
    -- 3. Best-fit по высоте
    ОстатокВысота ASC,
    -- 4. Потенциал (направление — по флагу)
    ПотенциалСекции [УБЫВ / ASC],
    -- 5. Best-fit по весу ячейки
    ОстатокВесЯчейка ASC,
    -- 6. Best-fit по ёмкости секции (Типоразмер.Вес, НЕ ОстатокВес)
    Типоразмер.Вес ASC,
    -- 7. Остаток ширины
    ОстатокШирина,
    -- 8. Остаток веса
    ОстатокВес,
    -- 9. Зона доступа (tiebreaker)
    УровеньДоступа [УБЫВ / ASC],
    -- 10. Время доступа (tiebreaker)
    ВремяДоступа [УБЫВ / ASC]
```

### 🚨 КЛЮЧЕВОЕ ПРАВИЛО: `Узкопроходный` — приоритет в ORDER BY

`Стеллаж.Узкопроходный` работает в ORDER BY на позиции 0:

**ORDER BY: `Узкопроходный УБЫВ`:**
- Стеллажи с `Узкопроходный = Истина` → ПРИОРИТЕТ
- Стеллажи с `Узкопроходный = Ложь` → в конец
- **Смотри поле `Узкопроходный` в выдаче — не угадывай по номеру стеллажа.**
- Все паллеты, которые помещаются в узкопроходные, идут туда в первую очередь
- Широкопроходные заполняются только паллетами, которые НЕ влезли в узкопроходные

### 🚨 `МаксШиринаПаллета` — ТОЛЬКО жёсткий фильтр в WHERE

`Стеллаж.МаксШиринаПаллета` работает ТОЛЬКО в WHERE как жёсткий физический фильтр:
```sql
(Стеллаж.МаксШиринаПаллета = 0 ИЛИ Стеллаж.МаксШиринаПаллета >= ШиринаПаллета)
```
Стеллаж с МаксШиринаПаллета ≠ 0 и ШиринаПаллета > МаксШиринаПаллета → исключается.
Аналогично для МинШирина, МаксГлубина, МинГлубина.

МаксШиринаПаллета больше НЕ используется в ORDER BY — его заменил Узкопроходный.

> 🚨 НЕ ПУТАТЬ: `Узкопроходный` в ORDER BY (приоритет) vs `МаксШиринаПаллета` в WHERE (фильтр).
> Это приоритет узкопроходным стеллажам перед широкопроходными.

## Динамические флаги

### Потенциал3ПаллетаВСекции
```bsl
ШиринаЯчейки = ПредопределенныеЗначения.ШиринаСкладскойСекции / 3;
Потенциал3ПаллетаВСекции = (Ширина <= ШиринаЯчейки);
```
| Флаг | Паллет | Направление ПотенциалСекции |
|------|--------|---------------------------|
| Истина | Узкий (≤ W/3) | УБЫВ — сначала пустые секции |
| Ложь | Широкий (> W/3) | ASC — дозаполняем перед новыми |

### ОбратныйПорядокВремени
Управляет `УровеньДоступа` и `ВремяДоступа`:
| Значение | Поведение |
|----------|-----------|
| Ложь (default) | Ближние зоны, быстрый доступ — первыми |
| Истина | Дальние зоны, медленный доступ — первыми |

## Ключевые решения

1. **Типоразмер.Вес вместо ОстатокВес** — паллет 500кг → секция 2.5т предпочтительнее 6т.
2. **ОстатокШирина убран из ORDER BY** — для узкого паллета ширина закодирована в ПотенциалСекции.
3. **УровеньДоступа на позиции 7, не 1** — tiebreaker, не главный критерий.
4. **Потенциал3ПаллетаВСекции — динамический порог** из `ПредопределенныеЗначения`, не хардкод 900.
5. **Узкопроходный в ORDER BY** — заменил МаксШиринаПаллета для приоритета. Флаг вычисляется как `МаксШиринаПаллета <> 0`.
