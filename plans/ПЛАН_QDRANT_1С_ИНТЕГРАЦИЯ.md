## 0. Ключевые архитектурные решения

### Приоритет №1: Определение машины

**Первая и главная задача Qdrant-поиска** — по параметрам этикетки определить подходящую печатную машину (рабочий центр).

Пример: «Этикетка 295×80 мм, флексо, 7 цветов, ламинация» → поиск по всем историческим заказам → «22 Omet (N=450 заказов), Nilpeter FA 4 (N=120 заказов)» → LLM выбирает оптимальную.

### Технология как категориальный признак

Флексо/офсет/цифра/трафарет — это **точный payload-фильтр**, не размытый embedding. Машина (рабочий центр) тоже категория.

### Гибридный поиск

```
dense_vector(текст_описания)  → семантическая близость (размеры, клиент, материал)
+ filter: technology = "флексо"   → точное совпадение категории
+ filter: work_center = "22 Omet" → точная машина
+ filter: width BETWEEN 200..350  → числовой диапазон
```

### Поток данных

**Индексация:**
```
ЗаказКлиента (1С) → формирование текста → Ollama /api/embeddings → вектор
                                                                    ↓
                 числовые поля (payload) ────────────────────→ Qdrant PUT /collections/liko_orders/points
```

**Поиск (в Agent Loop):**
```
LLM вызывает search_similar_orders(query, filters)
        ↓
1С → Ollama embedding(query) → Qdrant POST /collections/liko_orders/points/search
        ↓                              ↑
   вектор + payload-фильтры ──────────┘
        ↓
   Возврат top-5 похожих заказов → контекст для LLM
```

## 2. Схема коллекции Qdrant `liko_orders`

### 2.1 Параметры коллекции

| Параметр | Значение |
|----------|----------|
| Размерность вектора | 1024 (BGE-m3) |
| Метрика расстояния | Cosine |
| Индексация payload | Включена для всех полей |

### 2.2 Payload (структурированные поля)

```json
{
  "order_id": "ЛК006640049",          // keyword — точный поиск
  "order_date": "2026-04-30T10:04:27", // datetime — фильтрация по дате
  "client": "КАВКАЗСКИЙ БЮВЕТ ООО",   // keyword
  "label_name": "Этикетка СССР 1,35 л", // текст (для векторизации)
  "size_width_mm": 295,                // integer — фильтр диапазона
  "size_height_mm": 80,                // integer
  "rapport_mm": 592.138,               // float
  "lanes_print": 4,                    // integer
  "labels_per_lane": 8,                // integer
  "core_mm": 152,                      // integer
  "technology": "флексо",              // keyword
  "colors_count": 7,                   // integer
  "material": "Пленка GMM15",          // keyword
  "has_lamination": true,              // boolean
  "has_embossing": false,              // boolean
  "has_screen": false,                 // boolean
  "work_center": "22 Omet",            // keyword
  "circulation_thousands": 200,        // integer
  "linear_meters": 14750,              // float
  "price_per_thousand_eur": 20.42,     // float
  "profitability_pct": 20.02,          // float

Размер: {size_width_mm}×{size_height_mm} мм. Рабочий центр: {work_center}.
Тираж: {circulation_thousands}K шт. Клиент: {client}.
```

## 3. Часть 1: Docker Compose — Qdrant + Ollama

### 3.1 Стратегия сохранности данных

**Проблема:** По умолчанию все данные внутри Docker-контейнера живут в его файловой системе. При `docker rm` контейнера — данные удаляются безвозвратно.

**Решение:** Docker **volumes** (тома) — данные хранятся на хосте, контейнер их только использует.

#### Типы томов и что выбрать

| Тип | Путь на хосте | Когда удаляется | Надёжность |
|-----|--------------|-----------------|------------|
| **Named volume** | Docker управляет (`/var/lib/docker/volumes/`) | Только `docker volume rm` | ★★★★☆ — нужен бэкап |
| **Bind mount** | Абсолютный путь (например `d:/project/OKIL/qdrant_storage`) | Никогда (это твоя папка) | ★★★★★ — видно в проводнике, легко бэкапить |
| **tmpfs** | RAM | При остановке контейнера | ☆☆☆☆☆ — не для нас |

**Для продакшена:** bind mount для Qdrant (уже так), named volume для Ollama.

#### Текущее состояние Qdrant

```
d:/project/OKIL/qdrant_storage/   ←  данных на ~119K векторов (Roo Code)
    ├── raft_state.json
    ├── aliases/
    └── collections/
        └── ws-5e70e849fd3d1c12/   ← коллекция Roo Code (~119K точек)
```

Qdrant уже смонтирован через bind mount → **данные переживут удаление контейнера**. Новая коллекция `liko_orders` будет в той же папке.

#### Что будет при удалении контейнера

| Сценарий | Данные Qdrant | Данные Ollama |
|----------|--------------|---------------|
| `docker stop qdrant` | ✅ Сохранены в `d:/project/OKIL/qdrant_storage/` | N/A |
| `docker rm qdrant` | ✅ Сохранены (bind mount не удаляется) | N/A |
| `docker compose down` | ✅ Сохранены (bind mount) | ✅ Сохранены (named volume) |
| `docker compose down -v` | ✅ Сохранены (bind mount НЕ удаляется флагом -v) | ❌ Удалены! (named volume удаляется) |
| Удаление папки `qdrant_orders_storage` вручную | N/A | ❌ Потеряны | N/A |

### 3.2 `docker-compose.yml` (финальная версия с двумя Qdrant)

```yaml
version: '3.8'

services:
  # Qdrant для Roo Code (уже работает — порты 6333/6334)
  qdrant_roo:
    image: qdrant/qdrant:latest
    container_name: qdrant_roo
    ports:
      - "6333:6333"   # REST API для Roo Code
      - "6334:6334"   # gRPC
    volumes:
      - d:/project/OKIL/qdrant_storage:/qdrant/storage
    restart: unless-stopped

  # Qdrant для заказов (НОВЫЙ — полностью изолирован)
  qdrant_orders:
    image: qdrant/qdrant:latest
    container_name: qdrant_orders
    ports:
      - "6335:6333"   # REST API для заказов (снаружи 6335 → внутри 6333)
      - "6336:6334"   # gRPC (снаружи 6336 → внутри 6334)
    volumes:
      - d:/project/OKIL/qdrant_orders_storage:/qdrant/storage
    restart: unless-stopped

  # Ollama — embedding-модель BGE-m3
  ollama:
    image: ollama/ollama:latest
    container_name: ollama
    ports:
      - "11434:11434"
    volumes:
      - ollama_data:/root/.ollama
    restart: unless-stopped
    environment:
      OLLAMA_KEEP_ALIVE: 24h
      OLLAMA_HOST: 0.0.0.0
    deploy:
      resources:
        limits:
          memory: 4G

volumes:
  ollama_data:
    name: liko_ollama_models
```

### 3.3 Порты (итоговая карта)

| Сервис | Внешний порт | Внутренний порт | Назначение |
|--------|-------------|----------------|------------|
| **qdrant_roo** | 6333 | 6333 | REST API для Roo Code |
| **qdrant_roo** | 6334 | 6334 | gRPC |
| **qdrant_orders** | 6335 | 6333 | REST API для заказов (1С) |
| **qdrant_orders** | 6336 | 6334 | gRPC |
| **ollama** | 11434 | 11434 | Embedding API |

**ВАЖНО:** весь BSL-код должен использовать порт **6335** для `qdrant_orders`, а не 6333!

### 5.3 Поиск (гибридный — вектор + payload-фильтры)

// Гибридный поиск похожих заказов
// Параметры:
//   ВекторЗапроса - Массив из 1024 чисел
//   Фильтры - Структура с payload-фильтрами (необязательно)
//     * min_circulation - Число
//     * max_circulation - Число
//     * technology - Строка
//     * min_profitability - Число
//     * has_lamination - Булево
//   Лимит - Число (по умолчанию 5)
&НаСервере
Функция ПоискПохожихЗаказов(ВекторЗапроса, Фильтры = Неопределено, Лимит = 5) Экспорт
    Результат = Новый Массив;
    
    Попытка
        URL = "localhost";
        Порт = 6335;  // qdrant_orders
        Путь = "/collections/liko_orders/points/search";
        
        Заголовки = Новый Соответствие;
        Заголовки.Вставить("Content-Type", "application/json");
        
        Тело = Новый Структура;
        Тело.Вставить("vector", ВекторЗапроса);
        Тело.Вставить("limit", Лимит);
        Тело.Вставить("with_payload", Истина);
        
        // Если есть фильтры — добавляем
        Если Фильтры <> Неопределено Тогда
            Условия = Новый Массив;
            
            Если Фильтры.Свойство("min_circulation") Тогда
                Условие = Новый Структура;
                Условие.Вставить("key", "circulation_thousands");
                Условие.Вставить("range", Новый Структура("gte", Фильтры.min_circulation));
                Условия.Добавить(Условие);
            КонецЕсли;
            
            Если Фильтры.Свойство("max_circulation") Тогда
                Условие = Новый Структура;
                Условие.Вставить("key", "circulation_thousands");
                Условие.Вставить("range", Новый Структура("lte", Фильтры.max_circulation));
                Условия.Добавить(Условие);
            КонецЕсли;
            
            Если Фильтры.Свойство("technology") Тогда
                Условие = Новый Структура;
                Условие.Вставить("key", "technology");
                Условие.Вставить("match", Новый Структура("value", Фильтры.technology));
                Условия.Добавить(Условие);
            КонецЕсли;
            
            Если Фильтры.Свойство("min_profitability") Тогда
                Условие = Новый Структура;
                Условие.Вставить("key", "profitability_pct");
                Условие.Вставить("range", Новый Структура("gte", Фильтры.min_profitability));
                Условия.Добавить(Условие);
            КонецЕсли;
            
            Если Фильтры.Свойство("has_lamination") Тогда
                Условие = Новый Структура;
                Условие.Вставить("key", "has_lamination");

## 9. Скрытые зависимости и риски

| Риск | Меры |
|------|------|
| Ollama может не хватить RAM (4GB) при большой нагрузке | Лимит в docker-compose, BGE-m3 требует ~2GB |
| 1С HTTPСоединение не поддерживает localhost | Использовать `127.0.0.1` или `host.docker.internal` |
| Долгая индексация (10K заказов × 0.2 сек = ~30 мин) | Пакетный режим, индексация ночью |
| Qdrant уже занят Roo Code | Отдельная коллекция `liko_orders`, конфликта нет |
| Изменение заказа после индексации | Периодическая реиндексация или индексация при проведении |
