# ФАЗА 1: Итоговый план V2 (с Multi-file + Confidence + Interactive refinement)

## Архитектурное разделение

Пользователь уточнил требования. Теперь нужны **два отдельных процесса**:

### СТАДИЯ 1: Индексирование (background, один раз или периодически)
```
1С (100K+ заказов) + Docling (Phase 1: текст из макетов)
                    ↓
                Qdrant (orders_phase1)
```
- Берем данные из 1С (ЗаказКлиента с макетами)
- Извлекаем текст через Docling (Phase 1)
- Индексируем в Qdrant с BM25 sparse vectors
- Также сохраняем точные 1С параметры как payload

### СТАДИЯ 2: Поиск параметров новой макеты + ИНТЕРАКТИВНОЕ УТОЧНЕНИЕ (real-time)
```
Менеджер загружает:
- PDF/JPG макет
- Доп файлы (PNG, DOCX, TXT, JPG)
- Текст в поле ввода (комментарии)
    ↓
Phase 0 (Vision LLM) → визуальные параметры
    ↓
Phase 1 (Docling)   → текст макеты + доп файлы
    ↓
RAG: поиск TOP-3 заказов в Qdrant по Phase1 текст
    ↓
LLM (prompt) → объединяет все + confidence scores для каждого параметра
    ↓
Confidence scoring:
- Если confidence параметра < порог → запросить уточнение у менеджера
- Иначе → автоматически определено
    ↓
[Optional] Interactive loop: менеджер отвечает на вопросы
    ↓
JSON параметров → программное создание в 1С
```

---

## Ключевые отличия от V1

1. **Multi-file support** - не только основной PDF, но и JPG, PNG, DOCX, TXT
2. **Text input field** - менеджер может добавить комментарии/дополнительную информацию
3. **Confidence scoring** - каждый параметр получает оценку надежности
4. **Configurable thresholds** - настраиваемые пороги с дефолтными значениями:
   - `conf_threshold_default = 70` (%)
   - `conf_threshold_print_tech = 80` (% для технологии печати)
   - `conf_threshold_work_center = 85` (% для рабочего центра)
5. **Interactive refinement** - если confidence < порог → система задает вопросы

### ШАГ 2: Создать Docling FastAPI сервис в Docker

**Путь**: `services/docling/` 
**Функционал**:
- Endpoint: `POST /api/parse`
- Параметры: 
  - `file` (multipart) - основной файл (PDF, JPG, PNG, DOCX, TXT)
  - `additional_files` (multipart, optional) - доп файлы
  - `text_input` (string, optional) - текст от менеджера
  
- Ответ: 
```json
{
  "main_file": {
    "text": "извлеченный текст из основного файла",
    "confidence": 0.95,
    "images": ["base64 изображений"],
    "tables": [{"text": "...", "type": "table"}],
    "file_type": "pdf"
  },
  "additional_files": [
    {
      "filename": "spec.txt",
      "text": "содержимое",
      "confidence": 1.0,
      "file_type": "txt"
    }
  ],
  "manager_input": "комментарии менеджера",
  "combined_text": "объединенный текст из всех файлов + комментарии"
}
```

**Поддерживаемые форматы**:
- PDF (через Docling)
- JPG, PNG (через Docling с OCR)
- TXT, DOCX (простое чтение текста)

### ШАГ 5: Реализовать Hybrid Search функция

**Где**: Python сервис или Common module в 1С
**Что делает**:
1. Берет combined_text из Phase 1 (новый макет + доп файлы + менеджерский текст)
2. Разбивает на токены для BM25
3. Создает dense vector (эмбединг)
4. Ищет в Qdrant:
   - Sparse (BM25): текст токены (с весом 0.3)
   - Dense: семантический поиск (с весом 0.7)
5. Мержит результаты → TOP-3

**Результат**: список похожих заказов с 1С параметрами

### ШАГ 6: Реализовать Confidence Scoring система

**Что**: Функция, которая вычисляет confidence для каждого параметра

**Input**:
- Phase 0 параметры (от Vision LLM)
- Phase 1 combined_text (от Docling + доп файлы + менеджер)
- TOP-3 похожих заказов из Qdrant

**Алгоритм confidence**:
```
для каждого параметра (print_tech, work_center, material, colors, ...):
  confidence = (
    0.3 * phase0_confidence +
    0.4 * rag_match_score (насколько похожи на TOP-3) +
    0.3 * text_clarity (насколько явно текст указывает на параметр)
  )
```

**Output**: JSON с параметрами + confidence scores:
```json
{
  "parameters": {
    "work_center": {
      "value": "Печать_Офсет",
      "confidence": 0.92,
      "source": "phase0+rag"
    },
    "print_technology": {
      "value": "Офсет",
      "confidence": 0.88,
      "source": "phase1+rag"
    },
    "material_type": {
      "value": "Плёнка",
      "confidence": 0.65,
      "source": "rag_only"
    }
  },
  "thresholds": {
    "default": 70,
    "print_tech": 80,
    "work_center": 85
  },
  "uncertain_parameters": [
    {
      "name": "material_grammar",
      "reason": "confidence 0.65 < threshold 70"
    }
  ]
}
```

**Configurable thresholds** (в 1С настройках или env переменных):
- `CONF_THRESHOLD_DEFAULT = 70` (для большинства параметров)
- `CONF_THRESHOLD_PRINT_TECH = 80` (критичный параметр)
- `CONF_THRESHOLD_WORK_CENTER = 85` (критичный параметр)
- Можно переопределить через UI

### ШАГ 7: Реализовать RAG + LLM pipeline с интерактивностью

**Что**: Функция, которая объединяет все в один prompt для LLM

**Input**:
- Новый PDF Phase 0 параметры (от Vision)
- Новый PDF Phase 1 combined_text (от Docling)
- TOP-3 похожих заказов (из Qdrant)
- Confidence scores для каждого параметра

**Output**: JSON с параметрами ИЛИ список вопросов для менеджера

**Prompt структура**:
```
Ты — система определения параметров заказа этикеток.

НОВЫЙ ЗАКАЗ (из загруженного макета):
- Фаза 0 (Vision): {размеры, ориентация, тип печати}
- Фаза 1 (Docling): {текст этикетки}
- Дополнительные файлы: {содержимое spec.txt, spec.docx, ...}
- Комментарий менеджера: "{текст от менеджера}"

ПОХОЖИЕ ЗАКАЗЫ ИЗ ИСТОРИИ (TOP-3):
1. Заказ #123: рабочий центр={}, технология={}, материал={}, ...
2. Заказ #456: ...
3. Заказ #789: ...

ТРЕБОВАНИЯ К CONFIDENCE:
- Если параметр <PRINT_TECH> не может быть определен с confidence >= 80%, 
  вместо значения верни вопрос: "Какая технология печати?" с вариантами
- Если параметр <WORK_CENTER> не может быть определен с confidence >= 85%, 
  верни вопрос менеджеру

На основе сравнения, определи:
- Рабочий центр (печать, флексо, глубокая, цифра, комбо)
- Технологию
- Материал
- Типы цветов
- Граммажа
- Доп работы (конвертация, вырубка, и т.д.)
- Прочие параметры

Ответ в JSON: {...}
```

**Возможные сценарии**:
1. Все параметры определены с высокой confidence → вернуть JSON параметров
2. Некоторые параметры низкой confidence → вернуть JSON с параметрами + список вопросов
3. Критичные параметры не определены → вернуть только вопросы
