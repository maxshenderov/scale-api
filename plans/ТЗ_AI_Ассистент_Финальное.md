## 1. Контекст и бизнес-цель

### 1.1 Компания и предметная область

**Компания:** Лико — типография, специализирующаяся на печати этикеток для товаров широкого потребления (шампуни, бутылки, бытовая химия, алкогольная продукция и т. п.).

**Система учёта:** 1С:Предприятие (конфигурация `УправлениеПредприятием` с расширениями `Лико_*`).

**Центральная сущность:** Документ [`ЗаказКлиента`](1c/ERP/Конф/Documents/ЗаказКлиента.xml) содержит:
- Параметры этикетки (размеры, раппорт, раскладка, материал)
- Технологические параметры (вид печати, краски, ламинация, тиснение и т. д.)
- Экономические данные (цена, рентабельность, себестоимость)
- Файлы оригинал-макетов (PDF/JPG)
- Табличные части: `Цвета` (операции печати), `ВидыРабот`, `Товары`, `Производство`

### 1.2 Проблемы, которые решает система

1. **Технолог** тратит время на анализ макета и параметров заказа вручную
2. **Экономист** не имеет быстрого способа оценить рентабельность и риски
3. **Менеджер** не может быстро предложить альтернативные технологии (флексо/офсет/цифра)
4. **Система не автоматизирует** создание заказов из входящих PDF-макетов
5. **Нет RAG-поиска** похожих заказов для быстрого заполнения параметров

### 1.3 Глобальная цель

Создать **AI-ассистент**, который:
- **Этап 0 (MVP):** Анализирует существующий заказ в 1С и возвращает HTML-форму с технической и экономической оценкой
- **Этап 1:** Создаёт заказ в 1С из входящего PDF-макета, используя RAG для поиска похожих заказов
- **Этап 2:** Рассчитывает стоимость заказа по разным технологиям (флексо, офсет, цифра, трафарет)
- **Этап 3:** Анализирует тендеры и рассчитывает вероятность выигрыша

## 3. Этапы разработки

### Этап 0 (2–3 недели): Кнопка «AI-Ассистент» в 1С

**Цель:** MVP — анализ существующего заказа и возврат HTML-оценки.

**Входные данные:**
- JSON заказа из 1С (шапка + табличные части)
- PDF/JPG оригинал-макета (base64)

**Выходные данные:**
- HTML-форма с блоками:
  - **Техническая оценка** (для технолога)
  - **Экономическая оценка** (для экономиста)
  - **Анализ макета** (что видно на PDF)
  - **Чек-лист готовности** (что заполнено, что нет)

**Компоненты:**
- Кнопка в форме ЗаказКлиента
- Модуль `Лико_АИАссистентДанные` (сбор данных)
- Модуль `Лико_АИАссистентКлиент` (отображение)
- FastAPI эндпоинт `POST /api/v1/analyze`
- Нормализатор JSON
- LLM-промпт для анализа

### Этап 1 (4–6 недель): Формирование заказа из PDF

**Цель:** Создание заказа в 1С из входящего PDF-макета с использованием RAG.

**Входные данные:**
- PDF/JPG макета от клиента (первичный, без технологических параметров)

**Выходные данные:**
- JSON параметров заказа (технология, краски, материал и т. д.)
- Human-in-the-loop форма для подтверждения
- Программное создание заказа в 1С

**Компоненты:**
- FastAPI эндпоинт `POST /api/v1/create-from-pdf`
- PDF-парсер (IBM OpenRAG)
- RAG-индексер (Qdrant)
- Production-промпт для извлечения параметров
- Модуль `Лико_ПрограммноеСозданиеДокументовСправочников` (создание заказа)

### Этап 1.5 (3–4 недели): Индексация базы заказов

**Цель:** Подготовка RAG-индекса для поиска похожих заказов.

**Входные данные:**
- Все заказы из 1С (~5000–10000 заказов)
- PDF-макеты (из хранилища 1С)

**Выходные данные:**
- Qdrant-коллекция с векторами заказов
- PostgreSQL-таблица метаданных

**Компоненты:**
- Скрипт индексации (`rag_indexer.py`)
- Qdrant-клиент
- PostgreSQL-клиент

### Этап 2 (6–8 недель): Мультитехнологический расчёт стоимости

**Цель:** Рассчитать стоимость заказа по разным технологиям и сравнить.

**Входные данные:**
- JSON заказа
- Параметры технологий (флексо, офсет, цифра, трафарет)

**Выходные данные:**
- Таблица вариантов с ценами и рентабельностью
- Рекомендация оптимальной технологии

**Компоненты:**
- FastAPI эндпоинт `POST /api/v1/cost-analysis`
- Модуль `cost_calculator.py`
- Интеграция с 1С для получения нормативов

### Этап 3 (8–10 недель): Анализ тендеров

**Цель:** Поиск тендеров, расчёт стоимости, вероятность выигрыша.

**Входные данные:**
- Параметры тендера (размер, материал, технология)
- Исторические данные о выигранных/проигранных тендерах

**Выходные данные:**
- Список подходящих тендеров
- Расчётная стоимость и рентабельность
- Вероятность выигрыша (%)

**Компоненты:**
- FastAPI эндпоинт `POST /api/v1/tenders/analyze`
- Модуль `tender_analyzer.py`
- Интеграция с источниками тендеров (API, парсинг)

| Поле | Тип | Назначение |
|------|-----|-----------|
| `id` | string | Уникальный ID заказа |
| `vector` | float[] | 1536-мерный вектор (от OpenAI Embedding) |
| `order_id` | string | Номер заказа в 1С |
| `label_name` | string | Название этикетки |
| `size_mm` | string | Размеры (ширина×высота) |
| `technology` | string | Технология печати (флексо/офсет/цифра/трафарет) |
| `colors_count` | int | Количество цветов |
| `material` | string | Основной материал |
| `has_lamination` | bool | Наличие ламинации |
| `has_embossing` | bool | Наличие тиснения |
| `work_center` | string | Рабочий центр |
| `circulation_thousands` | int | Тираж (тыс. шт) |
| `price_per_thousand_eur` | float | Цена за 1000 шт (EUR) |
| `profitability_pct` | float | Рентабельность (%) |
| `created_date` | string | Дата создания заказа |
| `pdf_file_path` | string | Путь к PDF в S3 |
| `text_content` | string | Текстовое описание заказа |

### 5.3 Пайплайн индексации

1. **Выгрузка заказов из 1С** (ежедневно, ночью)
   - Запрос всех заказов за последний месяц
   - Сериализация в JSON
   - Загрузка PDF-макетов из хранилища 1С

2. **Нормализация данных**
   - Преобразование в стандартный формат
   - Очистка текста
   - Извлечение ключевых параметров

3. **Генерация векторов**
   - Текстовое описание заказа → OpenAI Embedding
   - Сохранение в Qdrant

4. **Индексация в Qdrant**
   - Создание/обновление коллекции
   - Сохранение payload с метаданными

5. **Резервная копия в PostgreSQL**
   - Сохранение метаданных для быстрого поиска
   - Логирование операций

### 5.4 Обработка новых заказов

При создании нового заказа в 1С:
1. Триггер в 1С отправляет JSON в FastAPI
2. FastAPI нормализует данные
3. Генерирует вектор
4. Добавляет в Qdrant
5. Сохраняет в PostgreSQL
