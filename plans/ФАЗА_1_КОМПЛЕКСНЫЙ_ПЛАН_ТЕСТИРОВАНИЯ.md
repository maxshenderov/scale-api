# ФАЗА 1: Комплексный план тестирования end-to-end

## Обзор тестирования

Тестирование покрывает полный цикл работы системы:
- **Setup**: инициализация всех сервисов
- **Unit tests**: тестирование отдельных компонентов
- **Integration tests**: тестирование взаимодействия компонентов
- **E2E tests**: полный workflow (загрузка PDF → анализ → создание заказа)
- **Performance**: проверка производительности
- **Acceptance**: проверка функциональности против требований

## ЧАСТЬ 3: INTEGRATION ТЕСТИРОВАНИЕ

### 3.1 Тестирование Phase1 → Phase0 → RAG LLM

**Сценарий 3.1.1: Полный цикл анализа**

```bash
# 1. Загруженный PDF макет
PDF_FILE="sample_order_macket.pdf"

# 2. Фаза 1: Парсинг текста
curl -X POST http://localhost:8001/api/parse \
  -F "file=@$PDF_FILE" > phase1_output.json

# 3. Извлекаем текст из Фазы 1
PHASE1_TEXT=$(jq -r '.text' phase1_output.json)

# 4. Фаза 0: Vision анализ макета (mock)
PHASE0_DATA=$(cat <<EOF
{
  "label_width": 50,
  "label_height": 100,
  "orientation": "portrait",
  "print_type": "color",
  "estimated_colors": 4,
  "confidence": 0.85
}
EOF
)

# 5. RAG LLM: Генерирование параметров
curl -X POST http://localhost:8003/api/generate-order-parameters \
  -H "Content-Type: application/json" \
  -d "{
    \"phase0\": $PHASE0_DATA,
    \"phase1\": {
      \"text\": \"$PHASE1_TEXT\",
      \"confidence\": 0.92
    }
  }" > order_parameters.json

# 6. Проверяем результаты
jq '.parameters | keys' order_parameters.json
# [
#   "work_center",
#   "print_technology",
#   "material_type",
#   "label_width",
#   "label_height",
#   ...
# ]
```

## ЧАСТЬ 4: END-TO-END ТЕСТИРОВАНИЕ

### 4.1 Полный workflow (загрузка → анализ → создание заказа)

**Тест 4.1.1: Основной сценарий**

Шаги:
1. Менеджер загружает PDF макет в обработку AIАссистент
2. Система выполняет Phase1 парсинг (Docling)
3. Система получает Phase0 параметры (Vision LLM)
4. Гибридный поиск находит TOP-3 похожих заказов
5. RAG LLM генерирует параметры нового заказа
6. Система вычисляет confidence scores
7. Если все параметры уверены (> threshold) → создание заказа в 1С
8. Если есть неопределённые параметры → вывод вопросов менеджеру
9. Менеджер отвечает на вопросы → пересчет
10. Создание заказа в 1С с финальными параметрами

Ожидаемые результаты:
- Время обработки: 30-60 сек (в зависимости от размера PDF)
- Точность определения work_center: > 90%
- Точность определения print_technology: > 85%
- Точность определения material_type: > 80%

**Тест 4.1.2: Сценарий с требованиями уточнения**

Если confidence параметра < threshold:
1. Система выводит вопрос менеджеру
2. Менеджер выбирает вариант из dropdown
3. Система пересчитывает с учетом ответа
4. Новые confidence scores выше
