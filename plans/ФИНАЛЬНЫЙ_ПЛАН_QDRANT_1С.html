🔄 Qdrant + 1С: Гибридный поиск похожих заказов

Интеграция векторной БД Qdrant с конфигурацией 1С:ERP для семантического поиска исторических заказов по параметрам этикетки. Только BSL, без Python.

✅ Готов к реализации 📅 08–12.05.2026 🧩 Стек: 1С BSL + Qdrant + Ollama

🎯 Ключевые архитектурные решения

Приоритет №1: Определение машины

Первая и главная задача Qdrant-поиска — по параметрам этикетки определить подходящую печатную машину (рабочий центр).

Пример: «Этикетка 295×80 мм, флексо, 7 цветов, ламинация» → поиск → «22 Omet (N=450), Nilpeter FA 4 (N=120)» → LLM выбирает оптимальную.

Гибридный поиск

dense_vector(текст_описания) → семантическая близость
+ filter: technology = "флексо"      → точное совпадение
+ filter: work_center = "22 Omet"    → точная машина
+ filter: width BETWEEN 200..350     → числовой диапазон

🏷️ Наименование → тип продукции

Наименование этикетки содержит скрытый тип продукции, которого нет в явном виде в 1С:

НаименованиеСкрытый тип
"Этикетка СССР 1,35 л"Самоклеящаяся для напитков
"Пленка для йогурта 500мл"Термоусадочная плёнка
"Вплавляемая IML 500мл"IML-этикетка

✅ Решение: поле inferred_product_type — эвристика из наименования

🧹 Фильтрация «шума» в данных

Не все исторические заказы репрезентативны:

  • ❌ Пробники (тираж < 1K) — аномальные параметры
  • ❌ Эксперименты — один раз, не типовое
  • ❌ Убыточные заказы — рентабельность < 0
  • ✅ Повторные заказы — надёжный сигнал

✅ Решение: payload-фильтры + группировка по work_center

Эвристика: определение типа продукции из наименования (подробно)

Как это работает

Наименование этикетки в 1С — это свободная строка, но она содержит скрытые маркеры типа продукции:

Маркер в наименованииВыводПочему важно для машины
"этикет" + "вплав" / "iml"Вплавляемая этикеткаТребует машину с модулем вплавки
"этикет" + "термоусад"Термоусадочная этикеткаДругая технология усадки, другая машина
"этикет" + "вино" / "алкоголь" / "пиво"Этикетка для напитковСпециальные требования к влагостойкости
"этикет" + "масло" / "авто"Этикетка для масел/химииСтойкость к маслам, другие краски
"этикет" + "фармацевт" / "лекарств"Фармацевтическая этикеткаВысокие требования к качеству печати
"этикет" + "пищев" / "продукт" / "йогурт"Пищевая этикеткаКонтакт с пищей, сертификация
"этикет" (остальное)Самоклеящаяся этикеткаСтандартная машина
"пленк" / "рукав"Гибкая упаковка/рукавМашина с модулем ламинации
"пакет"ПакетПакетная машина, не рулонная
"упаковк"УпаковкаШирокоформатная машина
"рулон" / "термоэтикет"Термоэтикетка (рулон)Термоголовка, не флексо

Полная эвристика (BSL)

//+Лико m.shenderov 12.05.2026
// Определяет тип продукции из наименования этикетки
// Возвращает: строка-идентификатор типа продукции
Функция ОпределитьТипПродукцииПоНаименованию(Наименование)
    Нижнее = НРег(Наименование);

    // ===== ЭТИКЕТКИ =====
    Если Найти(Нижнее, "этикет") > 0 Тогда

        // Вплавляемые (IML)
        Если Найти(Нижнее, "вплав") > 0
            Или Найти(Нижнее, "iml") > 0
            Или Найти(Нижнее, "in-mold") > 0 Тогда
            Возврат "вплавляемая_этикетка";
        КонецЕсли;

        // Термоусадочные
        Если Найти(Нижнее, "термоусад") > 0
            Или Найти(Нижнее, "sleeve") > 0 Тогда
            Возврат "термоусадочная_этикетка";
        КонецЕсли;

        // Термоэтикетки (рулонные)
        Если Найти(Нижнее, "термоэтикет") > 0
            Или Найти(Нижнее, "термо") > 0 Тогда
            Возврат "термоэтикетка";
        КонецЕсли;

        // Для напитков (алкоголь, вино, пиво, вода)
        Если Найти(Нижнее, "вино") > 0
            Или Найти(Нижнее, "алкоголь") > 0
            Или Найти(Нижнее, "пиво") > 0
            Или Найти(Нижнее, "водк") > 0
            Или Найти(Нижнее, "коньяк") > 0
            Или Найти(Нижнее, "виски") > 0
            Или Найти(Нижнее, "минеральн") > 0
            Или Найти(Нижнее, "напитк") > 0
            Или Найти(Нижнее, "ссср") > 0 Тогда  // "СССР" — бренд напитков
            Возврат "этикетка_для_напитков";
        КонецЕсли;

        // Для масел и автохимии
        Если Найти(Нижнее, "масло") > 0
            Или Найти(Нижнее, "авто") > 0
            Или Найти(Нижнее, "моторн") > 0
            Или Найти(Нижнее, "химия") > 0 Тогда
            Возврат "этикетка_для_масел_химии";
        КонецЕсли;

        // Фармацевтические
        Если Найти(Нижнее, "фармацевт") > 0
            Или Найти(Нижнее, "лекарств") > 0
            Или Найти(Нижнее, "медицинск") > 0
            Или Найти(Нижнее, "таблетк") > 0 Тогда
            Возврат "фармацевтическая_этикетка";
        КонецЕсли;

        // Пищевые
        Если Найти(Нижнее, "пищев") > 0
            Или Найти(Нижнее, "продукт") > 0
            Или Найти(Нижнее, "йогурт") > 0
            Или Найти(Нижнее, "молоко") > 0
            Или Найти(Нижнее, "сыр") > 0
            Или Найти(Нижнее, "мяс") > 0 Тогда
            Возврат "пищевая_этикетка";
        КонецЕсли;

        // По умолчанию — самоклеящаяся
        Возврат "самоклеящаяся_этикетка";

    // ===== ПЛЁНКИ И РУКАВА =====
    ИначеЕсли Найти(Нижнее, "пленк") > 0
        Или Найти(Нижнее, "рукав") > 0
        Или Найти(Нижнее, "film") > 0 Тогда
        Возврат "гибкая_упаковка";

    // ===== ПАКЕТЫ =====
    ИначеЕсли Найти(Нижнее, "пакет") > 0
        Или Найти(Нижнее, "bag") > 0 Тогда
        Возврат "пакет";

    // ===== УПАКОВКА =====
    ИначеЕсли Найти(Нижнее, "упаковк") > 0
        Или Найти(Нижнее, "packaging") > 0 Тогда
        Возврат "упаковка";

    // ===== ТЕРМОЭТИКЕТКИ (без слова "этикет" в начале) =====
    ИначеЕсли Найти(Нижнее, "термоэтикет") > 0
        Или Найти(Нижнее, "термо") > 0 Тогда
        Возврат "термоэтикетка";

    // ===== НЕ ОПРЕДЕЛЕНО =====
    Иначе
        Возврат "неопределено";
    КонецЕсли;

Как inferred_product_type используется

ЭтапКак используется
ИндексацияЗаполняется в payload точки Qdrant при индексации заказа
Текст для embeddingДобавляется в text_for_embedding: "{label_name} — {inferred_product_type}. ..."
Поиск (фильтр)LLM определяет inferred_product_type из запроса → 1С добавляет payload-фильтр
ГруппировкаРезультаты группируются по work_center ВНУТРИ одного inferred_product_type

Ограничения и fallback

  • Покрытие: ~75% наименований определяются эвристикой
  • ~25% → "неопределено": нестандартные наименования, аббревиатуры, коды
  • Fallback: если "неопределено" — поиск идёт без фильтра по типу продукции (только вектор + другие фильтры)
  • Улучшение: LLM-инференс при индексации (дороже, но точнее) — отдельный этап

LLM вызывает search_similar_orders(query, filters) ↓ 1С → Ollama embedding(query) → Qdrant POST search (top-20) ↓ ↑ вектор + payload-фильтры ──────────┘ ↓ СгруппироватьПоМашинам(top-20) ↓ {work_centers: [ {name: "22 Omet", count: 45, avg_profit: 20.5%, samples: [...]}, {name: "Nilpeter FA 4", count: 12, avg_profit: 18.2%, samples: [...]} ]} ↓ LLM анализирует статистику → рекомендует машину

⚠️ Риски и меры

🧠
Ollama может не хватить RAM (4 GB) — BGE-m3 требует ~2 GB. Решение: лимит deploy.resources.limits.memory: 4G в docker-compose.
🌐
1С HTTPСоединение не поддерживает localhost — использовать 127.0.0.1 или host.docker.internal.
⏱️
Долгая индексация — 10K заказов × 0.2 сек ≈ 30 мин. Решение: пакетный режим, ночной запуск.
🗄️
Qdrant занят Roo Code — отдельная коллекция liko_orders, отдельный порт 6335. Конфликта нет.
🔄
Изменение заказа после индексации — периодическая реиндексация или индексация при проведении документа.
🏷️
Эвристика типа продукции может ошибаться — не все наименования содержат явные маркеры. Решение: LLM-инференс при индексации (дороже, но точнее) или ручная корректировка.
🧹
Пробники могут не быть помечены — если в 1С нет флага «тестовый заказ», эвристика по тиражу (< 1K) может пропустить некоторые. Решение: комбинировать несколько критериев (тираж + рентабельность + repeat_count).
