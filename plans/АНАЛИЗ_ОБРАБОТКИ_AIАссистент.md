## 4. Режим 1: Анализ заказа через Agent Loop

### Точка входа
Кнопка **"Анализ заказа"** → `АнализЗаказа(Команда)` (стр. 373) → `ОтправитьЗапросАнализаЗаказа()` (стр. 425) → `AgentLoop()` (стр. 1635)

### Алгоритм AgentLoop

```
1. ЗадачиАнализа() → ПараметрыЗадачи (Персона, Название, Иконка)
2. СобратьСистемныйПромпт() → системный промпт с персоной + инструкция возврата JSON
3. История = [system_message, user_message("Проанализируй заказ...")]
4. Инструменты = ОписаниеИнструментов() — 11 инструментов для получения данных
5. ЦИКЛ до 10 итераций:
   a. ОтправитьЗапросКLLM_сИнструментами() → {Успех, Сообщение, ПолныйОтвет}
   b. Если message.tool_calls:
      - Добавить assistant message в историю
      - ВыполнитьИнструменты() → JSON-результаты каждого инструмента
      - Добавить tool-messages в историю → продолжить цикл
   c. Если message.content:
      - ИзвлечьJSONИзОтвета() (4 попытки парсинга)
      - JSON_Анализа_в_HTML() → финальный HTML-отчёт
      - Если не JSON → фаза 2 (просим переформатировать)
      - Если фаза 2 не помогла → fallback HTML
```

### 11 инструментов (function calling)

| № | Имя инструмента | Источник данных |
|---|-----------------|-----------------|
| 1 | `get_order_header` | Шапка заказа: номер, дата, клиент, менеджер, статус, тип, состояние, РЦ |
| 2 | `get_label_params` | Шапка: ширина/высота этикетки, раппорт, ручьи, шаг, длина, тираж |
| 3 | `get_production_flags` | Шапка: цифровой, ламинация, тиснение, трафарет, конгрев, нумератор |
| 4 | `get_colors` | ТЧ Цвета: краски, грамматура, заливка, пантоны, секции |
| 5 | `get_costs` | РегСвед `Лико_Затраты`: статьи затрат, РЦ, суммы, метраж |
| 6 | `get_production_params` | РегСвед `Лико_ПараметрыПроизводстваЗаказа`: скорости, время, себестоимость |
| 7 | `get_metrics` | Шапка: тираж, метраж пм/кв.м, время, нормо-часы, клики, ролики |
| 8 | `get_economics` | Шапка: сумма, валюта, себестоимость, рентабельность план, доход план |
| 9 | `get_quality` | Шапка: орфография, ШК, ОТК, дизайнер, образец цвета |
| 10 | `get_order_items` | ТЧ Товары: номенклатура, кол-во, цена, втулка, намотка, оригинал-макет |
| 11 | `get_sections` | ТЧ Секции: секции с полными параметрами технологии |

## 5. Режим 2: Анализ макета через Vision LLM

### Точка входа
Кнопка **"Извлечь параметры макета"** → `ИзвлечьПараметрыМакета(Команда)` (стр. 3555)

### Два источника файлов

**Источник A: Файлы с диска** (выбор через диалог)
- Кнопка **"..."** → `ВыбратьФайлМакета(Команда)` → диалог множественного выбора
- Сохраняется в клиентскую переменную `МассивПутейМакетов`

**Источник B: Файлы из ОригиналМакетов заказа**
- `ПолучитьВсеФайлыМакетовИзЗаказаСервер(Заказ)` (стр. 3503)
- Цикл по ТЧ `Товары.ОригиналМакет` → запрос в `Справочник.Лико_ОригиналМакеты.Файлы`
- Возвращает `{СсылкаМакет, ИдентификаторФайла, ИмяФайла, GUID_Объекта, GUID_Строки}`

### Получение двоичных данных
`ПолучитьДвоичныеДанныеФайлаМакетаДваСпособа(Параметры)` (стр. 3188):
- Способ **"FileStore"**: ADODB → SQL FileStore (GUIDOM + GUIDRow)
- Способ **"Папка"**: прямое чтение файла с диска

### Vision LLM запрос
`ОтправитьИзображениеВVisionLLM(ДвоичныеДанные, Расширение, Настройки)` (стр. 3319):
- Конвертация в Base64 → DataURL
- Формат запроса: `[{"type":"text", "text": ПРОМПТ}, {"type":"image_url", "image_url":{"url": DataURL}}]`
- Параметры: `response_format: {"type": "json_object"}`

### JSON-схема от Vision LLM

```json
{
  "label": {
    "width_mm": 72.5,
    "height_mm": 180.0,
    "shape": "rectangle"
  },
  "layout": {
    "across": 1,
    "along": 1,
    "total_per_sheet": 1
  },
  "colors": {
    "count": 4,
    "list": ["PANTONE 485 C", "PANTONE 7687 C", "Black", "White"]
  },
  "finishing": {
    "varnish": "glossy",
    "foil": null,
    "embossing": false
  },
  "content": {
    "has_barcode": true,
    "barcode_type": "EAN-13",
    "languages": ["ru"]
  },
  "label_type": "СамоклеящаясяЭтикетка",
  "technology": "Флексо",
  "material_hint": "плёнка белая",
  "confidence": 0.85
}
```

## 7. ПЛАНИРУЕМЫЕ ИЗМЕНЕНИЯ

### Идея
Перед индексацией автоматически запустить Vision LLM анализ первого файла из ОригиналМакета заказа, и использовать полученный JSON для обогащения payload.

### Новая сигнатура функции
```bsl
Функция СформироватьДанныеДляИндексации(ЗаказСсылка, ПараметрыМакета = Неопределено) Экспорт
```

Параметр `ПараметрыМакета` — это распарсенный JSON от Vision LLM (тип `Соответствие/Структура`).

### Обогащение payload из ПараметрыМакета

| Поле payload | Логика обогащения |
|-------------|-------------------|
| `technology` | Из `ПараметрыМакета.technology` если пустое в заказе |
| `label_type` | Из `ПараметрыМакета.label_type` |
| `label_shape` | Из `ПараметрыМакета.label.shape` (новое поле) |
| `size_width_mm` | Из `ПараметрыМакета.label.width_mm` если 0 в заказе |
| `size_height_mm` | Из `ПараметрыМакета.label.height_mm` если 0 в заказе |
| `lanes_print` | Из `ПараметрыМакета.layout.across` если 0 в заказе |
| `labels_per_rapport` | Из `ПараметрыМакета.layout.along` (новое поле) |
| `material` | Из `ПараметрыМакета.material_hint` если пустой в заказе |
| `has_embossing` | ИЛИ с `ПараметрыМакета.finishing.embossing` |
| `varnish_type` | Из `ПараметрыМакета.finishing.varnish` (новое поле) |
| `foil_type` | Из `ПараметрыМакета.finishing.foil` (новое поле) |
| `has_barcode` | Из `ПараметрыМакета.content.has_barcode` (новое поле) |
| `maket_colors_list` | Из `ПараметрыМакета.colors.list` — список пантонов (новое) |
| `maket_colors_count` | Из `ПараметрыМакета.colors.count` если colors пустые |
| `maket_confidence` | Из `ПараметрыМакета.confidence` (качество анализа) |
| `maket_analyzed` | Булево — флаг что анализ макета был выполнен |

### Обогащение текста для эмбеддинга
- Если технология из макета — добавить в текст
- Если тип этикетки из макета — добавить в текст
- Если пантоны из макета — добавить список
- Если форма — добавить (прямоугольная/круглая и т.д.)
- Если лак/фольга — добавить

### Изменения кнопки ИндексироватьЗаказQdrant

**Новый алгоритм (клиентский, т.к. нужен ADODB):**
```
1. Проверить заказ
2. ПолучитьВсеФайлыМакетовИзЗаказаСервер(Заказ) → список файлов
3. Если файлы есть:
   a. Взять первый файл (ИмяФайла, GUID_Объекта, GUID_Строки)
   b. ПолучитьДвоичныеДанныеФайлаМакетаДваСпособа() → двоичные данные
   c. ОтправитьИзображениеВVisionLLM() → РезультатVision
   d. Если РезультатVision.Успех:
      - ПарситьJSONМакета(РезультатVision.Ответ) → ПараметрыМакета
   e. Иначе: ПараметрыМакета = Неопределено
4. Иначе: ПараметрыМакета = Неопределено
5. ИндексироватьЗаказСервер(Заказ, ПараметрыМакета) → Данные
6. Показать результат в htmlЗаказ
```

## 8. Диаграмма нового потока индексации

```
Нажата кнопка "🔍 Qdrant"
    │
    ▼
Проверить Заказ
    │
    ▼
ПолучитьВсеФайлыМакетовИзЗаказаСервер(Заказ)
    │
    ├─── Нет файлов ──→ ПараметрыМакета = Неопределено
    │
    └─── Есть файлы
              │
              ▼
         ПолучитьДвоичныеДанныеФайлаМакетаДваСпособа(первый файл)
              │
              ▼
         ОтправитьИзображениеВVisionLLM(двоичные, расширение, настройки)
              │
              ├─── Ошибка ──→ ПараметрыМакета = Неопределено
              │
              └─── Успех
                        │
                        ▼
                   Распарсить JSON ответа → ПараметрыМакета
    │
    ▼
ИндексироватьЗаказСервер(Заказ, ПараметрыМакета)
    │
    ▼
СформироватьДанныеДляИндексации(ЗаказСсылка, ПараметрыМакета)
    ├── СформироватьPayloadЗаказа(ЗаказОбъект, ПараметрыМакета)
    │       → payload обогащён technology, label_type, shape, varnish, etc.
    └── СформироватьТекстДляЭмбеддинга(payload)
            → текст обогащён данными из макета
    │
    ▼
Показать результат в htmlЗаказ
```
