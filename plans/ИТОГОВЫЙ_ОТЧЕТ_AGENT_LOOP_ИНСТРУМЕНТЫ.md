## 📋 Обзор проекта

Реализована полнофункциональная архитектура **Agent Loop** для обработки заказов через LLM с поддержкой:
- ✅ Function calling (инструменты)
- ✅ Итеративное взаимодействие с LLM
- ✅ JSON-анализ с HTML-рендерингом
- ✅ Множественные типы анализа (технолог, экономист, комплексный, образовательный)

---

## 🏗️ Архитектура решения

### Уровень 1: Сбор данных (11 инструментов)

Каждый инструмент возвращает JSON с конкретными данными заказа:

| # | Инструмент | Функция | Возвращает |
|---|-----------|---------|-----------|
| 1 | `get_order_header` | `ВыполнитьИнструмент_get_order_header()` | Шапка заказа (номер, дата, клиент, статус) |
| 2 | `get_label_params` | `ВыполнитьИнструмент_get_label_params()` | Параметры этикетки (размеры, раппорт, тираж) |
| 3 | `get_production_flags` | `ВыполнитьИнструмент_get_production_flags()` | Флаги производства (цифра, ламинация, тиснение) |
| 4 | `get_colors` | `ВыполнитьИнструмент_get_colors()` | Табличная часть Цвета (краски, пантоны, грамматура) |
| 5 | `get_costs` | `ВыполнитьИнструмент_get_costs()` | Затраты из регистра (статьи, суммы, метраж) |
| 6 | `get_production_params` | `ВыполнитьИнструмент_get_production_params()` | Параметры производства (скорости, времена, стоимость) |
| 7 | `get_metrics` | `ВыполнитьИнструмент_get_metrics()` | Метрики (тираж, метраж, время, нормо-часы) |
| 8 | `get_economics` | `ВыполнитьИнструмент_get_economics()` | Экономика (сумма, валюта, себестоимость, рентабельность) |
| 9 | `get_quality` | `ВыполнитьИнструмент_get_quality()` | Качество (проверки, образцы, дизайнер) |
| 10 | `get_order_items` | `ВыполнитьИнструмент_get_order_items()` | Табличная часть Товары (номенклатура, количество, цена) |
| 11 | `get_sections` | `ВыполнитьИнструмент_get_sections()` | Табличная часть Секции (полные параметры технологии) |

### Уровень 2: Диспетчер инструментов

**Функция:** [`ВыполнитьИнструменты(ToolCalls, ДокументСсылка)`](1c/ERP/Обраб/AIАссистент/AIАссистент/Forms/Форма/Ext/Form/Module.bsl:1240)

- Получает массив `tool_calls` от LLM
- Выполняет каждый инструмент
- Возвращает результаты в формате `role="tool"` для истории

### Уровень 3: Agent Loop

**Функция:** [`AgentLoop(ДокументСсылка, КодЗадачи, ПараметрыПровайдера)`](1c/ERP/Обраб/AIАссистент/AIАссистент/Forms/Форма/Ext/Form/Module.bsl:1489)

**Алгоритм:**
```
1. Получить параметры задачи (персона, инструкция)
2. Собрать системный промпт
3. Инициализировать историю сообщений
4. Цикл (макс 10 итераций):
   a. Отправить запрос к LLM с инструментами
   b. Если tool_calls → выполнить инструменты → добавить в историю
   c. Если content → парсить JSON → рендерить HTML → вернуть
   d. Иначе → ошибка
5. Если превышены итерации → ошибка
```

### Уровень 4: Парсинг JSON

**Функция:** [`ИзвлечьJSONИзОтвета(СыройОтвет)`](1c/ERP/Обраб/AIАссистент/AIАссистент/Forms/Форма/Ext/Form/Module.bsl:1293)

**Четырёхуровневая защита:**
1. Прямой парсинг
2. Удаление markdown-блоков (` ```json `, ` ``` `)
3. Извлечение JSON между первой `{` и последней `}`
4. Логирование ошибок

### Уровень 5: HTML-рендеринг

**Функция:** [`JSON_Анализа_в_HTML(ДанныеJSON, КодЗадачи)`](1c/ERP/Обраб/AIАссистент/AIАссистент/Forms/Форма/Ext/Form/Module.bsl:1687)

**Поддерживаемые секции:**
- `verdict` → Вердикт (accept/reject/conditional)
- `risks` → Таблица рисков с уровнями
- `technology` → Технология печати и краски
- `timeline` → Таймлайн производства
- `economics` → Экономика и структура затрат
- `resources` → Материалы и персонал
- `quality_checkpoints` → Контроль качества

**Специальный режим для educational:**
- `order_overview` → Описание заказа простым языком
- `process_steps` → Пошаговое объяснение производства
- `technology_explained` → Объяснение технологии
- `glossary` → Словарь терминов
- `fun_facts` → Интересные факты

## 📊 Типы анализа

### 1. Технолог (`technologist`)
**Персона:** Опытный технолог типографии  
**Фокус:** Технологические риски, сложность, оптимизация  
**Выход:** JSON с `risks`, `technology`, `timeline`

### 2. Экономист (`economist`)
**Персона:** Финансовый аналитик  
**Фокус:** Рентабельность, структура затрат, ценообразование  
**Выход:** JSON с `economics`, `cost_breakdown`, `price_scenarios`

### 3. Комплексный (`full`)
**Персона:** Главный технолог + финансовый директор  
**Фокус:** Технология + экономика + ресурсы  
**Выход:** JSON со всеми секциями

### 4. Образовательный (`educational`)
**Персона:** Преподаватель полиграфии  
**Фокус:** Объяснение простым языком без жаргона  
**Выход:** JSON с `order_overview`, `process_steps`, `glossary`, `fun_facts`

## 📈 Пример работы

### Входные данные
```
Заказ: ОК008690008
Тип анализа: full (комплексный)
Провайдер: Омниум
Модель: anthropic/claude-haiku-4.5
```

### Процесс
```
1. AgentLoop запускается
2. LLM получает системный промпт + инструменты
3. LLM запрашивает: get_order_header, get_colors, get_economics
4. 1С выполняет инструменты → возвращает JSON
5. LLM анализирует данные → запрашивает: get_production_params, get_metrics
6. 1С выполняет инструменты → возвращает JSON
7. LLM формирует итоговый JSON-анализ
8. 1С парсит JSON → рендерит HTML
9. HTML отображается в форме
```

### Выходные данные
```json
{
  "order_analysis": {
```

## 🐛 Известные проблемы и решения

### Проблема 1: Ошибка парсинга JSON
**Симптом:** `Непредвиденный символ при чтении JSON`  
**Причина:** LLM возвращает ` ```json ... ``` `  
**Решение:** Использовать улучшенную функцию [`ИзвлечьJSONИзОтвета()`](plans/ИСПРАВЛЕНИЕ_ПАРСИНГА_JSON.md)

### Проблема 2: Переменная `Задачи` конфликтует с реквизитом
**Симптом:** Ошибка при вызове `ЗадачиАнализа()`  
**Причина:** Локальная переменная имеет то же имя, что и реквизит формы  
**Решение:** Переименовать на `ВсеЗадачи` (уже сделано в коде)
