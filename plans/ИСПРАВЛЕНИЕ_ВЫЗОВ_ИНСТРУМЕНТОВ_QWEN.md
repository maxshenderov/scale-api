# 🔧 Исправление вызова инструментов Qwen в Agent Loop

**Дата:** 07.05.2026
**Статус:** 🟡 Анализ завершён, ожидает реализации

---

## 🔍 Диагностика

После анализа кода [`Module.bsl`](../1c/ERP/Обраб/AIАссистент/AIАссистент/Forms/Форма/Ext/Form/Module.bsl) выявлены три причины, почему Qwen3.6+ (через RouterAI) не вызывает инструменты:

### Причина №1 (КРИТИЧЕСКАЯ): Несовместимость `response_format: json_object` и `tools`

**Где:** [`ОтправитьЗапросКLLM_сИнструментами()`](../1c/ERP/Обраб/AIАссистент/AIАссистент/Forms/Форма/Ext/Form/Module.bsl:1382-1385)

В запрос одновременно передаются:
```bsl
ЗапросОбъект.Вставить("tools", Инструменты);           // стр. 1379
ЗапросОбъект.Вставить("response_format", РеспонсФормат); // стр. 1385, type=json_object
```

По спецификации OpenAI-compatible API это взаимоисключающие параметры:
- `response_format: json_object` → «ты ДОЛЖЕН ответить JSON-объектом»
- `tools` → «ты МОЖЕШЬ вызвать функции»

Когда заданы оба — модель выбирает что-то одно. Qwen выбирает JSON (потому что это жёсткое ограничение) и игнорирует инструменты.

**Подтверждение из документации DeepSeek (тот же API-стандарт):**
> Чтобы включить вывод в формате JSON, задайте `response_format: {'type': 'json_object'}` и включите слово «json» в промпт.

Инструменты (function calling) в этой документации — отдельный режим, не совместимый с `json_object`.

### Причина №2: Отсутствие `tool_choice`

**Где:** [`ОтправитьЗапросКLLM_сИнструментами()`](../1c/ERP/Обраб/AIАссистент/AIАссистент/Forms/Форма/Ext/Form/Module.bsl:1371-1385)

Параметр `tool_choice` не задан. По умолчанию модель САМА решает, вызывать ли инструменты. Claude агрессивно использует инструменты по умолчанию, а Qwen — консервативен.

### Причина №3: Системный промпт форсирует JSON-ответ

**Где:** [`СобратьСистемныйПромпт()`](../1c/ERP/Обраб/AIАссистент/AIАссистент/Forms/Форма/Ext/Form/Module.bsl:1477)

```
ВАЖНО: Верни ТОЛЬКО валидный JSON, без ```json, без markdown, без пояснений до или после JSON.
```

В комбинации с `response_format: json_object` Qwen интерпретирует это буквально: «моя задача — сразу выдать JSON, инструменты не нужны».

## 📐 План исправлений

### Исправление 1: `response_format` только когда нет инструментов

**Файл:** [`Module.bsl`](../1c/ERP/Обраб/AIАссистент/AIАссистент/Forms/Форма/Ext/Form/Module.bsl)
**Функция:** [`ОтправитьЗапросКLLM_сИнструментами()`](../1c/ERP/Обраб/AIАссистент/AIАссистент/Forms/Форма/Ext/Form/Module.bsl:1382-1385)

```bsl
// БЫЛО (всегда):
РеспонсФормат = Новый Структура;
РеспонсФормат.Вставить("type", "json_object");
ЗапросОбъект.Вставить("response_format", РеспонсФормат);

// СТАЛО (только без инструментов):
Если Инструменты = Неопределено ИЛИ Инструменты.Количество() = 0 Тогда
    РеспонсФормат = Новый Структура;
    РеспонсФормат.Вставить("type", "json_object");
    ЗапросОбъект.Вставить("response_format", РеспонсФормат);
КонецЕсли;
```

### Исправление 2: Добавить `tool_choice`

**Там же, после блока инструментов:**

```bsl
Если Инструменты <> Неопределено И Инструменты.Количество() > 0 Тогда
    ЗапросОбъект.Вставить("tools", Инструменты);
    ЗапросОбъект.Вставить("tool_choice", "auto");  // ← добавить
КонецЕсли;
```

### Исправление 3: Переписать системный промпт

**Функция:** [`СобратьСистемныйПромпт()`](../1c/ERP/Обраб/AIАссистент/AIАссистент/Forms/Форма/Ext/Form/Module.bsl:1471-1481)

```bsl
// БЫЛО:
Инструкция =
    "|ИНСТРУКЦИЯ:
    |1. Ты можешь вызывать инструменты (function calling) чтобы получить данные заказа из 1С.
    ...
    |5. ВАЖНО: Верни ТОЛЬКО валидный JSON, без ```json, без markdown, ...

// СТАЛО:
Инструкция =
    "|ИНСТРУКЦИЯ:
    |1. ДЛЯ ПОЛУЧЕНИЯ ДАННЫХ ВЫЗЫВАЙ ИНСТРУМЕНТЫ (function calling). Без данных из 1С анализ невозможен.
    |2. Сначала запроси ВСЕ нужные данные через инструменты за ОДИН шаг (вызови несколько инструментов сразу).
    |3. Не запрашивай данные, которые тебе не нужны для анализа.
    |4. Когда данных достаточно — предоставь ИТОГОВЫЙ анализ в JSON-формате.
    |5. Верни ТОЛЬКО валидный JSON, без ```json, без markdown, без пояснений до или после JSON.
    |6. Все числа должны быть числами (не строками). Проценты — дробные (47.46, не ""47.46%"").
    |7. Если данных недостаточно — отметь это в анализе, но не запрашивай бесконечно.
    |
    |ЗАКАЗ ДЛЯ АНАЛИЗА: " + Строка(ДокументСсылка);
```

**Ключевое изменение:** пункт 1 теперь НАЧИНАЕТСЯ с требования вызвать инструменты, а не с возможности.

## 📊 Ожидаемый результат

**До:**
```
LLM получает: { tools: [...], response_format: json_object, prompt: "Верни JSON" }
→ Qwen: «Мне сказали вернуть JSON — возвращаю пустой анализ»
→ Результат: нет вызовов инструментов, пустой/неполный JSON
```

**После:**
```
LLM получает: { tools: [...], tool_choice: "auto", prompt: "Вызови инструменты для данных, потом JSON" }
→ Qwen: «Мне нужно вызвать инструменты чтобы получить данные»
→ Шаг 1: tool_calls [get_order_header, get_economics, get_costs, ...]
→ Шаг 2: получает данные, возвращает полный JSON-анализ
→ Результат: полноценный анализ с реальными данными
```

---

## 📝 Примечания

- `response_format: json_object` по-прежнему будет использоваться для финального ответа (без инструментов) — когда модель уже получила все данные и формирует JSON
- `tool_choice: "auto"` — безопасный дефолт. При желании можно сделать `"required"` для первой итерации Qwen, но это рискованно для других моделей
