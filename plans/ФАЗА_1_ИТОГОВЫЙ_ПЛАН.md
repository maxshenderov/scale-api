# ФАЗА 1: Итоговый план (два процесса: индексирование + поиск)

## Архитектурное разделение

Пользователь уточнил, что нужны **два отдельных процесса**:

### СТАДИЯ 1: Индексирование (background, один раз или периодически)
```
1С (100K+ заказов) + Docling (Phase 1: текст из макетов)
                    ↓
                Qdrant (orders_phase1)
```
- Берем данные из 1С (ЗаказКлиента с макетами)
- Извлекаем текст через Docling (Phase 1)
- Индексируем в Qdrant с BM25 sparse vectors
- Также сохраняем точные 1С параметры как payload

### СТАДИЯ 2: Поиск параметров новой макеты (real-time, интерактивно)
```
Новый PDF макет (пользователь загружает)
    ↓
Phase 0 (Vision LLM) → визуальные параметры
    ↓
Phase 1 (Docling)   → текст макеты
    ↓
RAG: поиск TOP-3 заказов в Qdrant по Phase1 текст
    ↓
LLM (prompt) → объединяет новые Phase0+Phase1 + похожие заказы из RAG
    ↓
JSON параметров → программное создание в 1С
```

---

## Ключевые отличия от предыдущего плана

1. **Без Phase 0 в индексировании** - только 1С данные + Docling текст
2. **Phase 0 только для новых макетов** - для визуальной верификации
3. **Две разные задачи Qdrant**:
   - Индексирование: 1С параметры → payload, Docling текст → BM25 для поиска
   - Поиск: новый PDF → Phase1 текст → поиск в Qdrant → получить похожие заказы с их 1С параметрами

- Ответ: 
  ```json

    "images": ["base64 изображений из PDF"],
    "tables": [{"text": "...", "type": "table"}]
  ```

### ШАГ 3: Создать Batch Indexer сервис в Docker

**Путь**: `services/batch_indexer/`
**Задача**: Фоновая переиндексация 100K+ заказов
- Читает заказы из 1С (через HTTP API или прямое подключение)
- Для каждого: скачивает макет → Docling → текст
- Создает BM25 sparse vectors
- Уpsert в Qdrant collection `orders_phase1`

### ШАГ 4: Добавить Hybrid Search функцию

**Где**: Common module в 1С или Python сервис
**Что делает**:
1. Берет текст из Phase 1 (новый PDF)
2. Разбивает на токены для BM25
3. Создает dense vector (эмбединг)
4. Ищет в Qdrant:
   - Sparse (BM25): текст токены
   - Dense: семантический поиск
5. Мержит результаты → TOP-3

### ШАГ 5: Реализовать RAG + LLM pipeline

**Что**: Функция, которая объединяет все в один prompt для LLM
**Input**:
- Новый PDF Phase 0 параметры (от Vision)
- Новый PDF Phase 1 текст (от Docling)
- TOP-3 похожих заказов (из Qdrant)

**Output**: JSON с параметрами для создания заказа в 1С

**Prompt структура**:
```
Ты — система определения параметров заказа этикеток.

НОВЫЙ ЗАКАЗ (из загруженного макета):
- Фаза 0 (Vision): {размеры, ориентация, тип печати}
- Фаза 1 (Docling): {текст этикетки}

ПОХОЖИЕ ЗАКАЗЫ ИЗ ИСТОРИИ (TOP-3):
1. Заказ #123: {1С параметры + текст}
2. Заказ #456: {1С параметры + текст}
3. Заказ #789: {1С параметры + текст}

На основе сравнения, определи:
- Рабочий центр (печать, флексо, глубокая, цифра)
- Технологию
- Материал
- Типы цветов
- Прочие параметры

Ответ в JSON: {...}
```

## Данные 1С для RAG-контекста

Какие поля из ЗаказКлиента попадают в Qdrant как payload для похожих заказов:

```
Лико_ТипЗаказа          (enum: СамоклеящаясяЭтикетка, Термоусадка, ...)
Лико_ВидЗаказа          (enum)
ТипографскийАгрегат     (boolean)
НомерЗаказаЭтикеток     (string - внешний номер)
ШиринаЭтикетки          (decimal)
ДлинаЭтикетки           (decimal)
ЭтикетокНаЛисте         (integer)
КоличествоЭтикетокВСтопеТУ (integer)

Товары (табличная часть):
  - КоличествоЭтикетокВРолике
  - ДопЭтикетокВРолике
  
Цвета (табличная часть):
  - ЭтикетокВПодаче
  - формулы пантонов
  
ВидыРабот (табличная часть):
  - [Печать, Флексо, Глубокая, ЦифровойМодуль]
  
Секции (табличная часть):
  - параметры технологии
```
