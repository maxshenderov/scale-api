# ЗагрузкаСклада

> Визуализация поперечного сечения стеллажа склада + чат-интерфейс AI-ассистента. Внешний отчёт (ExternalReport), версия 1.0.0.1.

## Формы

- **Форма** — основная (4 страницы)
- **ФормаОбъекта** — карточка паллета/ячейки (открывается по двойному клику из визуализации)

---

## Страницы основной формы

### 1. Схема (визуализация)

Элементы выбора: `Склад`, `Паллет`, `ТипоразмерПаллета` (read-only), `УровеньДоступа`, `ФилтрПоПаллету`.
HTML-поле `html` — интерактивная визуализация стеллажа с зумом, картой стеллажей, подсветкой.

### 2. АдресаХранения

Таблица `АдресаХранения` (28 колонок) — результат подбора ячеек через `ПодобратьЯчейкуПоПаллету()`.
Заголовок привязан к `КоличествоВозможныхАдресов`.

### 3. Асистент AI (чат)

Чат-интерфейс с LLM:

- **HTML-поле `ОтветLLMHTML`** — история чата с пузырями
- **Поле ввода `ВопросКLLM`** (многострочное, h=2)
- **Кнопка `ОтпрвитьВLLM`** (SendMessage, картинка)
- **Кнопка `Очистить`** (NewConversation) — сброс истории
- **Кнопка `ВыбратьФайлы`** (Attach) — до 5 файлов (pdf/jpg/png/txt/docx/xlsx/csv)
- **Выпадающий список `Задача`** — выбор роли AI (заполняется из `ЗадачиДляLLM()`)

#### Боковая панель (вложенные страницы справа от чата)

| Страница | Поле | Назначение |
|----------|------|-----------|
| Требования | `Требования` (многострочное) | Ввод требований для ТЗ |
| Черновик (тех. задание) | `ЧерновикТЗ` (многострочное) | Сформированное ТЗ |
| Техническое задание | `ТехническоеЗадание` (многострочное) | Финальное утверждённое ТЗ |

> ⚠️ Поля `Требования`, `ЧерновикТЗ`, `ТехническоеЗадание` существуют как атрибуты формы, но НЕ подключены к LLM-потоку. Кнопки «Сформировать ТЗ» и «Экспертиза» отсутствуют.

### 4. Настройки

| Поле | Тип | Назначение |
|------|-----|-----------|
| `ИспользоватьАсистентаAI` | Булево | Вкл/выкл |
| `Провайдер` | Выпадающий список | RouterAI / Омниум |
| `Модель` | Выпадающий список | зависит от провайдера |
| `ОписаниеМодели` | Многострочное | Информация о модели |
| `ФорматОтветаLLM` | Выпадающий список | text / html / markdown / json |

## Модуль формы: ключевые функции (3279 строк)

### Чат / LLM — полный цикл запроса

```
Кнопка ОтпрвитьВLLM
  → ОтпрвитьВLLM(Команда) [&НаКлиенте]
    → ДобавитьПользовательскийПузырьНаСервере(Текст)
    → ДобавитьИндикаторОжиданияНаСервере()
    → ПодключитьОбработчикОжидания("ВыполнитьЗапросКLLМ", 0.1, Истина)

  → ВыполнитьЗапросКLLМ() [&НаКлиенте, Экспорт]
    → ЗадачиДляLLM()[Задача].СистемныйПромпт
    → ОтправитьЗапросLLMНаСервере(СистемныйПромпт, ВопросКLLM, ИсторияJSON, Файлы, Формат)

  → ОтправитьЗапросLLMНаСервере() [&НаСервере]
    → НоваяИсторияДиалога(СистемныйПромпт, ФорматОтвета)
    → СпроситьLLM(История, Вопрос, Настройки, , Формат, КонтекстФайлов)
    → Возврат {Ответ, История, ТокеныВход, ТокеныВыход, Модель}
```

### `НоваяИсторияДиалога(СистемныйПромпт, ФорматОтвета, ПостоянныйКонтекст)` — стр. 2279

Формирует начальный массив сообщений:
```
system: СистемныйПромпт + ИнструкцияФормата(ФорматОтвета)
        + "=== СПРАВОЧНЫЕ ДАННЫЕ ===" + ПостоянныйКонтекст  (если заполнен)
```

> 🔑 **`ПостоянныйКонтекст`** — ключевой параметр для WMS Expert. Именно сюда будут подставляться MD-знания из макетов.

### `СпроситьLLM(ИсторияДиалога, Вопрос, НастройкиLLM, Инструменты, ФорматОтвета, КонтекстВопроса)` — стр. 2339

Основной оркестратор: добавляет вопрос → формирует тело → HTTP → нормализует ответ → поддерживает function calling (tool_calls) с циклом до `МаксИтерацийИнструментов` (по умолчанию 5).

### `ЗадачиДляLLM()` — стр. 3255

Определяет доступные задачи (роли AI). Сейчас одна:
```bsl
ЗадачиLLM.Вставить("АналитикСклада");
// Описание: "Анализ складского учета"
// СистемныйПромпт: "Вы — полезный ассистент по складскому учёту. Отвечай кратко и по делу."
```

## Макеты (Templates)

В обработке созданы 7 текстовых макетов. 4 — MD-знания WMS, подключены к LLM (см. ниже); 3 — `_BSL`/`BSL`-суффиксом — сырые дампы исходного кода, **не используются** в LLM-потоке (не встречаются в `ПолучитьSystemPromptWMS`), только для человека как справка. Дампы устарели относительно текущего `ManagerModule.bsl` (не отражают `Узкопроходный`/лимиты стеллажа, монтажный зазор, `ВиртуальноеСостояние`, `ПолныйОтвет`) — не читай их как источник правды.

| Макет | Используется в LLM | Назначение |
|-------|:---:|-----------|
| `WMS_ПодобратьЯчейку` | ✅ | Алгоритм ПодобратьЯчейку (5 CTE, WHERE-правила + монтажный зазор, ORDER BY: 13 приоритетов с ПотенциалИтого и ПотенциалПоВесу) |
| `WMS_ОшибкиРазмещения` | ✅ | 21 проверка ОшибкиРазмещенияВАдрес, включая 13a (монтажный зазор), ПолныйОтвет, ВиртуальноеСостояние |
| `WMS_ВремяДоступа` | ✅ | Алгоритм ЗаполнитьВремяДоступаКСекциям |
| `WMS_Топология_ЛК_Высотный` | ✅ (для склада «ЛК Высотный Новый») | Топология склада (10 стеллажей, 20 типоразмеров) |
| `WMS_ПодобратьЯчейку_BSL` | ❌ устарел | Старый дамп исходного кода до рефакторинга Узкопроходный/лимиты стеллажа |
| `WMS_ОшибкиРазмещения_BSL` | ❌ устарел | Старый дамп исходного кода, без 13a/ПолныйОтвет/ВиртуальноеСостояние |
| `WMS_ВремяДоступаBSL` | ❌ устарел | Старый дамп исходного кода |

**Подключение к LLM:** `ПолучитьSystemPromptWMS(Склад)` (стр. 6593+) собирает `ПолучитьТекстМакета("WMS_ПодобратьЯчейку") + WMS_ОшибкиРазмещения + WMS_ВремяДоступа` (+ топология по складу) и передаёт как `ПостоянныйКонтекст` в `НоваяИсторияДиалога` → задача `WMS_Эксперт`.

## LLM-инструменты (Function Calling)

В модуле формы реализованы два инструмента для LLM:

### `find_cell_for_pallet` — подбор ячейки

**Tool definition:** `ИнструментПодбораЯчейки()`

**Adapter:** `Адаптер_ПодобратьЯчейкуПоПаллету(Аргументы)`

**Бизнес-логика:** `ПодобратьЯчейкуПоПаллетуБизнес(КодПаллета)` → `ПодобратьЯчейкуПоПаллетуДляLLM(Паллет)`

**Параметры:**
| Параметр | Тип | Обязательный | Описание |
|----------|-----|-------------|----------|
| `pallet` | string | Да | Код паллета |
| `rack` | array of string | Нет | Код/наименование стеллажа (можно несколько) |
| `floor` | integer | Нет | Номер этажа |
| `section` | array of string | Нет | Код секции, формат: `Р<ряд>-М(<м1>-<м2>-<м3>)-Э<этаж>` |
| `cell` | array of string | Нет | Код ячейки/адреса, формат: `Р<ряд>М<место>Э<этаж>` |
| `limit` | integer | Нет | Макс. кандидатов (по умолчанию 10, 0 = без ограничений) |

**Инструкция LLM:** «ВЫЗЫВАЙ ОДИН РАЗ — передавай cell/section сразу вместе с pallet, не делай отдельных вызовов.»

**Оптимизация токенов (16.06.2026):**
- Колонки сокращены с 28 до 14 (только значимые для LLM)
- Пост-фильтрация в адаптере: rack, floor, section, cell — все принимают массивы
- Хелперы: `СовпадаетПоСтроке()`, `НормализоватьВМассив()`
- Без фильтров — лимит 10 кандидатов по умолчанию
- С фильтрами — лимит не применяется (фильтр уже сужает)

**Ответ:** JSON с полями `pallet`, `totalCandidates`, `filteredCandidates`, `filters`(если заданы), `candidates[]`. Каждый кандидат: `Приоритет_Номер, СекцияКод, Адрес, Стеллаж, Ряд, Место, Этаж, ШиринаСекции, ВысотаСекции, ОстатокВысота, ОстатокШирина, ПотенциалСекции, УровеньДоступа, ВремяДоступа`.

### `validate_pallet_placement` — валидация размещения

**Tool definition:** `ИнструментОшибкиРазмещения()`

**Adapter:** `Адаптер_ОшибкиРазмещенияПаллета(Аргументы)`

**Параметры:** `cell` (string), `pallet` (string) — оба обязательные.

**Ответ:** `{valid, cell, pallet, errors[], cellFound, palletFound, message}`.
