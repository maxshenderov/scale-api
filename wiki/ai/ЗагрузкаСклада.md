# ЗагрузкаСклада

> Визуализация поперечного сечения стеллажа склада + чат-интерфейс AI-ассистента. Внешний отчёт (ExternalReport), версия 1.0.0.1.

## Формы

- **Форма** — основная (4 страницы)
- **ФормаОбъекта** — карточка паллета/ячейки (открывается по двойному клику из визуализации)

---

## Страницы основной формы

### 1. Схема (визуализация)

Элементы выбора: `Склад`, `Паллет`, `ТипоразмерПаллета` (read-only), `УровеньДоступа`, `ФилтрПоПаллету`.
HTML-поле `html` — интерактивная визуализация стеллажа с зумом, картой стеллажей, подсветкой.

### 2. АдресаХранения

Таблица `АдресаХранения` (28 колонок) — результат подбора ячеек через `ПодобратьЯчейкуПоПаллету()`.
Заголовок привязан к `КоличествоВозможныхАдресов`.

### 3. Асистент AI (чат)

Чат-интерфейс с LLM:

- **HTML-поле `ОтветLLMHTML`** — история чата с пузырями
- **Поле ввода `ВопросКLLM`** (многострочное, h=2)
- **Кнопка `ОтпрвитьВLLM`** (SendMessage, картинка)
- **Кнопка `Очистить`** (NewConversation) — сброс истории
- **Кнопка `ВыбратьФайлы`** (Attach) — до 5 файлов (pdf/jpg/png/txt/docx/xlsx/csv)
- **Выпадающий список `Задача`** — выбор роли AI (заполняется из `ЗадачиДляLLM()`)

#### Боковая панель (вложенные страницы справа от чата)

| Страница | Поле | Назначение |
|----------|------|-----------|
| Требования | `Требования` (многострочное) | Ввод требований для ТЗ |
| Черновик (тех. задание) | `ЧерновикТЗ` (многострочное) | Сформированное ТЗ |
| Техническое задание | `ТехническоеЗадание` (многострочное) | Финальное утверждённое ТЗ |

> ⚠️ Поля `Требования`, `ЧерновикТЗ`, `ТехническоеЗадание` существуют как атрибуты формы, но НЕ подключены к LLM-потоку. Кнопки «Сформировать ТЗ» и «Экспертиза» отсутствуют.

### 4. Настройки

| Поле | Тип | Назначение |
|------|-----|-----------|
| `ИспользоватьАсистентаAI` | Булево | Вкл/выкл |
| `Провайдер` | Выпадающий список | RouterAI / Омниум |
| `Модель` | Выпадающий список | зависит от провайдера |
| `ОписаниеМодели` | Многострочное | Информация о модели |
| `ФорматОтветаLLM` | Выпадающий список | text / html / markdown / json |

## Модуль формы: ключевые функции (3279 строк)

### Чат / LLM — полный цикл запроса

```
Кнопка ОтпрвитьВLLM
  → ОтпрвитьВLLM(Команда) [&НаКлиенте]
    → ДобавитьПользовательскийПузырьНаСервере(Текст)
    → ДобавитьИндикаторОжиданияНаСервере()
    → ПодключитьОбработчикОжидания("ВыполнитьЗапросКLLМ", 0.1, Истина)

  → ВыполнитьЗапросКLLМ() [&НаКлиенте, Экспорт]
    → ЗадачиДляLLM()[Задача].СистемныйПромпт
    → ОтправитьЗапросLLMНаСервере(СистемныйПромпт, ВопросКLLM, ИсторияJSON, Файлы, Формат)

  → ОтправитьЗапросLLMНаСервере() [&НаСервере]
    → НоваяИсторияДиалога(СистемныйПромпт, ФорматОтвета)
    → СпроситьLLM(История, Вопрос, Настройки, , Формат, КонтекстФайлов)
    → Возврат {Ответ, История, ТокеныВход, ТокеныВыход, Модель}
```

### `НоваяИсторияДиалога(СистемныйПромпт, ФорматОтвета, ПостоянныйКонтекст)` — стр. 2279

Формирует начальный массив сообщений:
```
system: СистемныйПромпт + ИнструкцияФормата(ФорматОтвета)
        + "=== СПРАВОЧНЫЕ ДАННЫЕ ===" + ПостоянныйКонтекст  (если заполнен)
```

> 🔑 **`ПостоянныйКонтекст`** — ключевой параметр для WMS Expert. Именно сюда будут подставляться MD-знания из макетов.

### `СпроситьLLM(ИсторияДиалога, Вопрос, НастройкиLLM, Инструменты, ФорматОтвета, КонтекстВопроса)` — стр. 2339

Основной оркестратор: добавляет вопрос → формирует тело → HTTP → нормализует ответ → поддерживает function calling (tool_calls) с циклом до `МаксИтерацийИнструментов` (по умолчанию 5).

### `ЗадачиДляLLM()` — стр. 3255

Определяет доступные задачи (роли AI). Сейчас одна:
```bsl
ЗадачиLLM.Вставить("АналитикСклада");
// Описание: "Анализ складского учета"
// СистемныйПромпт: "Вы — полезный ассистент по складскому учёту. Отвечай кратко и по делу."
```

## Макеты (Templates)

В обработке созданы 4 текстовых макета с MD-знаниями WMS:

| Макет | Назначение |
|-------|-----------|
| `WMS_ПодобратьЯчейку` | Алгоритм ПодобратьЯчейку (5 CTE, 14 правил, ORDER BY) |
| `WMS_ОшибкиРазмещения` | 14 проверок ОшибкиРазмещенияВАдрес |
| `WMS_ВремяДоступа` | Алгоритм ЗаполнитьВремяДоступаКСекциям |
| `WMS_Топология_ЛК_Высотный` | Топология склада ЛК Высотный (10 стеллажей, 20 типоразмеров) |

> ⚠️ Макеты созданы, но **не подключены** к LLM-потоку. Требуется BSL-интеграция.
