# ТестLLM

> Тестовая обработка для отладки и валидации LLM-интеграции: отправка запросов к AI-провайдерам, анализ заказов через LLM с тремя типами промптов.

## Что делает

Простая форма с выбором заказа, модели и кнопкой «Анализ». Используется для:

1. **Отладки HTTP-запросов к LLM** — две реализации (`ОтправитьЗапросКLLM` на сервере и `ОтправитьЗапросКLLM2` на клиенте) с разными способами формирования JSON.
2. **Тестирования смены моделей** — жёстко закодированный список из ~20 моделей (OpenAI, Anthropic, Google, MoonshotAI, Perplexity).
3. **Анализа заказа через LLM** — отправка JSON-данных заказа в LLM с тремя типами промптов (Технолог / Экономист / Полный).
4. **Валидации парсинга ответа** — преобразование Markdown/HTML/простого текста из ответа LLM.

## Ключевые процедуры

### LLM-клиент (две реализации)
- `ОтправитьЗапросКLLM(ТекстЗапроса, НастройкиЗапроса)` — **серверная**: использует `ЗаписьJSON` для формирования тела, запрос к `aichat-okil-sato.kartochka.tech:443`, возвращает `{Успех, Ответ, ПолныйОтвет, ОписаниеОшибки}`.
- `ОтправитьЗапросКLLM2(ТекстЗапроса, НастройкиЗапроса)` — **клиентская**: формирует JSON вручную через строковую интерполяцию, запрос к `https://aichat-okil-sato.kartochka.tech/api/v1/chat/completions`.
- `ЗаменитьСпецСимволыJSON(Строка)` — экранирует `\`, `"`, `\r`, `\n`, `\t` для ручного JSON.

### Управление моделями
- `МоделиLLM()` — возвращает Соответствие со списком из ~20 моделей (gpt-4o, claude-opus-4.5, gemini-3-pro-preview, kimi-k2 и др.).
- `СоздатьСписокЗначенийИзКлючейСтруктуры(Структура)` — конвертирует Соответствие в СписокЗначений для формы.
- `ЗаполнитьСписокВыбораМодели(СписокЗначенийИсточник)` — заполняет выпадающий список в форме.

### Анализ заказа
- `АнализЗаказа(Команда)` — клиентский обработчик: проверяет выбор заказа -> вызывает `ОтправитьЗапросАнализаЗаказа()` -> показывает HTML-результат.
- `ОтправитьЗапросАнализаЗаказа(ДокументСсылка, ТипАнализа)` — серверная: собирает JSON заказа -> формирует промпт -> запрос к LLM -> HTML.
- `ПолучитьТипАнализаИзПараметров()` — читает `ПараметрыСеанса.Лико_ТипАнализаЗаказа`.
- `ПолучитьСистемныйПромпт(ТипАнализа, ДанныеЗаказаJSON)` — возвращает один из трёх промптов:
  - **Технолог** — оценка сложности, технологии печати, риски, время.
  - **Экономист** — рентабельность, структура затрат, ценообразование.
  - **Полный** — комплексный анализ (технология + экономика + рекомендации).
- `ОбработатьРезультатLLM(РезультатLLM, ТипАнализа)` — определяет формат ответа (HTML / Markdown / plain text) и делегирует.
- `ПреобразоватьMarkdownВHTML(ТекстMarkdown)` — упрощённый конвертер (`##` -> `<h2>`, `**` -> `<strong>`, `- ` -> `<li>`).
- `ОборнутьВHTML(ПростойТекст, ТипАнализа)` — оборачивает plain text в HTML с базовыми стилями.
- `ПолучитьОшибкуHTML(СообщениеОбОшибке)` — HTML-блок ошибки с красным фоном.

### Извлечение данных заказа
- `ПолучитьДанныеЗаказаДляАИ(ДокументСсылка)` — собирает 9 секций данных в JSON.
- `ОчиститьСтруктуруДляJSON(Значение)` — рекурсивная очистка от ссылок/дат/УИД.
- 8 функций `ПолучитьДанные*()` — шапка, этикетка, производство, цвета, затраты, параметры производства, метрики, экономика, качество.

### Отличия от AIАссистент
- Нет Agent Loop (tool calling).
- Нет Vision-анализа и Qdrant-индексации.
- Нет Phase1/PyMuPDF тестов.
- Список моделей жёстко закодирован (не запрашивается с сервера).
- Две реализации HTTP-клиента (для сравнения/отладки).
