# AIАссистент

> Универсальная обработка-комбайн для AI/LLM интеграции: анализ заказов через LLM, Vision-анализ макетов, Qdrant-индексация, тестирование PyMuPDF и Phase1.

## Что делает

Обработка объединяет все AI-функции в одном интерфейсе:

1. **LLM-чат** — отправка запросов к OpenAI-совместимому API (`aichat-okil-sato.kartochka.tech`) с поддержкой выбора модели/провайдера.
2. **Agent Loop с инструментами** — LLM получает JSON-описание инструментов (12 шт.), вызывает `ВыполнитьИнструменты()` для получения данных заказа, итеративно до финального ответа.
3. **Анализ заказа** (`АнализЗаказа`) — комплексный анализ `ЗаказКлиента`: технологический, экономический, полный. Данные собираются из документа, регистров `Лико_Затраты`, `Лико_ПараметрыПроизводстваЗаказа` и отображаются в HTML.
4. **Vision-анализ макетов** — отправка изображения макета в Vision LLM (`google/gemini-3-pro-image-preview`) с промптом для извлечения параметров этикетки.
5. **Qdrant-индексация** — Vision-анализ макета + данные документа -> вызов `Лико_QdrantИндексация.СформироватьДанныеДляИндексации()`.
6. **Phase1 тестирование** — загрузка файлов макетов из заказа, вызов Python-сервиса `docling`, отображение извлечённого текста.
7. **PyMuPDF тест** — аналогично Phase1, но через сервис `parser` (PyMuPDF).

## Ключевые процедуры

### LLM-клиент
- `ОтправитьЗапросКLLM(ТекстЗапроса, НастройкиЗапроса)` — базовый HTTP POST к LLM API, формирует JSON с `ЗаписьJSON`, парсит ответ.
- `ОтправитьЗапросКLLM_сИнструментами(ИсторияСообщений, Инструменты, ПараметрыПровайдера)` — отправка с tool_calls, возвращает структуру `{content, tool_calls}`.
- `Провайдеры()` — возвращает Соответствие провайдеров (aichat, routerai) с URL, ключами, путями API.
- `СписокМоделейСервер(Провайдер)` — запрашивает `/api/v1/models` и возвращает массив моделей.
- `МоделиLLM(Провайдер)` — строит Соответствие `ИмяМодели -> Структура(МодельID, Описание)`.

### Agent Loop
- `AgentLoop(ДокументСсылка, КодЗадачи, ПараметрыПровайдера)` — итеративный цикл: системный промпт -> LLM -> выполняет tool_calls через `ВыполнитьИнструменты()` -> повтор до финального ответа.
- `СобратьСистемныйПромпт(ПараметрыЗадачи, ДокументСсылка)` — формирует промпт с JSON-описанием 12 инструментов.
- `ОписаниеИнструментов()` — возвращает JSON-массив из 12 функций: `get_order_header`, `get_label_params`, `get_production_flags`, `get_colors`, `get_costs`, `get_production_params`, `get_metrics`, `get_economics`, `get_quality`, `get_order_items`, `get_sections`.
- `ВыполнитьИнструменты(ToolCalls, ДокументСсылка)` — диспетчеризует вызовы к 12 функциям `ВыполнитьИнструмент_*()`.
- `ИзвлечьJSONИзОтвета(СыройОтвет)` — вырезает JSON из markdown-блоков и чинит битые строки.

### Анализ заказа
- `АнализЗаказа(Команда)` — клиентская процедура: вызывает `ОтправитьЗапросАнализаЗаказа()` и показывает HTML.
- `ОтправитьЗапросАнализаЗаказа(ДокументСсылка, ТипАнализа)` — серверная: собирает JSON заказа -> формирует промпт -> LLM -> HTML.
- `ПолучитьДанныеЗаказаДляАИ(ДокументСсылка)` — собирает полный JSON заказа из 9 секций.
- `ОчиститьСтруктуруДляJSON(Значение)` — рекурсивно очищает от несериализуемых типов (ссылки -> строка, даты -> ISO).
- Секции данных: `ПолучитьДанныеШапки()`, `ПолучитьДанныеЭтикетки()`, `ПолучитьДанныеПроизводства()`, `ПолучитьДанныеЦветов()`, `ПолучитьДанныеЗатрат()`, `ПолучитьДанныеПараметровПроизводства()`, `ПолучитьДанныеМетрик()`, `ПолучитьДанныеЭкономики()`, `ПолучитьДанныеКачества()`, `ПолучитьДанныеТоваров()`, `ПолучитьДанныеСекций()`.

### JSON -> HTML рендеринг
- `JSON_Анализа_в_HTML(ДанныеJSON, КодЗадачи)` — main dispatcher: выбирает подходящий рендерер.
- `JSON_Обучения_в_HTML(ДанныеJSON)` — парсит ответ LLM с технолог/экономист/менеджер секциями в HTML.
- `РендеритьУниверсальныйJSON(ДанныеJSON)` — fallback-рендерер для произвольного JSON.
- Секционные рендереры: `СекцияВердикта()`, `СекцияРисков()`, `СекцияТехнологии()`, `СекцияТаймлайна()`, `СекцияЭкономики()`, `СекцияРесурсов()`, `СекцияКачества()`, `СекцияСхемыМашины()`.
- `СтилиHTML()` — общие CSS-стили для всех HTML-отчётов.

### Qdrant и Vision
- `ИндексироватьЗаказQdrant(Команда)` — полный пайплайн: Vision-анализ макета -> `ИндексироватьЗаказСервер()` -> HTML-отчёт.
- `ИндексироватьЗаказСервер(ЗаказСсылка, ПараметрыМакетаJSON)` — вызывает `Лико_QdrantИндексация.СформироватьДанныеДляИндексации()`.

### Phase1 и PyMuPDF
- `ЗагрузитьФайлыФаза1()` — выбирает файлы макетов из заказа или папки.
- `АнализироватьМакетФаза1Сервер(ПутьКФайлу)` — отправляет файл в Python-сервис docling (8001).
- `Фаза1ИзвлечьТекстМакеты(ДвоичныеДанные, РасширениеФайла)` — HTTP POST на docling-сервис.
- `ВызватьРАГЛЛМСервис(Phase0Параметры, Phase1Данные)` — вызов rag_llm сервиса (8003) для получения параметров этикетки.
- `ПроверитьPhase1(Команда)` / `ПроверитьPhase1НаСервере()` — тестирование Phase1 пайплайна.
- `ПроверитьPyMuPDF(Команда)` / `ПроверитьPyMuPDFНаСервере()` — тестирование PyMuPDF пайплайна.
