# Лико_ПодобратьЯчейку

> BSL-функция в менеджере [[Лико_СкладскиеСекции]] — подбирает оптимальную секцию и адрес для размещения паллета на складе.

## Сигнатура

```bsl
Функция ПодобратьЯчейку(Склад, Высота, Ширина, Глубина, Вес, ОбратныйПорядокВремени)
```

**Возвращает:** строку результата запроса с полями `Ссылка` (секция) и `Адрес` (конкретный адрес размещения). Пустая ссылка если ничего не найдено.

---

## Модель предметной области

Склад секционного хранения паллетов. Каждая **секция** (`Справочник.Лико_СкладскиеСекции`) содержит до **3 адресов** внутри одного физического слота:

```
┌─────────────────────────────────┐
│  Адрес1  │  Адрес2  │  Адрес3  │
│   W/3    │   W/3    │   W/3    │
└─────────────────────────────────┘
           W = Типоразмер.Ширина
```

На складе 20+ типоразмеров секций. `УровеньДоступа` — горизонтальная зона (удалённость от точки комплектации), **не** этаж.

**Категории паллетов по ширине:**

| Категория | Условие | Занимает адресов |
|-----------|---------|-----------------|
| Узкий | ≤ W/3 | 1 |
| Средний | > W/3, ≤ W/2 | 2 (блокирует Адрес2) |
| Широкий | > W/2 | 3 (все) |

---

## Структура запроса — 5 этапов

### ВТСекции
Фильтрация кандидатов: глубина/высота/вес/ширина стеллажа/запрет размещения/склад.
Вычисляется `УровеньДоступа`:
```sql
КОГДА (Место - 1) / 3 + 1 <= КоличествоСекций / 2 ТОГДА 1  -- ближняя зона
ИНАЧЕ 2                                                       -- дальняя зона
```

### ВтОстатки
Текущие паллеты в адресах из `РегистрНакопления.Лико_ПаллетыВСекциях.Остатки`.
INNER JOIN с `РегистрСведений.Лико_ПараметрыПаллет.СрезПоследних` — получаем типоразмер каждого паллета.

### ВтОстаткиИтог
Агрегация: один паллет может иметь движения по нескольким адресам → `МАКСИМУМ(Адрес)`.

### ВтСекцииСОстатками
LEFT JOIN секций × 3 адреса:
- `Паллет1` / `Типоразмер1` ← по Адрес1
- `Паллет2` / `Типоразмер2` ← по Адрес2
- `Паллет3` / `Типоразмер3` ← по Адрес3

### Финальный ПЕРВЫЕ 1
WHERE + вычисляемые поля + ORDER BY.

---

## Вычисляемые поля (финальный запрос)

### ПотенциалСекции
Максимум паллетов в секции **после** размещения текущего:

| Значение | Условие | Смысл |
|----------|---------|-------|
| **3** | Оба края пусты ИЛИ заняты узкими (≤ W/3) | Полная гибкость |
| **2** | Один край занят широким (> W/3), другой свободен | Средний паллет заблокировал Адрес2 |
| **0** | Оба края заняты | Потенциал исчерпан |

```sql
ВЫБОР
    КОГДА Паллет1 <> Пусто И Типоразмер1.Ширина > W/3 И Паллет3 = Пусто ТОГДА 2
    КОГДА Паллет3 <> Пусто И Типоразмер3.Ширина > W/3 И Паллет1 = Пусто ТОГДА 2
    КОГДА (Паллет1 = Пусто ИЛИ Типоразмер1.Ширина <= W/3)
          И (Паллет3 = Пусто ИЛИ Типоразмер3.Ширина <= W/3) ТОГДА 3
    ИНАЧЕ 0
КОНЕЦ КАК ПотенциалСекции
```

### Адрес (целевой адрес размещения)

| Ширина паллета | Выбор адреса |
|----------------|-------------|
| > W/2 | Адрес2 (центр) |
| > W/3 | Адрес1 если пуст → иначе Адрес3 |
| ≤ W/3 | Адрес1 → Адрес2 (если оба края узкие) → Адрес3 → **ПустаяСсылка** (нет доступного адреса) |

### ОстатокВысота / ОстатокШирина / ОстатокВес
Остаток вместимости. ОстатокВысота и ОстатокШирина — в ORDER BY. ОстатокШирина также в WHERE (`>= W/3`).

---

## WHERE — фильтры физической возможности

1. Хотя бы 1 свободный адрес (Паллет1/2/3 = пустая ссылка)
2. `ОстатокШирина >= Типоразмер.Ширина / 3` (минимум одна ячейка)
3. `ОстатокВес >= ВесПаллета` ИЛИ секция безлимитная
4. Если Паллет2 занят → его ширина < W/3
5. Широкий (> W/2): все 3 адреса пусты
6. Средний (> W/3): Адрес2 пуст + (Адрес1 ИЛИ Адрес3 пуст)
7. Вычисленный адрес ≠ ПустаяСсылка (дубликат SELECT-логики — исключает секции где fallback вернул бы ПустуюСсылку)

---

## ORDER BY — итоговая иерархия приоритетов

Структура **одинакова** для узкого и широкого паллета. Различается только направление `ПотенциалСекции`:

```sql
УПОРЯДОЧИТЬ ПО
    Узкопроходный УБЫВ,                    -- 0. Узкопроходные стеллажи — приоритет
    ДельтаГрузоподъемности ASC,             -- 1. Best-fit по весу (безлимит = 999999 → последние)
    МинимальнаяГлубинаНеОграничена ASC,    -- 2. Секции с ограничением глубины — первыми
    ОстатокВысота ASC,                     -- 3. Best-fit по высоте
    ПотенциалСекции [УБЫВ / ASC],          -- 4. Потенциал (направление — см. флаг)
    ОстатокВесЯчейка ASC,                  -- 5. Best-fit по весу ячейки
    Типоразмер.Вес ASC,                    -- 6. Best-fit по ёмкости секции
    ОстатокШирина,                         -- 7. Остаток ширины
    ОстатокВес,                            -- 8. Остаток веса
    УровеньДоступа [УБЫВ / ASC],           -- 9. Зона доступа (tiebreaker)
    ВремяДоступа [УБЫВ / ASC]              -- 10. Время доступа (tiebreaker)
```

## Динамическое управление направлением (BSL)

### Потенциал3ПаллетаВСекции
```bsl
ШиринаЯчейки = Справочники.Лико_ПредопределенныеЗначения
    .ШиринаСкладскойСекции.ЗначениеПараметра / 3;
Потенциал3ПаллетаВСекции = (Ширина <= ШиринаЯчейки);
```

| Флаг | Паллет | Направление | Логика |
|------|--------|-------------|--------|
| `Истина` | Узкий (≤ W/3) | **УБЫВ** | Сначала пустые секции — не создаём пустоты |
| `Ложь` | Широкий (> W/3) | **ASC** | Сначала занятые — дозаполняем перед новыми |

### ОбратныйПорядокВремени
Управляет только `УровеньДоступа` и `ВремяДоступа`:

| Значение | Поведение |
|----------|-----------|
| `Ложь` (default) | Ближние зоны, быстрый доступ — первыми |
| `Истина` | Дальние зоны, медленный доступ — первыми |

> `ДельтаГрузоподъемности` — всегда ASC, `ОбратныйПорядокВремени` его не меняет.

## Ключевые решения

### Типоразмер.Вес вместо ОстатокВес
`ОстатокВес` у секции 6т с загрузкой 4т = 2000кг — меньше чем у пустой 2.5т секции (2500кг). Паллет 500кг попадёт в 6т. Неправильно. `Типоразмер.Вес ASC` сравнивает полную ёмкость → выбирает минимально достаточную.

### ОстатокШирина убран из ORDER BY
Для узкого паллета ширина уже закодирована в `ПотенциалСекции`. Добавление `ОстатокШирина ASC` ломает логику: секция с широким паллетом (остаток 600мм, потенциал 2) обгоняет пустую (остаток 2700мм, потенциал 3).

### УровеньДоступа на позиции 5, не 1
Уровень доступа — tiebreaker, не главный критерий. На позиции 1 ближняя зона с пустотами обгоняла дальнюю с идеальным fit.

### Потенциал3ПаллетаВСекции — динамический порог
Раньше: `Потенциал3ПаллетаВСекции = (Ширина <= 900)` — хардкод.
Теперь: берётся из `Лико_ПредопределенныеЗначения.ШиринаСкладскойСекции / 3`.
