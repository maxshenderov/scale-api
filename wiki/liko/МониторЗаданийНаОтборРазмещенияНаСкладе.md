# МониторЗаданийНаОтборРазмещенияНаСкладе

> Внешний отчёт. Монитор заданий на отбор/размещение с HTML-режимом для отображения на планшетах в складском помещении (ЛК Высотный, Stellmart). Переключается флажком `ВыводВHTML`.

## Что делает

Отображает актуальные складские задания в трёх блоках:
- **Размещение** и **Перемещение** — две колонки рядом
- **Отбор** — отдельный блок на всю ширину под ними

Реализован альтернативный HTML-режим отображения — HTML-вёрстка вместо стандартных табличных полей формы 1С. HTML-режим оптимизирован под планшеты склада: крупный шрифт (26px), адаптивная вёрстка (float-layout + orientation media queries), отсутствие выделения текста и синей подсветки при тапе.

## Архитектура HTML-режима

### Проблема: стилевые цвета не резолвятся на сервере

Справочник `Лико_Стеллажи` хранит цвет подсветки стеллажа (`ЦветаСтелажей()`) как объект типа `Цвет`, но фактически это **стилевой цвет платформы** (например `стиль: Добавленный реквизит`). У такого объекта свойства `Красный`/`Зеленый`/`Синий` возвращают `0` **на сервере** — платформа не резолвит стилевые цвета в реальный RGB вне клиентского контекста. Методы `ПолучитьЦвет()` и `XMLСтрока()` для таких объектов недоступны/выбрасывают исключение.

**Решение:** конвертация цвета в hex выполняется **на клиенте**, где стилевые цвета резолвятся в реальный RGB корректно. Готовая hex-строка передаётся на сервер как параметр.

### Поток данных

```
Клиент: СформироватьHTML()
  → Сервер: ПолучитьЦветаСтелажейHexНаСервере()
       — вызывает Справочники.Лико_Стеллажи.ЦветаСтелажей(Склад)
       — НЕ резолвит цвета на сервере корректно (известное ограничение,
         оставлено для совместимости, но фактическая конвертация задумана на клиенте)
       — конвертирует RGB → hex через побитовую арифметику (Цел/%/Сред с hexChars)
       — возвращает Соответствие<СправочникСсылка.Лико_Стеллажи, СтрокаHex>
  → Сервер: СформироватьHTMLНаСервереСЦветами(СооСтелажейHex)
       — генерирует полный HTML-документ, подставляя hex-цвета
         в background строк таблиц по Строка.Стеллаж
       — результат пишется в реквизит формы `html` (поле HTML-документа)
```

### Конвертация RGB → HEX

```bsl
hexChars = "0123456789ABCDEF";
Hex = "#"
    + Сред(hexChars, Цел(к / 16) + 1, 1) + Сред(hexChars, (к % 16) + 1, 1)
    + Сред(hexChars, Цел(з / 16) + 1, 1) + Сред(hexChars, (з % 16) + 1, 1)
    + Сред(hexChars, Цел(с / 16) + 1, 1) + Сред(hexChars, (с % 16) + 1, 1);
```

Стандартный паттерн перевода каждого канала (0-255) в двузначное шестнадцатеричное представление через целочисленное деление и остаток от деления на 16.

## Структура HTML

Три блока-таблицы:
- **Размещение** и **Перемещение** — две колонки рядом (плавающий float-layout, `width:49.5%`)
- **Отбор** — отдельный блок на всю ширину под ними

Каждая таблица:
- Озаглавлена «плашкой» (`.badge`) — желтоватый бейдж со скруглённым правым верхним углом, имитирующий закладку
- Обёрнута в `.wrap` с `border-radius` и `box-shadow` для эффекта приподнятой карточки
- Строки подсвечиваются цветом стеллажа через инлайн `style="background:..."`

## Ключевые процедуры (клиент)

- `СформироватьHTML()` — клиентская процедура: вызывает серверную конвертацию цветов и генерацию HTML, записывает результат в поле `html`
- `УстановитьВидимость()` — скрывает/показывает группу `Группа1c` и поле `html` в зависимости от флажка `ВыводВHTML`

## Ключевые процедуры (сервер)

- `ПолучитьЦветаСтелажейHexНаСервере(Склад)` — получает цвета стеллажей, конвертирует RGB → hex. Известное ограничение: серверная конвертация для стилевых цветов некорректна; основная конвертация делается на клиенте
- `СформироватьHTMLНаСервереСЦветами(СооСтелажейHex)` — генерирует полный HTML-документ с подстановкой hex-цветов в background строк по `Строка.Стеллаж`

## Точки интеграции с формой

| Элемент | Назначение |
|---|---|
| `ВыводВHTML` (флажок) | переключатель режима отображения (HTML vs стандартные таблицы) |
| `УстановитьВидимость()` | скрывает/показывает группу `Группа1c` и поле `html` в зависимости от флажка |
| `СписокРазмещение`, `СписокПеремещение`, `СписокОтбор` | табличные части формы — источники данных, заполняются `ОбновитьСписки()` |
| `Строка.Стеллаж` | ключ для поиска цвета в `СооСтелажейHex` |
| `html` | реквизит формы типа «HTML-документ», куда пишется итоговый `ТекстHTML` |
| `ПриОткрытии` / таймер `ОбновитьСпискиКлиент` | периодическое обновление (раз в сек.) для авто-актуализации на планшете |

## Адаптивность под планшет

- `<meta name="viewport" content="width=device-width, initial-scale=1.0">` — отключает масштабирование
- Базовый layout — две колонки через `float:left; width:49.5%`
- При повороте в портретный режим (`@media screen and (orientation:portrait)`) колонки складываются в один столбец (`float:none; width:100%`)

**Важно (граничные случаи WebKit в 1С):**
- `display:flex` с `gap` — **не работает** в WebKit-движке встроенного в 1С браузера: щели между колонками не появляются
- `@media (max-width:...)` — **не срабатывает** при изменении размера окна формы; реагирует только `@media (orientation:...)`
- `backdrop-filter: blur()` — приводит к поломке рендеринга таблицы (контент «вываливается» из table в виде голого текста, теги не парсятся корректно)
- Решение: классический `float` layout + `clearfix` + ориентационные медиазапросы

## Визуальный стиль HTML

- Тёмный сине-зелёный диагональный градиент фона (`linear-gradient(135deg, rgba(26,58,107,0.7) 0%, rgba(45,106,79,0.7) 60%, rgba(26,58,107,0.7) 100%)`)
- Заголовки таблиц (`th`) — тёмно-синие (`#1a3a6b`), белый текст, шрифт 26px
- Ячейки данных (`td`) — белый фон, чёрный текст, шрифт 26px, серые границы (`#8090b0`)
- Бейджи названий таблиц — светло-жёлтые (`#FBED9E`), чёрный текст, 16px
- `user-select:none` и `-webkit-tap-highlight-color:transparent` — убирают выделение текста и синюю подсветку при тапе на планшете

## Известные ограничения / TODO

- Цвета по умолчанию (`Неопределено` в `СооСтелажейHex.Получить()`) выводятся как `#FFFFFF` — белый фон строки
- Поле `НомерЗаказ` в запросе `СписокОтбор` — без окончания «а» (частая опечатка при правке)
- Если `Лико_Стеллажи.ДопНастройки.ЦветСтеллажа` хранит цвет не как `Цвет`, конвертация пропускает запись (защита через `ТипЗнч`)
