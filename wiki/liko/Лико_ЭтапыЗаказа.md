# Лико_ЭтапыЗаказа

> Регистр сведений (периодический) — отслеживание прохождения этапов выполнения заказа клиента с возможностью отправки почтовых оповещений.

## Тип регистра
**Периодический** (`Periodical`). Фиксирует переход заказа между этапами с привязкой к дате.

## Измерения
- **Заказ** (`DocumentRef.ЗаказКлиента`) — заказ клиента
- **Площадка** (`CatalogRef.Лико_Площадки`) — производственная площадка

## Ресурсы
- **Количество** (`Число`) — количество на этапе
- **Этап** (`CatalogRef.Лико_ЭтапыВыполненияЗаказа`) — текущий этап выполнения заказа

## Реквизиты
- **Ответственный** (составной тип: `CatalogRef.Пользователи`, `CatalogRef.ФизическиеЛица`) — ответственный за этап
- **Комментарий** (`Строка`) — комментарий к этапу
- **РабочийЦентр** (`CatalogRef.РабочиеЦентры`) — рабочий центр, выполняющий этап
- **НомерБланка** (`Число`) — номер бланка заказа
- **ПричинаБлокировки** (`CatalogRef.Лико_ПричиныБлокировки`) — причина блокировки заказа на этапе
- **ИнформацияОСтатусеПоказанаНаТачпаде** (`Булево`) — флаг отображения статуса на тачпаде
- **ДатаОбработкиЭтапа** (`Дата`) — дата фактической обработки этапа

## Ключевые процедуры

### RecordSetModule — `ПолучитьЭтикеткиЗаказа()`
Возвращает таблицу с наименованиями номенклатуры и основным материалом по товарам указанного заказа. Используется для формирования текста оповещения.

### RecordSetModule — `ОтправитьОповещениеПриНеобходимости()`
Проверяет настройки оповещений (`Лико_НастройкиОпововещенияОбЭтапахЗаказа`) для пары (Этап, Заказ). Если у заказа включён **КонтрольЭтапов** и есть подписанные пользователи — отправляет email-оповещение через `Лико_Планирование.ОтправитьПисьмо()`. В теле письма:
- Номер заказа и этап
- Список этикеток (номенклатура)
- Основной материал первой этикетки
- Ссылка на поиск заказа: `https://dsp.ok-st.ru/orders-search?q=<НомерЗаказа>`

### RecordSetModule — `ПередЗаписью()`
При записи выполняет:
1. **Блокировка перехода в Производство без ДатыЭмиссии (ЧестныйЗнак)**: если площадка не Урал и не Сибирь, этап = Производство и включён ЧестныйЗнак — проверяет, что у всех товаров с заполненным Gtin заполнена ДатаЭмиссии. Если нет — запись удаляется из набора с сообщением пользователю.
2. **Отправка оповещений**: если дата записи = сегодня, вызывает `ОтправитьОповещениеПриНеобходимости()` для каждой строки.

### ФормаСписка — `ПриСозданииНаСервере()`
Стандартное создание формы списка (закомментированная логика отбора по площадке ИксПак).

## Связь с ЗаказКлиента
Центральный регистр для отслеживания жизненного цикла заказа. Каждый переход заказа на новый этап фиксируется записью в этом регистре. Используется:
- В [[Лико_Цветоделение]] для отображения текущего этапа в форме списка цветоделений
- Для почтовых оповещений ответственных при смене этапа
- Для контроля блокировок заказа (например, отсутствие ДатыЭмиссии для ЧестногоЗнака)
