# БизнесКонтекст

> Компания Лико, её боли и AI-продукт который мы строим — 4 этапа от MVP до тендерного анализа.

---

## Компания Лико

**Лико** — типография этикеток (Москва). Продукция:
- Самоклеящиеся этикетки (флексо, офсет, цифра)
- Термоусадочные этикетки
- Упаковка для FMCG (шампуни, алкоголь, молочка, бытовая химия, масла)
- Полуфабрикаты, пакеты

**Система учёта:** 1С ERP (`УправлениеПредприятием`) с кастомными расширениями `Лико_*`.

**Центральная сущность:** документ [[ЗаказКлиента]] — вся производственная жизнь вокруг него.
- Шапка: клиент, технология, рабочий центр, размеры этикетки, материал
- ТЧ `Цвета` — краски и операции печати
- ТЧ `ВидыРабот` — производственные секции
- ТЧ `Товары` — номенклатура, тираж, оригинал-макет
- ТЧ `Секции` — полные параметры технологии

## Боли, которые решает AI-ассистент

| # | Роль | Боль |
|---|------|------|
| 1 | Технолог | Тратит время на ручной анализ макета и параметров заказа |
| 2 | Экономист | Нет быстрого способа оценить рентабельность и риски нового заказа |
| 3 | Менеджер | Не может быстро предложить альтернативные технологии (флексо/офсет/цифра) |
| 4 | Менеджер | Нет автоматизации при создании заказа из входящего PDF-макета клиента |
| 5 | Все | Нет поиска похожих заказов из истории для быстрого заполнения параметров |

## 4 этапа AI-продукта

### Этап 0 — MVP: кнопка AI-Ассистент (2–3 недели) ← ТЕКУЩИЙ

**Что делает:** анализирует открытый заказ в 1С и возвращает HTML-форму с оценкой.

```
Кнопка в ЗаказКлиента
    ↓
[1С] AIАссистент.ПолучитьДанныеЗаказа() → JSON + PDF (base64)
    ↓ HTTP POST
[Python FastAPI] POST /api/v1/analyze
    ↓
order_normalizer.py → pdf_processor.py → LLM (Claude / Qwen) → html_generator.py
    ↓ HTML
[1С] Модальное окно с вкладками
```

**HTML-вкладки ответа:**
- ⚙️ **Техническая оценка** — параметры, раппорт, совместимость материалов, риски
- 💰 **Экономическая оценка** — цена, рентабельность, риски по расчёту
- 📄 **Анализ макета** — что Vision LLM видит на PDF
- ✓ **Чек-лист готовности** — что заполнено, чего не хватает

**1С-компоненты (новые модули):**

| Модуль | Тип | Назначение |
|---|---|---|
| `Лико_АИАссистентДанные` | Серверный | Сбор и сериализация данных заказа, HTTP → FastAPI |
| `Лико_АИАссистентКлиент` | Клиентский | Обработка кнопок, открытие модального окна с HTML |
| Расширение `Лико_ФормаДокумента` | Форма | Кнопки «AI-Ассистент технолога» и «AI-Ассистент экономиста» |

**Python-компоненты:**

| Модуль | Назначение |
|---|---|
| `api/main.py`, `routes.py` | FastAPI, POST /api/v1/analyze |
| `document_processor/order_normalizer.py` | Нормализация raw JSON из 1С |
| `document_processor/pdf_processor.py` | Парсинг PDF + Vision LLM |
| `llm/llm_client.py` | Клиент Claude API |
| `llm/prompts.py` | Production-промпты для технолога и экономиста |
| `html/html_generator.py` | Генерация HTML-форм |

**Прототип уже есть:** внешняя обработка [[AIАссистент]] в `1s/ERP/obrab/AIАссистент/` — реализован Agent Loop с 11 инструментами function calling. Это полноценный AI-ассистент прямо в 1С (без Python-бэкенда), работает через RouterAI и Омниум порталы.

### Этап 1 — Формирование заказа из PDF (4–6 недель)

**Что делает:** менеджер загружает PDF-макет клиента → система предлагает параметры нового заказа → human-in-the-loop подтверждение → программное создание `ЗаказКлиента` в 1С.

```
PDF (+ доп. файлы JPG/DOCX/TXT + комментарий менеджера)
    ↓
Phase 0: Vision LLM → визуальные параметры этикетки
Phase 1: Docling → структурный текст
    ↓
RAG: hybrid search (BM25 sparse + dense embeddings) → TOP-3 похожих заказов
    ↓
LLM + confidence scoring → параметры + вопросы для неопределённых
    ↓
[Если confidence < порог] → интерактивный уточняющий диалог с менеджером
    ↓
Лико_ПрограммноеСозданиеДокументовСправочников → новый ЗаказКлиента
```

**Ключевые пороги confidence:**
- `CONF_THRESHOLD_DEFAULT = 70%`
- `CONF_THRESHOLD_PRINT_TECH = 80%` (критичный)
- `CONF_THRESHOLD_WORK_CENTER = 85%` (критичный)

**Статус Phase1 кнопки:** реализована в обработке [[AIАссистент]] — кнопка «🧪 Тест Phase1» отправляет файл на Docling (:8001) и показывает извлечённый текст + confidence в HTML.

### Этап 1.5 — Индексация базы заказов (3–4 недели)

**Что делает:** фоновая переиндексация 100K+ заказов из 1С в Qdrant для RAG.

```
[batch_indexer] → 1С API (все ЗаказКлиента) → Docling (текст из макетов)
    ↓
Qdrant коллекция `orders_phase1`
    векторы: phase1_text_dense (384d COSINE) + phase1_text_bm25 (sparse DOT)
    payload: order_id, технология, рабочий центр, материал, размеры, цвета, рентабельность...
```

**Qdrant payload для каждого заказа:**
- Из реквизитов 1С: `order_type` (Лико_ТипЗаказа), `label_type` (Лико_ТипЭтикетки)
- Из наименования (эвристика): `product_category` (шампунь, вина, масла_автохимия и др. — 30+ категорий)
- Из Vision LLM анализа макета: `technology`, `label_shape`, `varnish_type`, `maket_confidence`

---

### Этап 2 — Мультитехнологический расчёт стоимости (6–8 недель)

**Что делает:** для заказа рассчитывает стоимость по нескольким технологиям (флексо/офсет/цифра/трафарет), сравнивает рентабельность, рекомендует оптимальную.

- FastAPI: `POST /api/v1/cost-analysis`
- Интеграция с 1С для получения нормативов
- Таблица вариантов с ценами и рентабельностью

---

### Этап 3 — Анализ тендеров (8–10 недель)

**Что делает:** мониторинг источников тендеров (Госзакупки, Тендер.про), фильтрация по типу этикеток, расчёт стоимости + вероятность выигрыша.

- FastAPI: `POST /api/v1/tenders/analyze`
- ML-модель оценки вероятности выигрыша
- Рекомендация: «Участвовать / Не участвовать»

## Критерии успеха

| Показатель | Цель |
|---|---|
| Анализ заказа (Этап 0) | < 5 сек |
| Создание заказа из PDF (Этап 1) | < 10 сек |
| Поиск похожих заказов | < 2 сек |
| Расчёт стоимости | < 3 сек |
| Human-in-the-loop | На всех критических решениях |
