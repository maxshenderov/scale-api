# WMS Optimizer — Итоговое резюме (2026-07-20)

> Статус: **в работе**. Три функции оптимизатора реализованы, но требуют доработок по ТЗ.

## Что сделано

### Функция 1: `ОптимальноеРазмещениеПаллет`
- **v1** (19.07): BFD-размещение с категориями wide/medium/narrow, две фазы (прямое + перестановки)
- **v2** (20.07): Убран категорийный подход, добавлен учёт реальной ширины секции (Σширин + (N+1)×зазор)
- **v3** (20.07): Добавлен быстрый пре-фильтр (высота/ширина/вес), `ОшибкиРазмещенияПаллетаВАдрес` вызывается 1 раз на паллет (для лучшего кандидата)
- **Текущий статус**: размещает ~1758 из 2690 паллет (65%) на ЛК Высотный 6

### Функция 2: `РеслотСклада`
- Жадный алгоритм: поиск кандидатов на объединение, сортировка по эффективности, отбор в бюджет перемещений
- Проверка ширины: Σширин + (N+1)×ЗазорШ (ЗазорШ=50 захардкожен)
- **Текущий статус**: работает, находит кандидатов

### Функция 3: `ПодобратьВысотыЭтажей(Стеллаж)`
- Двухпроходный подбор: p90 → каталог типоразмеров → геометрическое ограничение
- Распределение избытка одному этажу с максимальным запасом
- **Текущий статус**: работает корректно для одиночного стеллажа

### Функция 4: `ПодобратьВысотыЭтажейДляСклада(Склад)`
- Берёт ВСЕ паллеты склада, разделяет на VNA/Wide пулы
- Распределяет по стеллажам с расходованием пула
- Авто-определение последнего этажа как геометрического якоря
- Compression pass при Избыток < 0 (перераспределение паллет)
- Warehouse-level сводка (Всего/Сейчас/После/Прирост)
- **Текущий статус**: работает, но даёт 2026 паллет vs 2690 реальных

### Инфраструктура
- `СортироватьПоВысоте()` — хелпер пузырьковой сортировки
- Тест сохранён: `memory/wms-placement-test-2690.md`

## Критические несоответствия ТЗ (из wms-optimizer-fixes-for-claude.md)

### 🔴 `ОптимальноеРазмещениеПаллет`
1. **ВиртуальноеСостояние не передаётся в валидатор** — сейчас `ОшибкиРазмещенияПаллетаВАдрес(Ячейка, Паллет)` без 5-го параметра. Сигнатура: `ОшибкиРазмещенияПаллетаВАдрес(Ячейка, Паллет, Типоразмер, ПолныйОтвет, ВиртуальноеСостояние)`. ВиртуальноеСостояние = `Соответствие(Ячейка → ПаллетСсылка)`.
2. **Фаза 2 (перестановки) не работает** — `МаксПерестановок` игнорируется, `Rearrangements` всегда пуст
3. **Stats не соответствует ТЗ** — нет `ПлотностьДо`/`ПлотностьПосле`
4. **Нет инициализации ВиртуальногоСостояния текущими остатками**

### 🔴 `РеслотСклада`
5. **Самодельные проверки вместо `ОшибкиРазмещенияПаллетаВАдрес`** — захардкожен `Зазор = 50`, ручные проверки ширины/высоты/веса
6. **Тай-брейк при сортировке** — нет вторичного ключа (Cost) при равной эффективности
7. **Stats без `ПриростПлотности`**

### 🟡 `ПодобратьВысотыЭтажей`
8. **Нет защиты `МинДостаточно >= maxH`** (в одиночной функции)
9. **Нет обработки `Избыток < 0`** (Summary.Ошибка)
10. **Summary неполный** — нет `ВсегоПотерьМм`, `СреднийПроцентПотерь`, `ОптимизируемыхЭтажей`
11. **Floors без структур `ТекущийТипоразмер`/`РекомендуемыйТипоразмер`** — сейчас голая ссылка

### 🟡 `ПодобратьВысотыЭтажейДляСклада`
12. **Авто-якорь последнего этажа** противоречит ТЗ (флаг `ВысотаОтПолаФиксирована` должен проверяться только на самом этаже)
13. **Нет проверки границ массива** в блоке СЖАТИЕ (`Совместимые[Старт]` может выйти за границы)

## Нерешённые проблемы

### Производительность `ОптимальноеРазмещениеПаллет`
- 2690 паллет × 5100 адресов = 13.7M итераций
- Даже с пре-фильтром, полный прогон может занимать минуты
- **Решение**: передача `ВиртуальноеСостояние` в валидатор (п.1) + Фаза 2 с перестановками (п.2)

### Качество размещения
- 1758/2690 = 65% — хуже текущего ручного размещения
- Причина: best-fit по высоте не оптимален для максимизации плотности
- Нужна Фаза 2 с перестановками для улучшения показателя

### Подбор высот даёт ухудшение
- 2026 vs 2690 — алгоритм находит меньше мест, чем уже занято
- Причина: p90 + типоразмеры из каталога дают более высокие рекомендации, чем текущие «уплотнённые» высоты
