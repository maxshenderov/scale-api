# WMS Optimizer — Session End 20.07.2026

## Результат сессии

**Главное**: section-level knapsack разместил 2690/2690 паллет за 3.5 минуты.  
**Но**: БЕЗ валидации `ОшибкиРазмещенияПаллетаВАдрес` — только пре-проверки. Результат НЕДОСТОВЕРНЫЙ.

## Что сделано

### `ОптимальноеРазмещениеПаллет` — эволюция за сессию
1. BFD с категориями wide/medium/narrow → 1758/2690 (65%)
2. BFD + реальная ширина секции → улучшенная версия
3. Top-20 best-fit + `ВиртуальноеСостояние` в валидаторе → 392/500 (78%)
4. First-fit с сортировкой по высоте → не тестировалось
5. **Section-level Greedy Knapsack** → 2690/2690 (100%) за 212с

### Ключевые находки
- `ОшибкиРазмещенияПаллетаВАдрес` принимает **5 параметров**, 5-й = `ВиртуальноеСостояние` (Соответствие Ячейка→ПаллетСсылка)
- ВиртуальноеСостояние инициализируется текущими остатками, паллеты из партии исключаются
- Section-level подход (группировка адресов по секциям, подбор комбинаций 1-3 паллет) работает на порядок лучше, чем pallet-level подходы

### `ПодобратьВысотыЭтажейДляСклада`
- Пул расходуется между стеллажами
- Compression pass при Избыток < 0
- Warehouse-level сводка

## Что НЕ работает

### 🔴 Критическое
1. **Knapsack без валидации** — `ОшибкиРазмещенияПаллетаВАдрес` не вызывается в knapsack-версии. Нужно добавить вызов с `ВиртуальноеСостояние` для каждого размещаемого паллета.
2. **Фаза 2 (перестановки) не реализована** — `МаксПерестановок` игнорируется
3. **Нет фильтра по рядам** в запросе секций — паллеты с рядов 1-7 могут размещаться в ряды 8-10

### 🟡 Среднее
4. `РеслотСклада` использует самодельные проверки вместо `ОшибкиРазмещенияПаллетаВАдрес`
5. `ПодобратьВысотыЭтажей` — нет защиты `МинДостаточно >= maxH`
6. Авто-якорь последнего этажа противоречит ТЗ

### 🟢 Мелкое
7. Stats не по ТЗ (нет ПлотностьДо/ПлотностьПосле)
8. Floors без структур `ТекущийТипоразмер`/`РекомендуемыйТипоразмер`
