## Корневые проблемы (почему оптимизатор работает хуже ручного)

### 1. Best-fit по высоте — неоптимальная стратегия
Алгоритм выбирает секцию где паллет "лучше всего" помещается по высоте (минимальный зазор). Это приводит к тому что высокие секции заполняются низкими паллетами, а для высоких паллет потом не остаётся места.

**Что нужно**: алгоритм должен учитывать не только текущий паллет, но и будущие. Стратегии:
- First-Fit Decreasing (FFD) по высоте: сначала высокие паллеты в высокие секции
- Сортировка паллет по высоте (не по ширине) для размещения
- Или: сортировка секций по высоте и размещение паллет от высоких к низким

### 2. Top-20 кандидатов — мало
20 кандидатов может не хватить если первые 20 все заняты/неподходят. Нужно либо больше кандидатов, либо перебирать все адреса но с ранним выходом.

### 3. Паллеты исключаются из ВиртуальногоСостояния
При инициализации ВиртуальногоСостояния паллеты из партии исключаются (их текущие ячейки считаются свободными). Это правильно для переразмещения, но означает что оптимизатор должен найти НОВОЕ место для каждого паллета — он не может оставить паллет там где он уже стоит.

### 4. Нет Фазы 2 (перестановки)
`МаксПерестановок` не реализован. Без перестановок алгоритм не может "подвинуть" уже размещённые паллеты чтобы освободить место для новых.
