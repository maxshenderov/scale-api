## ЧАСТЬ 1: ТЗ Phase 1

Кнопка "Быстрая дефрагментация" на вкладке "Оптимизация" в обработке `ЗагрузкаСклада`. Результат — HTML с подсветкой.

**Время выполнения:** <1 минута.

### Алгоритм (6 шагов)

**Шаг 1: Сбор данных из БД**
- Все секции склада (код, стеллаж, этаж, типоразмер, адреса 1/2/3)
- Паллеты в секциях (`Лико_ПаллетыВСекциях.Остатки` + `Лико_ПараметрыПаллет.СрезПоследних`)
- Паллеты на полу (`ПаллетыНаПолу(Склад)`)
- Ограничения стеллажей (Мин/Макс ширины/глубины)

**Шаг 2: Граф совместимости**

Для каждой пары занятых секций (СекцияА, СекцияБ):
```
ПаллетА = паллет в СекцияА
Проверить: ОшибкиРазмещенияВАдрес(АдресБ, ПаллетА, ..., ВиртуальноеСостояние)
Если Ошибки.Количество() = 0 → ребро СекцияА → СекцияБ
```
Граф: `Соответствие(КодСекции → Массив(КодСекции))`

**Шаг 3: Найти "воздушные" секции**
Секции с потенциалом ≥ 2 (место для ещё 1-2 паллетов).

**Шаг 4: Жадное паросочетание**
```
Для каждой воздушной секции S (по убыванию потенциала):
  Для каждой S2 из графа[S]:
    Если S2 не использована:
      Добавить перестановку {S → S2}
      Пометить S и S2 как использованные
```

**Шаг 5: Посчитать результат**
- Сколько ячеек освобождено
- Сколько паллетов с пола теперь влезут в освобождённые ячейки

**Шаг 6: HTML**
```
До: 98% → После: 99.5% (+45 ячеек)
Потенциал: 45 паллетов разместятся
[зелёный] = освобождённая секция
[жёлтый] = перемещённый паллет
```

### Виртуальное состояние

Копия регистра в памяти. При перестановках БД не меняется:
```
ВиртуальноеСостояние = {} // Адрес → Паллет

Для Каждого Строка Из Лико_ПаллетыВСекциях.Остатки:
    ВиртуальноеСостояние[Строка.Адрес] = Строка.Паллет

// При перестановке:
ВиртуальноеСостояние.Удалить(АдресОткуда)
ВиртуальноеСостояние.Вставить(АдресКуда, Паллет)
```

### ОшибкиРазмещенияВАдрес — параметр ВиртуальноеСостояние

```
Функция ОшибкиРазмещенияВАдрес(Ячейка, Паллет, Типоразмер, ПолныйОтвет,
                                ВиртуальноеСостояние = Неопределено)
```
- `Неопределено` → текущее поведение (чтение из БД)
- `Соответствие` → чтение из виртуальной памяти

### Новые процедуры (#Область БыстраяДефрагментация)

```
СобратьДанныеДляДефрагментации(Склад) → Структура
ПостроитьГрафПерестановок(Данные, ВиртСостояние) → Соответствие
НайтиВоздушныеСекции(Данные) → Массив
НайтиПаросочетание(Граф, Воздушные) → Массив
ПосчитатьРезультат(Паросочетание, Данные, ВиртСостояние) → Структура
СформироватьHTMLДефрагментации(Результат) → Строка
ВыполнитьБыструюДефрагментациюНаСервере()
```

### Порядок реализации

1. Модифицировать `ОшибкиРазмещенияВАдрес` (+ параметр ВиртуальноеСостояние)
2. `СобратьДанныеДляДефрагментации` — сбор из БД
3. `ПостроитьГрафПерестановок` — граф совместимости
4. `НайтиВоздушныеСекции` — потенциал ≥ 2
5. `НайтиПаросочетание` — жадное
6. `ПосчитатьРезультат` — подсчёт
7. `СформироватьHTMLДефрагментации` — визуализация
8. `ВыполнитьБыструюДефрагментациюНаСервере` — точка входа
9. Кнопка на форме + привязка к команде

## ЧАСТЬ 2: ПРОБЛЕМА — почему не работает

### Ситуация

- Склад **ЛК Высотный**: 1403 секции, ~2880 паллет в секциях, ~700 на полу
- Склад **98% заполнен**
- Задача: кнопка "Быстрая дефрагментация" — алгоритм который за <1 минуты считает какие паллеты можно переставить чтобы освободить ячейки для паллетов с пола

### Текущий подход (МЕДЛЕННЫЙ)

```
Для КАЖДОГО паллета в секции (2880 штук):
    Вызвать ПодобратьЯчейку(Все=Истина) — SQL запрос который ищет секции
    где паллет физически влезает и есть свободный адрес
```
Проблема: 2880 SQL запросов, каждый тяжёлый (JOIN по ~10 таблицам).

### Почему `ПодобратьЯчейку` не подходит

- `ПодобратьЯчейку` ищет секции со **свободными адресами** + физическая совместимость
- В 98%-ном складе свободных адресов **крайне мало** — запрос возвращает пустоту
- Нельзя использовать как "фильтр совместимости" — он фильтрует по занятости

### Почему `НайтиВоздушныеСекции` не помогает

- Ищет секции где адрес свободен
- В 98%-ном складе таких секций **почти нет**

### Суть проблемы

В 98%-ном складе:
1. **Свободных адресов почти нет** — нельзя просто "поставить паллет в пустую ячейку"
2. **Все секции заполнены** — нельзя "переставить паллет из секции А в секцию Б" потому что в Б тоже все адреса заняты
3. Единственный способ освободить место — **уплотнить**: найти секцию где стоят 2 паллета, переставить одного из них в другую секцию где есть место для него

### Что нужно

Алгоритм который:
1. Находит **пары секций** где можно сделать перестановку (паллет А из секции 1 влезет в секцию 2)
2. После перестановки в секции 1 освобождается адрес → проверяет влезет ли туда паллет с пола
3. Работает за <1 минуты на 2880 паллетов × 1403 секции

### Ограничения 1С

- Нельзя делать 2880 SQL запросов — слишком долго
- `ОшибкиРазмещенияПаллетаВАдрес` — проверяет все 15 правил размещения
- Виртуальное состояние — копия регистра в памяти, БД не меняется

### Данные которые уже собираются (СобратьДанныеДляДефрагментации)

- Все секции: Код, Ссылка, Стеллаж, Этаж, Адрес1/2/3, Типоразмер (Высота×Ширина×Глубина/Вес), ЗапретРазмещения, МаксВесПодъёма
- Паллеты в секциях: Адрес → Паллет, Типоразмер паллета
- Паллеты на полу: Типоразмер → Количество
- Ограничения стеллажей: Мин/Макс ширины/глубины

### 15 правил размещения (ОшибкиРазмещенияВАдрес)

1. Высота паллета ≤ Высота секции
2. Ширина: ≤W/3 → узкий (3 паллета), >W/3 ≤W/2 → средний (2, края), >W/2 → широкий (1, центр)
3. Глубина паллета ≤ Глубина секции
4. Вес паллета ≤ Вес секции (или безлимитная)
5. Вес паллета ≤ МаксВесПодъёма на этаж
6. Суммарный вес в секции ≤ Вес секции
7. МинимальнаяГлубинаНеОграничена — позволяет ставить любой глубины
8. МаксимальнаяГлубинаНеОграничена
9. МинГлубинаПаллета стеллажа
10. МаксГлубинаПаллета стеллажа
11. МинШиринаПаллета стеллажа
12. МаксШиринаПаллета стеллажа
13. ЗапретРазмещения на секции
14. Адрес уже занят
15. Правила ширины 1/3, 1/2 (central vs edges)
