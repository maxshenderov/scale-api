### 2.3 Ключевая функция валидации

```bsl
Справочники.Лико_СкладскиеСекции.ОшибкиРазмещенияПаллетаВАдрес(
    Ячейка,           // СправочникСсылка.СкладскиеЯчейки
    Паллет,           // СправочникСсылка.Лико_Паллеты2_0
    Типоразмер,       // Необязательный
    ПолныйОтвет,      // Необязательный
    ВиртуальноеСостояние  // Соответствие(Ячейка → ПаллетСсылка) — симулирует размещение без записи в регистры
)
```

**Критично**: `ВиртуальноеСостояние` — 5-й параметр. Валидатор сначала проверяет виртуальное состояние, потом реальный регистр. Это позволяет симулировать размещение без физической записи.

## 3. Функция `ОптимальноеРазмещениеПаллет`

### 3.1 Сигнатура

```bsl
Функция ОптимальноеРазмещениеПаллет(Склад, МассивПаллет, МаксПерестановок = 0) Экспорт
```

### 3.2 Возврат

```bsl
Структура {
    Placements: Массив({Паллет, Адрес, Секция, Стеллаж, Этаж}),
    Rearrangements: Массив({Паллет, ОткудаАдрес, КудаАдрес}),
    Unplaced: Массив({Паллет, Причина}),
    Stats: {Всего, Размещено, НеРазмещено, Перестановок}
}
```

### 3.3 Что реализовано

#### Этап 1: Загрузка данных
1. Загрузка габаритов всех паллет через `РегистрСведений.Лико_ПараметрыПаллет.СрезПоследних`
2. Загрузка всех секций склада с типоразмерами (ВысотаТС, ШиринаТС, ВесТС, БезлимВес) и адресами

#### Этап 2: Инициализация ВиртуальногоСостояния
```bsl
ВиртуальноеСостояние = Новый Соответствие;  // ключ = Ячейка, значение = ПаллетСсылка

// Заполняется текущими остатками склада
// Паллеты из партии (МассивПаллет) ИСКЛЮЧАЮТСЯ — их текущие ячейки считаются свободными
```

#### Этап 3: Сортировка
- Паллеты: по высоте (убыв), затем по ширине (убыв) — tall-first
- Адреса: по высоте секции (возр) — short sections first

#### Этап 4: Section-level Greedy Knapsack (текущая версия)
```bsl
Для каждой секции (сгруппированы адреса по Секция):
  1. Определить свободные адреса (0-3)
  2. Собрать кандидатов из пула (до 30):
     - Высота паллета <= Высота секции
     - Ширина паллета <= Ширина секции
     - Вес паллета <= Вес секции (если не безлим)
  3. Перебор комбинаций 1/2/3 паллет:
     - Критерий: максимизация суммарной ширины
     - Проверка: Σширин + (N+1)×ЗазорШ <= ШиринаСекции
     - Проверка суммарного веса
  4. Разместить лучшую комбинацию, удалить паллеты из пула
Оставшиеся в пуле → Unplaced
```

**ВАЖНО: В текущей версии НЕТ вызова `ОшибкиРазмещенияПаллетаВАдрес` — только пре-проверки.**

#### Что НЕ реализовано
- **Нет валидации через `ОшибкиРазмещенияПаллетаВАдрес`** — размещение без проверки реальных ограничений 1С
- **Фаза 2 (перестановки)** — `МаксПерестановок` игнорируется
- **ПлотностьДо/ПлотностьПосле** в Stats
- **Фильтр по рядам** (секции загружаются со всего склада)

### 3.4 Результаты тестов

| Тест | Алгоритм | Размещено | Время |
|------|---------|-----------|-------|
| 500 паллет | BFD + top-20 best-fit | 392 (78%) | 257с |
| 500 паллет | Section-level knapsack | 500 (100%)* | 133с |
| 2690 паллет | Section-level knapsack | 2690 (100%)* | 212с |

\* Без валидации `ОшибкиРазмещенияПаллетаВАдрес` — результат НЕДОСТОВЕРНЫЙ

## 3.5 Правила из штатного `ПодобратьЯчейку` (обязательно реализовать)

Источник: `obrab/ZagSklad/ЗагрузкаСклада/Templates/WMS_ПодобратьЯчейку_BSL/Ext/Template.txt`

### 3.5.1 Пре-фильтр секций (пакет `ВТСекции`)

```bsl
ГДЕ
    НЕ ПометкаУдаления
    И Типоразмер.Глубина >= &Глубина
    И (Типоразмер.НеОграниченаПоГрузоподъемности ИЛИ Типоразмер.Вес >= &Вес)
    И Типоразмер.Высота >= &Высота
    И Склад = &Склад
    И НЕ ЗапретРазмещения
    И (Стеллаж.МинШиринаПаллета = 0 ИЛИ Стеллаж.МинШиринаПаллета <= &Ширина)
    И (Стеллаж.МаксШиринаПаллета = 0 ИЛИ Стеллаж.МаксШиринаПаллета >= &Ширина)
    И (Стеллаж.МинГлубинаПаллета = 0 ИЛИ Стеллаж.МинГлубинаПаллета <= &Глубина)
    И (Стеллаж.МаксГлубинаПаллета = 0 ИЛИ Стеллаж.МаксГлубинаПаллета >= &Глубина)
```

### 3.5.2 Фильтр секций с остатками (пакет `ВтСекцииСОстатками`)

```bsl
ГДЕ
    // Хотя бы один адрес свободен
    (Паллет1 = ПустаяСсылка ИЛИ Паллет2 = ПустаяСсылка ИЛИ Паллет3 = ПустаяСсылка)
    // Остаток ширины > 0
    И Типоразмер.Ширина - (Типоразмер1.Ширина + Типоразмер2.Ширина + Типоразмер3.Ширина) > 0
    // Остаток веса >= вес паллета
    И (НеОграниченаПоГрузоподъемности
       ИЛИ Типоразмер.Вес - (Типоразмер1.Вес + Типоразмер2.Вес + Типоразмер3.Вес) >= &Вес)
    // Если Адрес2 занят — паллет в нём должен быть узким
    И (Паллет2 = ПустаяСсылка ИЛИ Типоразмер2.Ширина < Типоразмер.Ширина / 3)
    // Wide (>W/2): все 3 адреса свободны
    И (&Ширина <= Типоразмер.Ширина / 2
       ИЛИ (Паллет1 = ПустаяСсылка И Паллет2 = ПустаяСсылка И Паллет3 = ПустаяСсылка))
    // Medium (>W/3): Адрес2 свободен + один из крайних свободен
    И (&Ширина <= Типоразмер.Ширина / 3
       ИЛИ (Паллет2 = ПустаяСсылка И (Паллет1 = ПустаяСсылка ИЛИ Паллет3 = ПустаяСсылка)))
```

### 3.5.3 Правило выбора адреса

```bsl
ВЫБОР
    // Wide (>W/2): занимает всю секцию → Адрес2 (средний)
    КОГДА &Ширина > Типоразмер.Ширина / 2
        ТОГДА Адрес2
    // Medium (>W/3): занимает 2 адреса → Адрес1 (если свободен), иначе Адрес3
    КОГДА &Ширина > Типоразмер.Ширина / 3
        ТОГДА ВЫБОР
                КОГДА Паллет1 = ПустаяСсылка ТОГДА Адрес1
                ИНАЧЕ Адрес3
            КОНЕЦ
    // Narrow (≤W/3): в любой свободный адрес
    ИНАЧЕ ВЫБОР
            КОГДА Паллет1 = ПустаяСсылка
                ТОГДА Адрес1
            КОГДА Паллет2 = ПустаяСсылка
                И Типоразмер1.Ширина <= Типоразмер.Ширина / 3
                И (Паллет3 = ПустаяСсылка ИЛИ Типоразмер3.Ширина <= Типоразмер.Ширина / 3)
                ТОГДА Адрес2
            КОГДА Паллет3 = ПустаяСсылка
                ТОГДА Адрес3
            ИНАЧЕ Адрес1
        КОНЕЦ
КОНЕЦ
```

### 3.5.4 Потенциал секции

```bsl
ВЫБОР
    КОГДА Паллет1 <> ПустаяСсылка И Типоразмер1.Ширина > Ширина / 3 И Паллет3 = ПустаяСсылка
        ТОГДА 2  // левый край занят широким, правый свободен
    КОГДА Паллет3 <> ПустаяСсылка И Типоразмер3.Ширина > Ширина / 3 И Паллет1 = ПустаяСсылка
        ТОГДА 2  // правый край занят широким, левый свободен
    КОГДА (Паллет1 = ПустаяСсылка ИЛИ Типоразмер1.Ширина <= Ширина / 3)
         И (Паллет3 = ПустаяСсылка ИЛИ Типоразмер3.Ширина <= Ширина / 3)
        ТОГДА 3  // оба края свободны или заняты узкими (≤W/3)
    ИНАЧЕ 0      // оба края заняты широкими
КОНЕЦ
```

### 3.5.5 Приоритеты сортировки (ORDER BY)

```
1. Стеллаж.МаксШиринаПаллета УБЫВ
2. ДельтаГрузоподъемности (Вес секции − Вес паллета)
3. ОстатокВысота (best-fit)
4. ПотенциалСекции УБЫВ
5. Типоразмер.Вес (минимальная грузоподъёмность)
6. ОстатокШирина
7. ОстатокВес
8. УровеньДоступа УБЫВ (ближняя зона = 1, дальняя = 2)
9. ВремяДоступа УБЫВ
```

## 4. Что нужно сделать

### Приоритет 1: Добавить валидацию в knapsack
В section-level цикле после подбора комбинации вызывать `ОшибкиРазмещенияПаллетаВАдрес` с `ВиртуальноеСостояние` для каждого паллета. Если паллет не проходит валидацию — пропустить его (не размещать), попробовать следующего кандидата.

```bsl
// После нахождения ЛучшиеИндексы, перед размещением:
Для Каждого Инд Из ЛучшиеИндексы Цикл
    П = Кандидаты[Инд];
    Ошибки = Справочники.Лико_СкладскиеСекции.ОшибкиРазмещенияПаллетаВАдрес(
        ЦелевойАдр.Ячейка, П.Ссылка, , , ВиртуальноеСостояние);
    Если Ошибки.Количество() > 0 Тогда
        // Этот паллет не подходит — пропускаем, пробуем другой адрес
        Продолжить;
    КонецЕсли;
    // Размещаем...
КонецЦикла;
```

### Приоритет 1.5: Правила выбора адреса внутри секции
В штатном `ПодобратьЯчейку` (пакет `ВТСекции`) адрес выбирается НЕ по порядку, а по правилам:

```bsl
ВЫБОР
    КОГДА &Ширина > Типоразмер.Ширина * 2 / 3           ТОГДА Адрес2  // wide pallet → middle
    КОГДА Паллет1 = ПустаяСсылка                          ТОГДА Адрес1  // left free
    КОГДА Паллет3 = ПустаяСсылка                          ТОГДА Адрес3  // right free
    КОГДА Паллет2 = ПустаяСсылка                          ТОГДА Адрес2  // middle free
    ИНАЧЕ ПустаяСсылка                                                  // все заняты
КОНЕЦ
```

**Нужно**: в knapsack при назначении паллета на адрес использовать эти же правила, а не просто первый свободный. Также учесть пре-фильтры из пакета `ВТСекции`.

### Приоритет 2: Фаза 2 — перестановки
Для паллетов оставшихся в пуле после Фазы 1:
1. Перебирать этажи снизу вверх
2. Находить стоящий паллет P в секции
3. Искать другое место для P на том же этаже (через валидатор + ВиртуальноеСостояние)
4. Если нашли → переместить P, поставить новый паллет в освобождённый адрес
5. Учитывать бюджет `МаксПерестановок`

### Приоритет 3: Stats по ТЗ
