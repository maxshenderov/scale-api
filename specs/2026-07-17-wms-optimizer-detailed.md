## 1. Предметная область

### Склад

Система управляет складом адресного хранения. Склад состоит из **стеллажей** — металлических конструкций с ячейками для паллет. Реальный склад: 9 стеллажей, 1403 секции, проект Gonvarri P90 VNA (Very Narrow Aisle — узкопроходная техника).

### Стеллаж (Rack)

Стеллаж — это ряд секций одинаковой структуры. Имеет:

- **Количество секций** (sectionsCount) — сколько секций в ряду (обычно 17-18)
- **Количество этажей** — сколько уровней по вертикали (9-10)
- **3 адреса в каждой секции** (cellsPerSection) — ячейки Адрес1, Адрес2, Адрес3
- **Узкопроходный** (narrowAisle) — флаг: стеллаж для узкопроходной техники (VNA)
- **Ограничения габаритов паллета** — мин/макс ширина и глубина паллета, которые можно ставить в этот стеллаж

### Этаж (Floor)

Каждый этаж стеллажа имеет свой **типоразмер секции** и **физические параметры для штабелёра**:

| Параметр | Описание | Единицы |
|---|---|---|
| Типоразмер секции | Габариты ячейки на этом этаже (высота×ширина×глубина×грузоподъёмность) | мм, кг |
| МаксимальныйВесПодъёмаНаЭтаж | Макс. вес который штабелёр может поднять на эту высоту | кг |
| Зазор (по высоте) | Пространство над паллетом до балки — для манёвра вил | мм |
| ВысотаБалки | Толщина горизонтальной балки стеллажа | мм |
| ВысотаОтПола | Расстояние от пола до низа балки первого этажа | мм |
| ВысотаОтПолаФиксирована | Если Истина — высоту от пола и последний этаж менять **нельзя** | bool |
| ЗазорПоШирине | Боковой зазор на один промежуток между паллетами и стойками | мм |
| МинимальнаяГлубинаНеОграничена | Нет ограничения снизу по глубине паллета | bool |
| МаксимальнаяГлубинаНеОграничена | Нет ограничения сверху по глубине паллета | bool |

**Геометрия этажа по вертикали (для вида сбоку и подбора высот):**

```
Высота секции = Высота габарита типоразмера + Зазор (по высоте)

Полная высота этажа (floor-to-floor) = Высота секции + ВысотаБалки
                                        ├── Габарит.Высота ──├─ Зазор ─├─ Балка ─┤

Балка ═══════════════════  ← верхняя граница этажа (она же низ следующего)
      │                    │
      │  Паллет            │ ← полезная высота = Габарит.Высота − Зазор
      │                    │    (паллет не должен быть выше этого)
      │                    │
──────├────────────────────┤ ← низ секции (верх балки предыдущего этажа или пол)
Балка ═══════════════════
```

**Ограничения при подборе высот этажей (§10):**
- Если `ВысотаОтПолаФиксирована = Истина` → высоту первого этажа от пола менять **нельзя**
- Последний (верхний) этаж — **фиксированная** высота, менять **нельзя**
- Остальные этажи между ними — можно оптимизировать

### Секция (Section)

Секция — это физический слот в стеллаже на конкретном этаже. Каждая секция содержит **ровно 3 адреса** (Address1, Address2, Address3).

**Правила размещения паллет в секции — ширина:**

Формула: `сумма ширин всех паллет + (N+1) × ЗазорПоШирине ≤ Ширина секции`

Где `ЗазорПоШирине` берётся из `Этажи.ЗазорПоШирине` стеллажа (**не** хардкод).

Паллеты классифицируются по ширине относительно ширины секции:

```
W = ширина секции (обычно 2700мм или 2300мм)

Узкий паллет:   ширина ≤ W/3 → занимает 1 адрес (влезает до 3 в секцию)
Средний паллет: W/3 < ширина ≤ 2W/3 → занимает 2 адреса (блокирует Address2)
Широкий паллет: ширина > 2W/3 → занимает 3 адреса (вся секция)
```

```
Визуально — секция 2700мм с 3 адресами:

┌─────────────┬─────────────┬─────────────┐
│  Address1   │  Address2   │  Address3   │
│   900мм     │   900мм     │   900мм     │
└─────────────┴─────────────┴─────────────┘

Три узких:     ▓▓▓│▓▓▓│▓▓▓     (≤900 каждый, 3 адреса заняты)
Средний:       ▓▓▓▓▓▓│░░░     (W/3 < ширина ≤ 2W/3, Address1+2 заняты, Address3 свободен)
               ░░░│▓▓▓▓▓▓     (Address1 свободен, Address2+3 заняты)
Широкий:       ▓▓▓▓▓▓▓▓▓▓▓     (> 2W/3, все 3 адреса заняты)
```

**Монтажный зазор по ширине:**

Между паллетами и стойками нужен зазор для манёвра штабелёра. Формула:

```
ОбщийЗазор = (N + 1) × ЗазорПоШирине

где N = количество паллетов в секции
ЗазорПоШирине = значение из этажа стеллажа (обычно 50мм)
```

| N паллетов | Зазор |
|---|---|
| 1 | (1+1)×50 = 100мм |
| 2 | (2+1)×50 = 150мм |
| 3 | (3+1)×50 = 200мм |

**Пример:** секция 2700мм, 3 паллета по 800мм:
- Сумма ширин = 3×800 = 2400мм
- Зазор = 200мм
- Всего = 2600мм ≤ 2700мм ✓ ВЛЕЗАЕТ

**Пример:** секция 2700мм, 3 паллета по 900мм:
- Сумма ширин = 3×900 = 2700мм
- Зазор = 200мм
- Всего = 2900мм > 2700мм ✗ НЕ ВЛЕЗАЕТ

### Паллет (Pallet)

Паллет — это единица хранения. Имеет:

- **Типоразмер** (PalletType): высота, ширина, глубина, вес
- **Штрихкод** — уникальный код паллета
- **Состав** — номенклатура, серии, количество (товары на паллете)

Паллет может находиться:
- **В секции** — размещён в конкретном адресе (ячейке)
- **На полу у стеллажа** — в зоне приёмки/отгрузки конкретного стеллажа
- **На полу общей зоны** — в зоне приёмки без привязки к стеллажу

### Ключевые справочники 1С

| Справочник | Что хранит |
|---|---|
| `Склады` | Склады предприятия |
| `Лико_Стеллажи` | Стеллажи: топология, этажи с типоразмерами, зоны приёмки |
| `Лико_СкладскиеСекции` | Секции: 3 адреса, привязка к стеллажу и этажу |
| `СкладскиеЯчейки` | Ячейки (адреса) — иерархический справочник |
| `Лико_Паллеты2_0` | Паллеты: код, тип |
| `Лико_ТипоразмерыПаллет` | Типоразмеры паллет: В×Ш×Г, вес |
| `Лико_ТипоразмерыСкладскихСекций` | Типоразмеры секций: В×Ш×Г, грузоподъёмность |

### Ключевые регистры 1С

| Регистр | Что хранит |
|---|---|
| `Лико_ПаллетыВСекциях` (остатки) | Какие паллеты в каких секциях/адресах |
| `Лико_ПараметрыПаллет` (срез последних) | Типоразмер каждого паллета |
| `ТоварыВЯчейках` (остатки) | Товары в ячейках (состав паллета) |

## 2. Что уже есть

### Существующая обработка «ЗагрузкаСклада»

Внешний отчёт 1С с визуализацией загрузки склада:

- **Страница «Схема»** — HTML-поле с интерактивной визуализацией стеллажа (вид спереди)
- **Страница «АдресаХранения»** — таблица результатов подбора ячеек
- **Страница «Ассистент AI»** — чат с LLM для анализа склада
- **Drag-and-Drop** — перемещение паллетов мышкой в HTML (уже работает)
- **Подсветка** — ячейки подсвечиваются при наведении
- **Процент загрузки** — на кнопках стеллажей

### Существующий алгоритм «ПодобратьЯчейку»

Функция `Лико_СкладскиеСекции.ПодобратьЯчейку()` — жадный подбор **одной** лучшей ячейки для **одного** паллета:

- Фильтрует секции по складу и габаритам (глубина, вес, высота)
- Определяет уровень доступа (ближняя/дальняя половина стеллажа)
- Собирает остатки паллет по 3 адресам каждой секции
- Вычисляет остатки ширины, веса, высоты
- Сортирует по 13 приоритетам (ORDER BY): узкопроходный, потенциал, best-fit высоты, веса, ширины, уровень доступа, время доступа
- Возвращает ПЕРВЫЕ 1 — ближайшую подходящую ячейку

**Ограничение:** работает с одним паллетом за раз. При пакетном размещении порядок паллетов влияет на результат — первый пришедший может занять место, которое лучше подошло бы другому.

### Существующий HTTP-сервис «Liko_Rest»

Единая точка входа для внешних систем: `POST /hs/Liko_Rest`

Принимает JSON с полем `ProcName`, делегирует вызов в BSL-функцию. Более 70 эндпоинтов: пользователи, остатки, продажи, отгрузки, производство. Все ответы — JSON.

### Существующий модуль расширения «Лико_WMS_Сервер»

Создан скелет модуля (XML) в расширении `РасширениеЛико`. BSL-код ещё не написан — будет содержать реализации 10 новых ProcName.

## 3. Задачи которые нужно решить

### Задача 1: Алгоритм плотного размещения партии паллет

**Проблема:** текущий `ПодобратьЯчейку` работает с одним паллетом. При пакетном размещении порядок влияет на плотность.

**Что нужно:** алгоритм, который принимает список паллет (с габаритами) и возвращает план размещения, максимизирующий количество секций с 3 паллетами.

**Пример проблемы:**
```
Приехало: [700, 900, 800, 850, 800, 700, 900, 800]

Жадный (как пришли):
  700 → секция A, Адрес1
  900 → секция A? 700+900+150=1750 ✓ Адрес2
  800 → секция A? 700+900+800+200=2600 ✓ Адрес3 — секция A полна (3) ✓
  850 → секция B, Адрес1
  800 → секция B? 850+800+150=1800 ✓ Адрес2
  700 → секция B? 850+800+700+200=2550 ✓ Адрес3 — секция B полна (3) ✓
  900 → секция C, Адрес1
  800 → секция C? 900+800+150=1850 ✓ Адрес2
  Итого: 3 секции (A,B полные, C с 2 паллетами)

Но если бы 900 пришли с другими 900:
  900+900+700 = 2500+200=2700 ✓ — секция A полна
  850+800+800 = 2450+200=2650 ✓ — секция B полна
  800+700 = 1500+150=1650 ✓ — секция C с 2 паллетами
  Тоже 3 секции — но с другим распределением.
```

Алгоритм MVP (фаза 1) решает задачу пакетного размещения **новых** паллет без перемещения существующих — greedy с сортировкой по убыванию ширины и приоритетом добивки частично занятых секций.

**Ре-слоттинг** (перемещение уже стоящих паллет для максимизации плотности) — фаза 2, будет спроектирован отдельно после валидации greedy-алгоритма на реальных данных склада.

### Задача 2: Визуализация — вид сбоку и фронтальный вид

**Проблема:** существующая обработка показывает только фронтальный вид (секции по горизонтали). Нет вида сбоку — профиля стеллажа с балками и глубиной паллет.

**Что нужно:** два режима отображения с переключением:

- **Фронтальный вид** — секции в ряд, этажи друг над другом, паллеты как цветные блоки
- **Вид сбоку** — профиль стеллажа: балки, зазоры по высоте, глубина паллета

Все размеры (высота балки, зазор, расстояние от пола) должны браться из 1С (из ТЧ `Этажи` стеллажа), а не хардкодиться.

### Задача 3: Drag-and-drop с валидацией и выполнением

**Проблема:** существующий DnD работает только внутри 1С-обработки. Нужен в веб-приложении с обратной связью с 1С.

**Что нужно:**
- При перетаскивании паллета над ячейкой — мгновенная проверка через 1С: можно ли поставить
- Зелёная/красная/оранжевая подсветка ячейки
- При отпускании (drop) — создание документа перемещения в 1С
- Обновление визуализации после перемещения

### Задача 4: Переключение между базами 1С

**Проблема:** нужно тестировать алгоритм на тестовой базе не трогая боевую.

**Что нужно:** PostgreSQL-таблица с настройками подключений к разным базам 1С. Выпадающий список в UI для переключения.

### Задача 5: Подбор оптимальных высот этажей стеллажа

**Проблема:** при проектировании нового стеллажа (или реконфигурации существующего) нужно определить какие типоразмеры секций назначить на какие этажи, чтобы максимизировать вместимость для ожидаемого распределения паллет по высотам.

**Входные данные:**
- Физические параметры стеллажа: общая высота, ширина секции, глубина, грузоподъёмность
- Количество этажей
- Распределение паллет по высотам: например, 20% паллет высотой 800-1000мм, 30% — 1000-1300мм, 35% — 1300-1600мм, 15% — 1600-2000мм
- Параметры балки: высота балки, зазор по высоте

**Что нужно:** алгоритм который для заданного распределения высот паллет подбирает высоты секций на каждом этаже так, чтобы:
1. Максимизировать количество паллет которые можно разместить
2. Минимизировать wasted space (пустое пространство над паллетом)
3. Учитывать ограничение по максимальному весу подъёма на этаж (тяжёлые паллеты — на нижние этажи)

**Выход:** таблица «этаж → рекомендуемая высота секции + ожидаемый % использования».

### Задача 6: Фильтры и поиск

**Что нужно:**
- Фильтр по стеллажам (галочки 1-9)
- Фильтр по заполненности (все / свободные / частично занятые / полные / запрет размещения)
- Поиск паллета по коду (подсветка найденного)
- Показ неразмещённых паллет (результат алгоритма)

### Задача 7: Информационные панели

**Что нужно:**
- При клике на секцию — параметры секции (код, габариты, остатки ширины/веса)
- При клике на паллет — характеристики паллета (код, габариты, вес)
- При двойном клике на паллет — состав паллета (номенклатура, серии, количество)
- Статистика внизу: % загрузки склада, всего/занято/свободно секций, результат размещения

### Поток данных (пример — открытие склада)

```
1. Пользователь выбирает базу 1С из выпадающего списка
   → POST /api/connections/activate { id: 2 }
   → Python: UPDATE connections SET is_active = true WHERE id = 2

2. Пользователь выбирает склад
   → Svelte: POST /api/racks { warehouse }
     → Python: берёт активное подключение из PG
     → Python: POST { ProcName: "WMS_GetRacks", warehouse } → 1С
     ← Python: обогащает (кэширует на 1 час)
   ← Svelte: отрисовывает стеллажи

3. Svelte: POST /api/occupancy { warehouse }
   → Python → 1С: WMS_GetOccupancy
   ← Python: считает проценты загрузки (без кэша)
   ← Svelte: раскрашивает ячейки

4. Пользователь жмёт «Рассчитать размещение»
   → Svelte: POST /api/optimize { warehouse, pallets: [...] }
     → Python: запускает алгоритм-рюкзак
     → Python → 1С: WMS_PlacePallets
   ← Svelte: показывает план (placementPlan store)
```

### Кэширование

| Данные | TTL | Причина |
|---|---|---|
| Список складов | 24 часа | Меняется крайне редко |
| Топология стеллажей | 1 час | Меняется при реконфигурации |
| Занятость секций | Без кэша | Меняется при каждом перемещении |
| Паллеты на полу | Без кэша | Меняется при каждом перемещении |

**Инвалидация кэша:** `POST /api/cache/invalidate` — сбрасывает кэш складов и топологии немедленно (на случай изменения типоразмеров этажей через §10).

## 5. 1С HTTP API (10 эндпоинтов)

Все 10 эндпоинтов — через существующий HTTP-сервис 1С `Liko_Rest`.
Формат вызова: `POST /hs/Liko_Rest` с JSON-телом `{ "ProcName": "...", ... }`.
Каждый ProcName — отдельная BSL-функция в модуле `Лико_WMS_Сервер`.

### Единый контракт ошибок

Все ProcName возвращают одинаковую структуру при ошибке:

```json
// Успех:
{ "ok": true, ... }

// Ошибка:
{ "ok": false, "error": { "code": "INTERNAL_ERROR", "message": "Текст ошибки BSL" } }
```

Python-клиент проверяет `ok` в каждом ответе. HTTP-статус всегда 200 (ошибка на уровне JSON, не HTTP).

### 5.5 WMS_FindCell — подбор ячеек для одного паллета

Обёртка над существующей `Лико_СкладскиеСекции.ПодобратьЯчейку(Все=Истина)`.
Возвращает все подходящие адреса для паллета с сортировкой по 13 приоритетам (узкопроходность, потенциал, best-fit, уровень доступа, время доступа).

Python-оптимизатор (§9) вызывает этот ProcName для каждого паллета, а сам занимается только: (1) сортировкой партии и (2) выбором лучшего кандидата из возвращённого каждой секцией списка — без дублирования логики размещения.

```
→ { "ProcName": "WMS_FindCell",
    "warehouse": "UUID", "pallet": "UUID" }

← {
  "candidates": [
    {
      "section":      "UUID", "sectionCode": "Р1-М(1-2-3)-Э1",
      "address":      "UUID", "addressCode": "Р1М1Э1",
      "rack":         "UUID", "floor": 1,
      "remainingHeight": 540, "remainingWidth": 900,
      "sectionPotential": 3, "accessLevel": 1, "accessTime": 120
    }
  ],
  "totalCandidates": 42
}
```

**BSL:** вызывает `ПодобратьЯчейку(Склад, Высота, Ширина, Глубина, Вес, , Все=Истина)` — существующая функция с 13 приоритетами ORDER BY. Возвращает не ПЕРВЫЕ 1, а все подходящие.

### 5.6 WMS_PlacePallets — план размещения (симуляция)

Принимает список паллет (с габаритами) и возвращает план размещения.
**Не создаёт документов, не двигает паллеты физически** — только расчёт.

```
ЗАПРОС: {
  "ProcName":  "WMS_PlacePallets",
  "warehouse": "guid",
  "pallets": [
    { "id": "guid", "width": 800, "height": 1200, "depth": 1100, "weight": 500 }
  ],
  "options": {
    "mode":                  "newOnly",
    "fillExistingFirst":     true,
    "maxPalletsPerSection":  3
  }
}

ОТВЕТ: {
  "placements": [{
    "pallet":       "guid",
    "section":      "guid",
    "sectionCode":  "Р1-М(1-2-3)-Э1",
    "address":      "guid",
    "addressCode":  "Р1М1Э1",
    "action":       "place",
    "fillLevel":   1
  }],
  "unplaced": [
    { "id": "guid", "reason": "Нет секции с достаточной шириной" }
  ],
  "stats": {
    "total":           20,
    "placed":          18,
    "perfectSections":  5,
    "sectionsUsed":    12,
    "movesRequired":    0
  }
}
```

**Параметры options:**

| Параметр | Значения | Описание |
|---|---|---|
| `mode` | `"newOnly"` | Разместить только переданные паллеты, существующие не трогать |
| `fillExistingFirst` | `true`/`false` | Сначала добивать частично занятые секции, потом открывать новые |
| `maxPalletsPerSection` | 3 | Максимум паллет в секции (всегда 3 для данного склада) |

> **Примечание:** режим `"fullReslot"` (полный пересчёт с перемещением существующих паллет) — фаза 2, не входит в MVP.

**Качество размещения (fillLevel):**

| fillLevel | Значение |
|---|---|
| 1 | Добил секцию до 3 паллет (отлично!) |
| 2 | Добил секцию до 2 паллет (хорошо) |
| 3 | Один паллет в секции (нормально) |
| 4 | Новая пустая секция |

### 5.9 WMS_ExportSnapshot — полный снимок склада

Экспортирует ВСЕ данные склада одним вызовом: топологию + занятость + пол.
Результат — автономный JSON-файл для работы веб-приложения без подключения к 1С.

**Сценарии использования:**
- Разработка/отладка фронтенда без доступа к 1С
- Демонстрация алгоритма на снимке реального склада
- Обмен состоянием склада между системами
- Модельные (синтетические) данные для тестирования алгоритма

```
→ { "ProcName": "WMS_ExportSnapshot", "warehouse": "UUID" }

← {
  "exportedAt": "2026-07-17T12:00:00",
  "warehouse": { "id": "guid", "name": "ЛК Высотный", "code": "000000001" },

  // Полная топология (то же что WMS_GetRacks)
  "racks": [ ... ],

  // Текущая занятость (то же что WMS_GetOccupancy)
  "sections": [ ... ],

  // Паллеты на полу (то же что WMS_GetFloor)
  "floorPallets": [ ... ],

  // Сводка
  "summary": {
    "racksCount": 9,
    "totalSections": 1403,
    "totalAddresses": 4209,
    "occupiedAddresses": 2847,
    "occupancyPercent": 67.6
  }
}
```

**BSL:** объединяет вызовы `WMS_GetRacks` + `WMS_GetOccupancy` + `WMS_GetFloor` в один ответ. Один HTTP-вызов вместо трёх.

**Python:** эндпоинт `POST /api/snapshot/export` — сохраняет снимок в PostgreSQL (таблица `snapshots`) или возвращает JSON напрямую.

**Автономный режим веб-приложения:**

### HTTP-клиент к 1С (`services/client_1c.py`)

```python
class Client1C:
    def __init__(self, base_url: str, username: str = None, password: str = None):
        self.base_url = base_url
        self.auth = (username, password) if username else None

    async def call(self, proc_name: str, **params) -> dict:
        """Вызвать ProcName в Liko_Rest"""
        body = {"ProcName": proc_name, **params}
        async with httpx.AsyncClient(auth=self.auth) as client:
            resp = await client.post(self.base_url, json=body, timeout=30)
            resp.raise_for_status()
            return resp.json()
```

## 7. PostgreSQL

База данных `wms`. Единственная таблица:

```sql
CREATE TABLE connections (
    id          SERIAL PRIMARY KEY,
    name        VARCHAR(100) NOT NULL,       -- "ЛК Высотный (боевая)"
    base_url    VARCHAR(255) NOT NULL,       -- "http://1c-server/hs/Liko_Rest"
    username    VARCHAR(100),                -- Basic auth user (опционально)
    password_encrypted VARCHAR(512),         -- AES-256 encrypted, key from env var
    is_active   BOOLEAN DEFAULT false,       -- Только одна строка = true
    created_at  TIMESTAMP DEFAULT NOW()
);

-- Триггер: только одно активное подключение
CREATE UNIQUE INDEX one_active_connection
    ON connections ((true)) WHERE is_active = true;
```

**Шифрование:** пароль шифруется/дешифруется в Python (AES-256, ключ из `SECRET_KEY` env var). В БД хранится только шифрованный блоб.

**Аутентификация приложения:** Basic Auth на все `/api/*` эндпоинты. Два уровня доступа:
- `read` — просмотр склада + запуск плана (без `WMS_MovePallet`)
- `write` — всё включая реальное перемещение паллет

Пользователи и пароли — через переменные окружения (`API_USERS=admin:hash,operator:hash`).

### Автономный режим (без 1С)

Таблица `snapshots` для хранения полных снимков склада:

```sql
CREATE TABLE snapshots (
    id          SERIAL PRIMARY KEY,
    name        VARCHAR(200) NOT NULL,       -- "ЛК Высотный — 17.07.2026"
    warehouse_name VARCHAR(100),
    data        JSONB NOT NULL,              -- полный JSON из WMS_ExportSnapshot
    created_at  TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_snapshots_name ON snapshots(name);
```

**Поток автономной работы:**
1. Пользователь делает `WMS_ExportSnapshot` в 1С → получает JSON
2. Через веб-приложение: `POST /api/snapshot/load` с этим JSON
3. Снимок сохраняется в `snapshots` (JSONB)
4. Все `/api/racks`, `/api/occupancy`, `/api/floor` работают из снимка без 1С
5. `/api/optimize` работает на данных снимка
6. Виртуальные перемещения — в in-memory состоянии сессии

> При работе в автономном режиме подключение к 1С не используется — все данные берутся из загруженного снимка.
> В онлайн-режиме все WMS-запросы используют строку где `is_active = true`.

## 9. Алгоритм размещения

Реализуется в `services/wms/services/optimizer.py` (Python) и/или в `Лико_WMS_Сервер` (BSL).

### Псевдокод

```
function place_pallets(warehouse, incoming_pallets, options):

    // Шаг 1: загрузить состояние склада
    sections = load_sections(warehouse)  // через WMS_GetOccupancy

    // Построить индекс: для каждой секции — занятые адреса, остаток ширины/веса
    section_state = build_section_index(sections)

    // Шаг 2: отсортировать паллеты по убыванию ширины
    sorted_pallets = sort_by_width_desc(incoming_pallets)
    // Группы: wide (>2W/3) → medium (>W/3, ≤2W/3) → narrow (≤W/3)

    placements = []
    unplaced   = []

    // Шаг 3: для каждого паллета — получить кандидатов через 1С
    for pallet in sorted_pallets:

        // Вызвать существующий ПодобратьЯчейку(Все=Истина) через HTTP
        candidates = call_1c("WMS_FindCell", warehouse, pallet.id)
        // candidates уже отсортированы по 13 приоритетам 1С

        placed = false

        // Фаза А: попытаться ДОБИТЬ существующую секцию
        if options.fillExistingFirst:

            // Приоритет 1: секции с 2 паллетами → добить до 3
            for candidate in filter_by_section_count(candidates, section_state, 2):
                if can_fit_physically(section_state[candidate.section], pallet, target=3):
                    placements.add(pallet, candidate, fillLevel=1)
                    update_section(section_state, candidate.section, pallet)
                    placed = true
                    break

            // Приоритет 2: секции с 1 паллетом → добить до 2
            if not placed:
                for candidate in filter_by_section_count(candidates, section_state, 1):
                    if can_fit_physically(section_state[candidate.section], pallet, target=2):
                        placements.add(pallet, candidate, fillLevel=2)
                        update_section(section_state, candidate.section, pallet)
                        placed = true
                        break

        // Фаза Б: лучший кандидат из оставшихся (включая пустые секции)
        if not placed:
            for candidate in candidates:
                if can_fit_physically(section_state[candidate.section], pallet, target=1):
                    placements.add(pallet, candidate, fillLevel=4)
                    update_section(section_state, candidate.section, pallet)
                    placed = true
                    break

        if not placed:
            unplaced.add(pallet, "Нет подходящей секции по габаритам")

    // Шаг 4: статистика
    stats = {
        total: len(incoming_pallets),
        placed: len(placements),
        perfectSections: count_sections_with_n(section_state, 3),
        sectionsUsed: count_used_sections(section_state)
    }

    return { placements, unplaced, stats }
```

> **Ключевое решение:** Python **не дублирует** логику размещения. Сортировка кандидатов и все 13 приоритетов (узкопроходность, потенциал, best-fit по высоте/весу/ширине, уровень доступа, время доступа) остаются в 1С внутри `ПодобратьЯчейку`. Python только сортирует партию по ширине и выбирает лучшего кандидата из возвращённого 1С списка — добивая частично занятые секции перед открытием новых.


function can_fit(section, new_pallet, target_count, racks):
    section_width = section.typeSize.width
    width_clearance = get_floor(section).widthClearance  // обычно 50мм

    // --- 1. Проверка доступности адресов под тип паллета ---
    if new_pallet.width > section_width * 2 / 3:
        // Широкий: все 3 адреса должны быть свободны
        if section.any_occupied:
            return false
    elif new_pallet.width > section_width / 3:
        // Средний: Address2 свободен И (Address1 свободен ИЛИ Address3 свободен)
        if section.address2_occupied:
            return false
        if section.address1_occupied and section.address3_occupied:
            return false
    else:
        // Узкий: любой из 3 свободен
        if section.all_occupied:
            return false

    // --- 2. Проверка что существующие паллеты не блокируют новый ---
    for existing in section.pallets:
        if existing.width > section_width / 3:
            // Существующий средний паллет блокирует Address2 + один крайний
            // Новый узкий паллет должен проверить доступность оставшегося крайнего
            if new_pallet.width <= section_width / 3:
                // Какой крайний адрес занят существующим средним?
                if existing.address == section.address1:
                    // Средний занял Address1+2 → доступен только Address3
                    if section.address3_occupied:
                        return false
                elif existing.address == section.address3:
                    // Средний занял Address2+3 → доступен только Address1
                    if section.address1_occupied:
                        return false

    // --- 3. Сумма ширин + монтажный зазор ---
    current_widths = [p.width for p in section.pallets]
    total_width = sum(current_widths) + new_pallet.width
    clearance = (target_count + 1) × width_clearance
    if total_width + clearance > section_width:
        return false

    // --- 4. Проверка веса ---
    if not section.typeSize.unlimitedWeight:
        current_weight = sum(p.weight for p in section.pallets)
        if current_weight + new_pallet.weight > section.typeSize.weight:
            return false

    // --- 5. Проверка высоты ---
    // Габарит.Высота — это физическая высота секции.
    // Зазор (heightClearance) — пространство над паллетом, уже включён в полную высоту секции.
    // Паллет должен быть ≤ габарита секции.
    if new_pallet.height > section.typeSize.height:
        return false

    // --- 6. Проверка глубины (из этажа стеллажа) ---
    if not floor.minDepthUnlimited and new_pallet.depth < section.rack.minPalletDepth:
        return false
    if not floor.maxDepthUnlimited and new_pallet.depth > section.rack.maxPalletDepth:
        return false

    // --- 7. Проверка макс. веса подъёма на этаж ---
    if new_pallet.weight > floor.maxLiftWeight:
        return false

    return true
```

## 10. Алгоритм подбора высот этажей

Реализуется в `services/wms/services/floor_optimizer.py`.

### Постановка задачи

Дано:
- **Стеллаж**: общая высота, ширина секции, глубина, количество этажей
- **Параметры балки**: высота балки, зазор по высоте, высота от пола, фиксирована ли
- **Распределение паллет по высотам**: гистограмма — процент паллет каждого диапазона высот
- **Ограничение по весу**: макс. вес подъёма на каждый этаж (для тяжёлых паллет — нижние этажи)

Найти:
- **Высоту секции для каждого этажа** (только из существующего каталога `Лико_ТипоразмерыСкладскихСекций`)
- **Ожидаемый % использования** каждого этажа

Цель:
- Минимизировать wasted space = сумма (высота секции − высота паллета − зазор) по всем размещённым паллетам
- Максимизировать количество размещённых паллет

### Псевдокод

```
function optimize_floor_heights(rack_params, pallet_height_distribution):

    // rack_params:
    //   totalHeight, sectionWidth, sectionDepth,
    //   beamHeight, heightClearance, heightFromFloor, heightFromFloorFixed,
    //   floorCount, maxLiftWeights[], catalogTypes[]

    // pallet_height_distribution:
    //   [{minHeight, maxHeight, percent, avgWeight}, ...]

    floors = []

    // Общая доступная высота = общая высота стеллажа − высота от пола
    remaining_height = rack_params.totalHeight - rack_params.heightFromFloor

    // Этаж 1 и последний этаж — фиксированные если ВысотаОтПолаФиксирована
    first_floor = 1
    last_floor  = rack_params.floorCount

    for floor_num in 1..floorCount:

        is_fixed = (floor_num == first_floor AND rack_params.heightFromFloorFixed)
                   OR (floor_num == last_floor)

        if is_fixed:
            // Фиксированный этаж — берём существующий типоразмер без изменений
            fixed_type = get_current_type_size(floor_num)
            section_height = fixed_type.height  // габарит
            total_floor_height = section_height + rack_params.heightClearance + rack_params.beamHeight

        else:
            // Оптимизируемый этаж — подбираем типоразмер из каталога
            eligible_pallets = filter_by_weight(pallet_height_distribution,
                                                rack_params.maxLiftWeights[floor_num])
            if empty(eligible_pallets):
                continue

            // Доступная высота для секции (габарит) = оставшаяся / кол-во этажей − clearance − beam
            avg_available = remaining_height / (floorCount - floor_num + 1)
                           - rack_params.heightClearance - rack_params.beamHeight

            best_type = find_best_section_height(
                eligible_pallets, rack_params.heightClearance,
                rack_params.beamHeight, avg_available, rack_params.catalogTypes
            )

            section_height   = best_type.height  // габарит
            total_floor_height = section_height + rack_params.heightClearance + rack_params.beamHeight

        utilization = estimate_utilization(section_height, eligible_pallets)

        floors.add({
            number:          floor_num,
            sectionHeight:   section_height,   // габарит секции
            totalHeight:     total_floor_height, // габарит + зазор + балка
            utilization:     utilization,
            fixed:           is_fixed
        })

        remaining_height -= total_floor_height

    return floors


function find_best_section_height(eligible_pallets, height_clearance, beam_height, avg_available, catalog_types):
    // catalog_types: массив существующих типоразмеров [{height, width, depth, weight}]
    // Перебираем только существующие типоразмеры

    best_type = null
    best_score  = infinity

    for type_size in catalog_types:
        if type_size.height > avg_available * 1.5:  // не больше чем в 1.5 раза выше среднего
            continue

        score = weighted_wasted_space(type_size.height, eligible_pallets, height_clearance)
        if score < best_score:
            best_score  = score
            best_type = type_size

    if best_type is null:
        // Предложить создать новый типоразмер
        return { recommended_new_height: avg_available, reason: "Нет подходящего в каталоге" }

    return best_type
```

## 12. Drag-and-Drop

### Поток

```
1. Пользователь начинает тянуть паллет (dragstart)
   → запоминаем palletId + его габариты

2. Пользователь ведёт над ячейкой (dragover)
   → КЛИЕНТСКАЯ валидация (мгновенная, без запроса к серверу):
     • занятость: pallet != null в этой ячейке? → красный
     • ширина: помещается ли pallet.width + текущие + зазор в секцию?
     • вес: текущий_вес_секции + pallet.weight ≤ грузоподъёмность?
     • структура адресов: совместим ли тип паллета со свободными адресами?
   → валидно: зелёная рамка
   → невалидно: красная/оранжевая рамка + tooltip с причиной
   → все данные уже есть в store sections — запросов к серверу НЕТ

3. Пользователь уводит мышь (dragleave)
   → убираем рамку

4. Пользователь отпускает (drop)
   → СЕРВЕРНАЯ валидация (один запрос, финальная проверка):
     → POST /api/validate { cell, pallet }
     → 1С: ОшибкиРазмещенияВАдрес — полная проверка
   → valid:true:
     → POST /api/move { pallet, targetCell }
     → 1С создаёт документ ПеремещениеПаллета2_0
     → обновляем occupancy (перезапрос /api/occupancy)
   → valid:false:
     → показываем toast с ошибкой, не двигаем
```

## Решения по итогам аудита (2026-07-17)

По результатам аудита (`2026-07-17-wms-optimizer-audit.md`) приняты следующие решения:

| ЗАМ | Суть | Решение |
|---|---|---|
| 01 | Алгоритм не решает реслот | Реслот — фаза 2, отдельно от MVP. `fullReslot` убран из API v1 |
| 02 | `can_fit` не проверяет структуру 3 адресов | Добавлена явная проверка: широкий→3 адреса, средний→Address2+край, узкий→любой + блокировка существующим средним |
| 03 | Дублирование логики 1С и Python | Добавлен `WMS_FindCell` (обёртка `ПодобратьЯчейку(Все=Истина)`). Python не дублирует приоритеты |
| 04 | Высота без зазора для вил | Отозвано: Габарит.Высота ≠ Высота секции. Высота секции = Габарит.Высота + Зазор. Паллет ≤ Габарит.Высота |
| 05 | Подбор высот — непрерывный вместо каталога | Алгоритм ищет только среди существующих типоразмеров |
| 06 | Креды в открытом виде, нет авторизации | AES-шифрование паролей + Basic Auth + роли read/write |
| 07 | DnD: запрос к 1С на каждый dragover | Клиентская валидация для dragover, серверная только на drop |
| 08 | `max_weight > 0` вместо `unlimitedWeight` | Исправлено на `section.typeSize.unlimitedWeight` |
| 09 | Нет ручной инвалидации кэша | Добавлен `POST /api/cache/invalidate` |
| 10 | `/api/optimize/floors` отсутствует на диаграмме | Добавлен на диаграмму архитектуры |
| 11 | Нет единого конверта ошибок | `{ "ok": false, "error": { "code": "...", "message": "..." } }` для всех ProcName |

**Открытые вопросы (закрыты):**

| Вопрос | Решение |
|---|---|
| Реслот — в MVP или отдельно? | Отдельная фаза 2 |
