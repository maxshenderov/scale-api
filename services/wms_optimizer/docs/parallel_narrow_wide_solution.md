# Параллельное решение для узкопроходных и широких секций

**Дата:** 2026-07-24  
**Статус:** 💡 Предложение (не реализовано)

---

## Идея

Когда `strictNarrowAislePlacement=True`, разделить задачу на две независимые подзадачи:

### ЗАДАЧА 1: Узкопроходные паллеты в узкопроходные секции
- Паллеты: `width ≤ 1200 AND depth ≤ 1200` (~2/3 от общего числа)
- Секции: `narrow_aisle=True`
- Ограничение: СТРОГО узкопроходные паллеты → узкопроходные секции

### ЗАДАЧА 2: Широкие паллеты в широкие секции  
- Паллеты: `width > 1200 OR depth > 1200` (~1/3 от общего числа)
- Секции: `narrow_aisle=False`
- Ограничение: Широкие паллеты → широкие секции

---

## Зачем это нужно

### Проблема текущего подхода

При размещении всех 3406 паллет сразу solver:
1. Создаёт ~2.35M переменных (даже после агрегации ~1000)
2. Тратит время на поиск баланса между узкопроходными и широкими
3. Может застревать в локальном оптимуме

### Преимущества параллельного подхода

✅ **Меньше переменных в каждой задаче** — быстрее решение  
✅ **Независимые задачи** — можно решать параллельно или последовательно  
✅ **Нет конфликтов** — узкопроходные и широкие секции не пересекаются  
✅ **Проще отладка** — можно видеть результаты по отдельности

## Реализация

### Вариант A: Последовательное решение

```python
def solve_parallel_narrow_wide(
    occupancy: List[OccupancySectionSchema],
    new_pallets: List[NewPalletSchema],
    settings: OptimizationSettingsSchema
) -> OptimizationResponse:
    
    # Разделение паллет
    narrow_pallets = [p for p in new_pallets 
                     if p.width <= 1200 and p.depth <= 1200]
    wide_pallets = [p for p in new_pallets 
                   if p.width > 1200 or p.depth > 1200]
    
    # Разделение секций
    narrow_sections = [s for s in occupancy if s.narrow_aisle]
    wide_sections = [s for s in occupancy if not s.narrow_aisle]
    
    # ЗАДАЧА 1: Узкопроходные
    req_narrow = OptimizationRequest(
        optimizationId=f"{req.optimizationId}-NARROW",
        mode="place",
        occupancy=narrow_sections,
        newPallets=narrow_pallets,
        settings=settings,
    )
    resp_narrow = run_optimization(req_narrow)
    
    # ЗАДАЧА 2: Широкие
    req_wide = OptimizationRequest(
        optimizationId=f"{req.optimizationId}-WIDE",
        mode="place",
        occupancy=wide_sections,
        newPallets=wide_pallets,
        settings=settings,
    )
    resp_wide = run_optimization(req_wide)
    
    # Объединение результатов
    return merge_responses(resp_narrow, resp_wide)
```

### Вариант B: Параллельное решение (Python multiprocessing)

```python
from multiprocessing import Pool

def solve_parallel_narrow_wide_concurrent(
    occupancy, new_pallets, settings
):
    with Pool(2) as pool:
        tasks = [
            (narrow_sections, narrow_pallets, settings),
            (wide_sections, wide_pallets, settings),
        ]
        results = pool.starmap(run_optimization_worker, tasks)
    
    return merge_responses(results[0], results[1])
```

## Условия применения

✅ **ТОЛЬКО при `strictNarrowAislePlacement=True`**  
- Если False, узкопроходные могут идти в широкие → нельзя разделить

✅ **Холодный старт (allowReslot=False) или минимальный existing**  
- Если много existing паллет — нужно корректно распределить по подзадачам

❌ **НЕ применять при реслоте**  
- Реслот требует видеть всё размещение целиком

## Связь с двухэтапным подходом

Можно комбинировать:

### ЭТАП 1: Параллельное размещение
- ЗАДАЧА 1a: Узкопроходные паллеты → узкопроходные секции (90s)
- ЗАДАЧА 1b: Широкие паллеты → широкие секции (60s)
- **Итого ЭТАП 1:** ~150s (vs 248s текущий)

### ЭТАП 2: Общий реслот
- Input: объединённая occupancy + не размещённые из обеих задач
- Settings: `allowReslot=True, maxReslotPercent=10`
- **ЭТАП 2:** 4-10s (как показал опыт)

**ИТОГО:** ~160s vs 253s текущий (экономия ~90s)

## Риски

⚠️ **Может быть хуже чем объединённая задача**  
- Solver видит меньше вариантов для балансировки
- Может застрять в локальном оптимуме в каждой подзадаче

⚠️ **Усложнение логики**  
- Нужно корректно разделить и объединить результаты
- Нужно обработать случай когда одна задача failed

⚠️ **Дополнительная логика для existing**  
- Нужно корректно распределить existing паллеты по подзадачам
