## Реализация

### Созданные файлы

1. **solver/aggregation.py** — функции группировки и дезагрегации
   - `pallet_type_key()` — ключ типа паллеты
   - `section_type_key()` — ключ типа секции с учётом занятости
   - `build_type_aggregation()` — построение типов и допустимых пар
   - `disaggregate_solution()` — распределение конкретных паллет по секциям

2. **solver/cp_sat_aggregated.py** — агрегированная CP-SAT модель
   - Класс `CPSATAggregatedSolver`
   - Переменные `Y[ptype_idx, stype_idx]` вместо `X[pallet_id, section_idx]`
   - Три стадии дорешивания: exact, consolidation, reslot

3. **tests/test_s7_vs_standard.py** — регрессионный тест на S7 данных

### Изменённые файлы

**solver/cp_sat_model.py:**
- Добавлен порог `AGGREGATION_THRESHOLD = 300_000`
- Метод `solve()` разделён на `_solve_exact()` и `_solve_aggregated()`

## Анализ производительности

### Почему 188 секунд вместо <60?

1. **CP-SAT solver:** 120s (лимит `timeLimitSeconds`)
2. **Дезагрегация + постобработка:** ~68s
   - `_resolve_residual_exact`: до 20s
   - `_resolve_residual_with_consolidation`: дополнительное время
   - `_resolve_residual_with_reslot`: до 60s

### Почему 3239 вместо ≥3242?

Solver достиг FEASIBLE, но не OPTIMAL за 120s — не успел найти лучшее решение.

### Текущие параметры агрегации

```python
# solver/cp_sat_aggregated.py
_BUCKET_CHUNK_SIZE = 1  # Каждая секция = отдельный бакет
_RESIDUAL_TIME_LIMIT_SECONDS = 20.0
_RESLOT_TIME_LIMIT_SECONDS = 60.0
_RESLOT_MAX_CANDIDATE_SECTIONS = 150

# solver/cp_sat_model.py
AGGREGATION_THRESHOLD = 300_000

# tests/test_s7_vs_standard.py (S7_SETTINGS)
timeLimitSeconds = 120
```

## Рекомендации по оптимизации

### Вариант 1: Увеличить BUCKET_CHUNK_SIZE

**Изменение:**


**Эффект:**

- Меньше переменных → быстрее решение
- Риск: может немного снизить качество из-за огрубления

**Изменение:**

- Для холодного старта reslot не нужен (нечего переставлять)
