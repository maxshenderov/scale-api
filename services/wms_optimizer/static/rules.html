Поля OccupancySection — занятость секций (текущее состояние склада)

Occupancy = снимок текущего состояния склада на момент запроса оптимизации. Одна строка = одна секция со всеми её параметрами (размеры, ограничения, правила) и до 3 паллет, которые уже стоят внутри. Источник — Лико_WMS_Сервер.СобратьЗанятостьСекций(). Схема: api/schemas.py:16 — OccupancySectionSchema.

Идентификация секции

Поле Тип Обязательное Описание

section_code string ✓ Код секции, например "Р601-М(01-02-03)-Э01"

Что реально используется, а что нет

Поля, которые НЕ влияют на размещение:

  • accessLevel (секция и паллета)
  • accessTime (секция)
  • floor (секция)

Эти поля хранятся в моделях, передаются через API, но не участвуют ни в одной проверке в optimizer/, solver/, validation/.

Комментарий в коде подтверждает: models/pallet.py:25-27 — «резерв на будущее: сортировка секций по accessLevel/accessTime в зависимости от значения 1 или 2».

narrowAisle (секция) раньше было в этом списке как неиспользуемое. Начиная с этой версии оно активно используется — см. раздел «Узкопроходные стеллажи» ниже.

Единственное полное исключение: restricted=true — такие секции полностью исключаются ещё на этапе построения модели (models/occupancy_builder.py:33-35):

for row in occupancy:
    if row.restricted:
        continue  # секция не попадёт в список sections

Узкопроходные стеллажи (narrowAisle)

Узкопроходная паллета — паллета, у которой width ≤ 1200 И depth ≤ 1200 (мм). Вычисляется на сервере, без отдельного входного поля (models/pallet.py, свойство is_narrow). Признак не запрашивается у 1С — только ширина/глубина паллеты.

Узкопроходная секция — секция с narrowAisle=true в occupancy (models/section.py, поле narrow_aisle).

Параметр settings.strictNarrowAislePlacement (по умолчанию true)

Значение Поведение
true (default) Узкопроходная паллета размещается ТОЛЬКО в секции с narrowAisle=true. Если все узкопроходные секции заняты → паллета попадает в notPlaced с причиной NARROW_AISLE_MISMATCH, даже если есть свободные широкопроходные секции.
false Узкопроходные секции проверяются первыми (приоритет), но если все заняты — паллета размещается в широкопроходную секцию как запасной вариант.

Проверка правила выполняется в трёх местах пайплайна:

  • optimizer/potential.py:section_fits_pallet — используется FFD warm start и постпроцессингом причин отказа
  • solver/cp_sat_model.py (предфильтрация feasible-пар) — текущая секция существующей паллеты всегда остаётся допустимой для неё, иначе она выпадает из модели целиком и её вес/ширина не учитываются в ограничениях секции
  • optimizer/global_optimizer.py:_determine_not_placed_reason — формирует причину NARROW_AISLE_MISMATCH

Приоритет узкопроходных секций

Независимо от strictNarrowAislePlacement, узкопроходные секции имеют более высокий приоритет:

  • FFD warm start (solver/warm_start.py): секции сортируются (not narrow_aisle, -width) — сначала все узкопроходные, потом по убыванию ширины.
  • CP-SAT целевая функция (solver/cp_sat_model.py): небольшой бонус +10 * narrow_priority_sum за размещение узкопроходной паллеты в узкопроходную секцию — без этого бонуса решателю всё равно, какую из двух одинаково валидных секций выбрать.

Широкопроходная паллета (width > 1200 ИЛИ depth > 1200) не подчиняется этому правилу вообще — может размещаться в любую подходящую по остальным ограничениям секцию, узкопроходную или широкопроходную.

Отбор допустимых секций для паллеты

Прежде чем CP-SAT начнёт решать задачу, для каждой паллеты строится список секций, где она физически может стоять (solver/cp_sat_model.py:76-86):

# Условие Смысл
1 pallet.height ≤ section.height Высота паллеты не превышает высоту секции (typeSize_height)
2 pallet.depth ≤ section.depth Глубина паллеты не превышает глубину секции (typeSize_depth)
3 pallet.weight ≤ section.max_lift_weight Вес паллеты не превышает грузоподъёмность подъёма (max_lift_weight)
4 pallet.width ≤ section.eff_max_width Ширина ОДНОЙ паллеты (узкопроходные стеллажи, max_widthPallet → fallback на typeSize_width)
5 pallet.depth ≤ section.eff_max_depth Глубина ОДНОЙ паллеты (узкопроходные стеллажи, max_depthPallet → fallback на typeSize_depth)

Все 5 условий обязательны. Если хотя бы одно не выполнено — секция исключается из рассмотрения для этой паллеты.

Важно: eff_max_width и eff_max_depth — это отдельные поля (models/section.py:59-67), не производные от gap_width. Они ограничивают размер ОДНОЙ паллеты, а не сумму всех паллет в секции.

Ограничения CP-SAT на секцию

После предфильтрации CP-SAT накладывает три дополнительных ограничения на совокупность паллет в секции:

1. Вместимость (max_pallets)

model.Add(sum(vars_in_sec) <= sec.max_pallets)

Количество паллет в секции ≤ max_pallets (обычно 3).

2. Ширина с зазорами (gap_width)

model.Add(width_sum + count_var * gap + gap <= width_limit)

Формула: SUM(pallet.width) + (N+1)*gap_width ≤ section.width

где N — количество паллет в секции после размещения новой паллеты.

Эквивалентная проверка в постпроцессинге (optimizer/potential.py:64-75):

free_width = section.width - SUM(existing_widths) - (N+1)*gap_width
# новая паллета входит, если:
if free_width >= pallet.width + gap_width:
    # ОК

3. Вес секции (max_weight)

if not math.isinf(sec.max_weight):
    weight_sum = sum(weights * X[pallet, section])
    model.Add(weight_sum <= sec.max_weight)

Если typeSize_unlimitedWeight=true, то sec.max_weight = math.inf и проверка пропускается.

Заблокированные паллеты

Паллета считается заблокированной (movable=False), если в occupancy blockedN > 0 для её слота.

Заблокированные паллеты ВСЕГДА зафиксированы на текущем месте — независимо от allowReslot (solver/cp_sat_model.py:144-155).

Реслот (allowReslot / maxReslotPercent)

  • Если allowReslot=false — движимые существующие паллеты тоже не двигаются, фиксируются как заблокированные.
  • Если allowReslot=true — количество перемещённых паллет ограничено:
    moved ≤ floor(current_movable_count * maxReslotPercent / 100)
  • В режиме compact реслот всегда включён принудительно (это единственная цель этого режима).

Лимит операций (maxOperations)

model.Add(new_placed + moved <= settings.maxOperations)

Суммарно PUT (новые) + MOVE (переставленные) не может превышать maxOperations за один запуск.

Тёплый старт (First Fit Decreasing — FFD, жадная эвристика)

Warm Start = эвристика для начального решения, передаваемого в CP-SAT как подсказка (solver/warm_start.py). Цель — дать солверу хорошую стартовую точку, чтобы он быстрее находил оптимум или хотя бы feasible решение в пределах таймаута:

  1. Заблокированные/недвижимые паллеты → сразу в текущую секцию
  2. Остальные сортируются по убыванию ширины
  3. Секции сортируются: сначала узкопроходные (narrowAisle=true), внутри каждой группы — по убыванию ширины
  4. Жадное размещение: для каждой паллеты — первая подходящая секция (First Fit)

Выбор адреса внутри секции

После того как CP-SAT определил Паллета → Секция, выбирается конкретный адрес (слот 1/2/3) в рамках этой секции.

Правило из 1С (точная копия условия из Лико_СкладскиеСекции, без scoring):

ВЫБОР
    КОГДА ШиринаПаллета > Типоразмер.Ширина * 2 / 3
        ТОГДА Адрес2 (центр, position=2)
    КОГДА Паллет1 = ПустаяСсылка
        ТОГДА Адрес1
    КОГДА Паллет3 = ПустаяСсылка
        ТОГДА Адрес3
    КОГДА Паллет2 = ПустаяСсылка
        ТОГДА Адрес2
    ИНАЧЕ
        Не ставим (None)
КОНЕЦ

Реализация (optimizer/section_optimizer.py:63-102):

  1. Если pallet.width > section.width * 2/3 → пробуем Адрес2. Свободен и не blocked → ставим. Иначе → None.
  2. Иначе → Адрес1 свободен и не blocked → ставим.
  3. Иначе → Адрес3 свободен и не blocked → ставим.
  4. Иначе → Адрес2 свободен и не blocked → ставим.
  5. Иначе → None.

Порядок проверки всегда: 2 (для большой) или 1→3→2 (для обычной).

Никакого сравнения по объёму, потенциалу или другим метрикам между адресами — первый подходящий по этому порядку и есть выбранный.

Причины отказа в размещении

Если новую паллету не удалось разместить, причина вычисляется в optimizer/global_optimizer.py:_determine_not_placed_reason:

Reason Условие
RESLOT_LIMIT Хотя бы одна секция подошла по всем физическим ограничениям, но паллета не разместилась (лимит реслота/операций/решатель не успел)
NARROW_AISLE_MISMATCH Паллета узкопроходная (width ≤ 1200 И depth ≤ 1200), все проверенные секции — narrowAisle=false, а settings.strictNarrowAislePlacement=true (по умолчанию). См. раздел «Узкопроходные стеллажи».
HEIGHT_LIMIT pallet.height > section.height во всех проверенных секциях
DEPTH_LIMIT pallet.depth > section.depth
LIFT_LIMIT pallet.weight > section.max_lift_weight
MAX_PALLET_SIZE_LIMIT pallet.width > eff_max_width или pallet.depth > eff_max_depth
WEIGHT_LIMIT Суммарный вес секции с этой паллетой превысил max_weight
NO_SPACE Не прошла section_fits_pallet (ширина+зазоры или количество) — дефолт

Целевая функция (score)

В самом CP-SAT (упрощённая):

objective = 100000 * placed - 1000 * section_moves + 10 * narrow_priority

Максимизируется количество размещённых паллет, минимизируется количество перемещений между секциями, небольшой бонус за размещение узкопроходной паллеты в узкопроходную секцию (см. «Узкопроходные стеллажи»).

В финальном ответе (постпроцессинг):

GlobalScore = placedPalletWeight * placed
            - sectionMovePenalty * section_moves
            - addressMovePenalty * address_moves  (всегда 0)
            - potentialLossPenalty * potential_loss
            - spaceLossPenalty * unused_space     (всегда 0)
            - sectionUsagePenalty * used_sections

Коэффициенты берутся из config/weights.json (захардкоживание запрещено).

address_moves и unused_space в текущей реализации всегда передаются 0 — это компоненты формулы, которые сейчас нигде не вычисляются.

Валидация запроса

validation/validator.py проверяет только ссылочную целостность:

  • Нет дублирующихся section_id в occupancy
  • Нет дублирующихся address_id (собранных из address1/2/3)
  • Нет дублирующихся pallet_id (из pallet1/2/3_id)
  • Нет дублирующихся id в newPallets
  • newPallets не содержит id, уже занятый существующей паллетой

Структурные проверки (обязательность полей, width/height/depth > 0, диапазоны) выполняет Pydantic на этапе разбора OptimizationRequest.

Нет проверки accessLevel in [1,2,3], нет проверки "секция не restricted" на этапе валидации — restricted обрабатывается позже, при построении модели.
