# Брифинг для Claude Code — Проект OKIL

## Кто я
Программист 1С. Разрабатываю ERP систему для компании **Лико** — типография этикеток (самоклеящиеся, термоусадка, FMCG упаковка).

## Проект
`D:\project\OKIL` — монорепозиторий:

```
D:\project\OKIL\
├── 1s\ERP\
│   ├── Conf\          — конфигурация 1С ERP в формате EDT (BSL + XML)
│   ├── extensions\    — расширения проекта в формате EDT (исходники!)
│   └── obrab\         — внешние обработки
│       ├── AIАссистент\
│       ├── ZagSklad\
│       └── ТестLLM\
├── services\          — Python FastAPI микросервисы (AI/RAG pipeline)
├── mcp\               — MCP сервер для поиска по коду (Qdrant)
├── qdrant_storage\    — векторная БД
├── wiki\              — живая документация (ты будешь её вести)
├── output\            — сюда кладёшь готовый BSL-код
├── plans\             — планы разработки
└── ТЗ\               — техническое задание
```

Все кастомные объекты имеют префикс `Лико_`. По нему отличаем наш код от типового ERP.
Подробная архитектура 1С — в `AGENTS.md`. Python сервисы — в `CLAUDE.md`.

## Что я хочу реализовать

### Система знаний по методу Карпатого
Андрей Карпатый описал подход: вместо RAG (поиск по чанкам) — LLM строит и поддерживает **постоянную вики** в виде markdown файлов. Знания накапливаются, не пересчитываются каждый раз.

Подробнее: https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f

### Как это работает в моём проекте
```
Я добавляю BSL модуль → ты читаешь → пишешь страницу в wiki\
                                              ↓
                              Я смотрю в Obsidian (граф связей)
                                              ↓
                    Я прошу написать новый код → ты читаешь вики
                    → понимаешь МОЙ стиль кода → пишешь правильно
```

**Obsidian** — приложение для markdown. Открыта папка `D:\project\OKIL` как vault.
Я вижу все страницы вики и граф связей между ними в реальном времени.

### Три типа задач которые я буду давать

**1. INGEST** — "добавь в вики [модуль/файл]"
Читаешь BSL → пишешь страницу в `wiki\` → обновляешь `wiki\index.md` → пишешь в `wiki\log.md`

**2. CODE** — "напиши [что-то]"
Сначала читаешь `wiki\index.md` → находишь похожие объекты → читаешь их страницы → пишешь код в нашем стиле → кладёшь в `output\`

**3. QUERY** — "как у нас работает [что-то]"
Читаешь `wiki\index.md` → находишь нужные страницы → отвечаешь со ссылками на вики
